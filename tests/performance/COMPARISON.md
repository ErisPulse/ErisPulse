# 性能优化前后对比（附 NoneBot2 参考）

数据来自 2026-10-05 在同一台机器（Python 3.13.14）上的前后两轮实测，方法论一致：预热 + 多轮采样取百分位。优化前后两组数据在同一时段采集，解释器空转对照 60.3ms / 59.5ms，负载条件可以认为一致；NoneBot2（2.5.0 + OneBot v11 适配器 2.4.6）跑在独立环境。所有数字都可用仓库自带的基准复现：`python tests/performance/benchmark.py`（用法见 [README.md](README.md)）。

## 优化了什么

2.9 开发周期对热路径做了一轮优化，共五项：

1. **transcript 写入**：每条消息改为内存缓冲 + 后台批量落盘（此前每条消息同步跳线程写存储，是消息桥吞吐减半的主因）；
2. **i18n 缓存**：此前每次翻译调用都重新打开并解析 `~/.erispulse/cli_state.json`；
3. **日志守卫**：级别关闭时热路径直接跳过字符串格式化和翻译；
4. **匹配器预编译**：detail_type / pattern / regex 改在注册时编译一次（此前每个事件、每个处理器都现场编译）；
5. **配置写入调度**：`setConfig` 延迟写改由常驻线程按到期时间统一刷盘（此前每次写入都创建一个 OS 线程，用完即弃）。

对外 API 无变化。

## 结论

- 这轮的主战场是事件分发：消息桥默认配置 811 → 2,804 ops/s，总线洪泛 1,249 → 9,877，命令 miss（每条消息都要走的前缀扫描路径）1,295 → 10,818，幅度在 3~9 倍。
- 和 NoneBot2 比，优化前单事件轻载落后 2~4 倍，现在反过来了：单处理器 3.0×、洪泛 4.8×、多处理器 9.9×、命令命中 3.2×（miss 11.7×）。多处理器差距拉得最大——ErisPulse 对每个处理器并行派发 Task，NoneBot2 的 matcher 按优先级串行调度。
- 存储读（+67%）、完整发送（+65%）、端到端（+48%）不是直接优化的结果，是 i18n 缓存和日志守卫的连带收益。
- 横向数据只当参考：两个框架在会话记录、事件模型、调度模型上都不一样，选型还是拿自己的业务负载跑一遍基准最实在。
- lifecycle.fire 零监听那一行（~32 万 ops/s）是微秒级纯调度，波动就是噪声，不用当回事。
