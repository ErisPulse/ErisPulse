# 高級トピック

このディレクトリには、ErisPulse フレームワークの高度なトピックが収録されています。権限管理、グレーディングリリース、複数ラウンドの対話、ストレージバックエンドなど、深い機能が含まれており、それぞれが特定の問題を解決します。

> [!NOTE]
> このディレクトリのすべてのドキュメントは**必要に応じて参照**するためのトピックドキュメントです。まず、ホームのL1コア5篇を読んでから、対応するニーズに遭遇したときに参照してください。各ドキュメントの冒頭には「このドキュメントを読む必要があるとき」が明記されています。

## L2 必読の4つの記事

生産レベルのモジュールを書く際に避けて通れない4つの記事です。複雑なモジュールを構築する前に、ぜひ全文を読んでください（本文の説明とドキュメントのトップページの説明は同一です）：

- [スコープ（scope）](scope.md) - 3次元スコープ制御：モジュールの可用性 / イベントのアクセス制限 / 出力アクションの制限（メソッドレベルの細かいルールとバインディング継承 merge を含む）
- [所有権（owner）システム](ownership.md) - リソースの所有権と自動回収：owner コンテキストメカニズム、所有リソースの全体像、アンロード時のクリーンアップシーケンスと設計の境界
- [ライフサイクル管理](lifecycle.md) - ライフサイクルイベントシステム：モジュール / アダプタのロード、アンロード、再ロード、無効化時にそれぞれ何をするべきか
- [インタラクションセッションシステム](interaction.md) - wait_reply / セッションタイマー / マルチウェイト / セッション排他リース / 受信箱 / メッセージトランザクション / リンク追跡

## シナリオ別にグループ化

ドキュメントのトップページ「原理を深く理解する」のグループ化基準と一致しており、各グループの最初の記事には「理解しないと何の落とし穴にハマるか」が明記されています。

**起動** —— 起動のチェーン（Finder / Loader / Manager / Router）を理解していないと、モジュールのロードに失敗した際にログをただ見つめて立ち尽くすことになります。

- [起動プロセスと手動制御](startup.md) - 起動チェーンの分解（Finder/Loader/Manager/Router）と手動による完全な起動
- [遅延ロードシステム](lazy-loading.md) - 遅延ロードモジュールシステムの動作原理、設定、およびイベント駆動による遅延アクティベーション（activate_on）

**通信接続** —— サービス契約（`meta.services`）のホワイトリストを理解していないと、モジュール間の `module.call` が `ServiceNotProvidedError` で拒否され、その原因が不明になります。

- [モジュール間通信](module-communication.md) - RPCプロトコル化（module.call）、サービス契約とディレクトリ、指定されたイベント、クールスタート時の再再生、イベントの冪等性と重複除去
- [接続プールとブロードキャスト](connections.md) - 接続レジストリ：ブロードキャスト、グループサブスクリプション、モジュール間のメッセージ転送と再利用、接続プールの確認
- [ルータマネージャー](router.md) - HTTP および WebSocket のルート管理（単一パラメータの登録、タプル形式のレスポンスの約束を含む）

**データ保存** —— 接続失敗時のクールダウン期間の意味を理解していないと、データベースの不安定性が発生した際に「フレームワークが停止した」と誤解してしまい、実際は即時失敗し、クールダウン後に自動的に再接続されます。

- [ストレージバックエンド](storage-backends.md) - sqlite / mysql / postgres の非同期ネイティブストレージバックエンドの選択、設定、切り替え
- [SQLクエリビルダー](sql-builder.md) - 一般的なSQLチェーン式クエリビルダーとストレージバックエンドの抽象化
- [HTTPクライアント](http-client.md) - 統一されたHTTPリクエストクライアント

**メッセージ対話** —— 会話の排他リースを理解していないと、2つのモジュールが同じユーザーの返信を同時に待っている場合、お互いに通信を打ち切ってしまいます。

- [Conversation 多段対話](conversation.md) - 多段対話コンテキストのインタラクションメソッド
- [会話受信箱](transcript.md) - メッセージの自動記録：保持ポリシーのスイッチ、実行時の上書きAPIとリスク/監査
- [MessageBuilder 詳解](message-builder.md) - OneBot12 メッセージセグメントビルダーの2つのモードの使い方
- [国際化 (i18n)](i18n.md) - 多言語サポート、翻訳の登録と言語の検出

**グレーディングシャドウ** —— 5つの隔離ゲートを理解していないまま本番に移行すると、シャドウの出力メッセージが本物のユーザーに外漏れしてしまいます。

- [シャドウモジュールとグレーディングの本番移行](shadow.md) - モジュールの新バージョンを独立したオーナーで並行して試運転：出力メッセージのブロッキングと記録、動作の差分比較、promoteによる本番移行と失敗時のロールバック

**例外と規範の参考**

- [例外体系とキャッチガイド](errors.md) - フレームワークのすべての例外の種類、発生場所、キャッチの提案
- [会話型システム](../standards/session-types.md) - 会話型の定義、マッピング、およびカスタム型の登録

## 対象読者

これらのドキュメントは以下の開発者に適しています：

- ErisPulse の基本機能に精通している開発者
- フレームワークの内部メカニズムを深く理解したい開発者
- パフォーマンスを最適化したり、複雑な機能を実装したい開発者
