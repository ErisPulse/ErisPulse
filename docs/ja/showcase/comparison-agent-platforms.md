# ErisPulse と AstrBot / LangBot の比較

> [!TIP]
> **この記事を読むタイミング**：「グループ内の AI ヘルパー」が目的で、AstrBot / LangBot といった統合プラットフォームと ErisPulse の選定に迷っている場合に読んでください。AI 以外の業務コードを書く場合は [NoneBot2 との比較](comparison-nonebot.md) を参照してください。

一言で差異を説明すると：

- **AstrBot / LangBot**：統合型 AI チャットボットプラットフォーム —— インストール、Key の設定、チャットの開始、LLM 対話が製品の中心
- **ErisPulse**：ロボットフレームワーク/SDK —— AI は QvQChat などの可動式モジュールの一つであり、フレームワーク自体は AI 以外の業務ロジックも扱う

いずれも最終的には「グループに仕事ができる AI がいる」状態になりますが、実現方法と可能性の上限は異なります。

## 対照

| 維度 | ErisPulse + QvQChat | AstrBot / LangBot |
|---|---|---|
| 起動体験 | プロジェクトの初期化 + アダプターのインストール + QvQChatのインストール + モデルプールの設定、約10分 | インストール + Keyの設定で即座に使用可能、より迅速 |
| プラットフォームカバレッジ | 16のプラットフォームアダプター（雲湖、メール、ターミナル、Webhookブリッジを含む） | 主要なIMプラットフォーム |
| LLMサポート | OpenAI互換のモデルプール（自己修復、障害転送、難易度ルーティング）、MCPクライアント | 複数のプロバイダーの内蔵接続 |
| AIの深さ | ツールループ + サブインテリジェントエージェント + 長期記憶/ユーザープロファイル + 知識ベース + コンピュータ操作サンドボックス + 定期的な「計画-実行-レビュー」 | チャット、人格、知識ベース、プラグインツール |
| エコシステム連携 | 任意のErisPulseモジュールがサービスを宣言すると、AIツールとして自動的に利用可能。モジュールの追加/削除でAI機能を増減 | 対応するプラグインをインストールすることでAI機能を拡張 |
| リバースオープン | [ApiMCP](../ecosystem/apimcp.md) により、ロボットをMCPツールとして公開し、ClaudeなどのAIクライアントが直接操作可能 | — |
| ホットリロード | モジュール/アダプター単位で、保存即座に有効 | プラグインの更新には通常、再起動が必要 |
| 非AI業務 | フレームワークが原生的に提供：コマンドシステム、複数回対話、ORM、定時タスク、メッセージ統計などのモジュールは個別に独立 | プラットフォームはAI対話を中心に設計され、非AI機能はプラグインに依存 |
| 管理パネル | Dashboard（モジュール/設定/ログ/イベント + 第三方ウィンドウの登録）、スマホアプリ、AIビルダー | WebUIが内蔵 |
| コミュニティ規模 | 若く、エコシステムは成長中 | ユーザー数が多く、サードパーティのプラグインも多数 |

## どちらを選ぶべきか

**AstrBot / LangBot を選ぶ**：AIチャットをすぐに使いたい、業務コードを書きたくない、また、雲湖（うんこ）のようなマイナーなプラットフォームとの連携も必要ない場合。これらは完成度の高い統合ソリューションです。

**ErisPulse を選ぶ**：ロボットにはAI以外にも別の機能（定時送信、グループ管理、メッセージ統計、ブリッジなど）が必要で、AIを単なるモジュールの1つとして切り替えたい、あるいはホットリロードによる開発の流れやモジュールマーケットでの配布方法、「モジュールを1つ追加するごとにAIの機能が1つ増える」ようなエコシステムの連携を重視したい、あるいは外部のAIがロボットを操作できる反転チャネルである ApiMCP が必要な場合。

> [!NOTE]
> 両方の公開ドキュメントに基づいて整理した比較です。AstrBot / LangBot のユーザー数とプラグイン数が多いのは事実ですが、決定に当たっては[それぞれの公式ドキュメント](https://astrbot.app/) / ([LangBot](https://docs.langbot.app/))を参考にしてください。
