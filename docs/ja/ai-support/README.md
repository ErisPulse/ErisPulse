# AI 支援開発

ErisPulse は、AI が最新のフレームワーク仕様に基づいてコードを生成できるようにする、2つの補完的な AI 支援開発の方法を提供します：

- **マテリアルドキュメント**：1つの大きな Markdown で、コンテキストを一括投入します。プロジェクト全体の開発に適しています
- **MCP サーバー**：AI が必要に応じて公式ドキュメントを検索できるようにします。日常のコード補完や API 参照に適しています

| | マテリアルドキュメント | MCP サーバー |
|---|---|---|
| 形式 | 1つの大きな Markdown、**一括投入** | AI による**オンデマンド検索** |
| コンテキストコスト | 高い（token を消費） | 低い（関連部分のみ取得） |
| 鮮度 | バージョンリリースに合わせて更新 | リアルタイム（GitHub から取得 + キャッシュ） |
| 適する場面 | コンテキストウィンドウが大きい、プロジェクト全体の開発 | 日常のコード補完、API 参照 |
| クライアント | あらゆる AI ツール | MCP 対応クライアントのみ |

両者は矛盾しません：大規模プロジェクトの開発では同時に使用できます——マテリアルドキュメントを土台とし、MCP で抜け漏れを補完します。

## マテリアルドキュメント

マテリアルドキュメントは `prompts/` ディレクトリにあり、開発シーンに応じて3種類に分かれています：

| ドキュメント | シーン | 説明 |
|------|------|------|
| **ErisPulse-ModuleDev.md** | モジュール開発 | モジュール開発の全フローをカバー（イベント処理、ルーティング、ライフサイクルなど） |
| **ErisPulse-AdapterDev.md** | アダプター開発 | モジュール開発の内容に加え、アダプターのコア概念、SendDSL、プラットフォーム適合ガイド |
| **ErisPulse-Full.md** | フルスタックリファレンス | 上記すべての内容 + 完全なユーザーガイドと API リファレンスのコレクション |

入手方法：[docs-generated ブランチ](https://github.com/ErisPulse/ErisPulse/tree/docs-generated) の `prompts/` ディレクトリから取得（ドキュメントと同期更新）、または公式サイトのダウンロードページから。

### 使用方法

1. 目的に応じてドキュメントを選択（モジュール → `ModuleDev`、アダプター → `AdapterDev`、複雑な要件 → `Full`）
2. ドキュメントの内容をコンテキストとして AI に提供：IDE 内ではワークスペースに置き、チャット型では直接貼り付け、API 呼び出しでは system message として注入
3. 以下のテンプレートで要件を記述します。具体的であるほど生成品質が高くなります

### 要件記述テンプレート

**モジュール：**

```
ErisPulse モジュール開発規範に基づき、[モジュール名] モジュールの完全なコードを生成してください。

機能説明：[コア機能]
リッスンが必要なイベント：[メッセージ / コマンド / 通知 / リクエスト]、処理ロジック：[操作]
必要な設定項目：[キー名]：[用途]（[必須/任意]、デフォルト値：[値]）
その他の要件：[追加の制約]
```

**アダプター：**

```
ErisPulse アダプター開発規範に基づき、[アダプター名] アダプターの完全なコードを生成してください。

プラットフォーム情報：[名称]、通信プロトコル：[WebSocket / WebHook / HTTP ポーリング]、API ドキュメント：[URL]
イベント変換：プラットフォームイベント [タイプ] → OneBot12 マッピング [対応関係]
実装が必要な送信メソッド：[Text / Image / Voice ...]
設定項目：[キー名]：[用途]（[必須/任意]）
```

## ドキュメントパック

`skills.zip` はこの言語の全ドキュメントを原文のまま収録（統合・書き換えなし）し、ルートに README 索引（ディレクトリ別に分组し、各文書に「いつ読むべきか」付き）を同梱したパックです。AI は必要な文書だけを読み込みます。

### 素材ドキュメントとの違い

| | 素材ドキュメント | ドキュメントパック |
|---|---|---|
| 形式 | 単一の統合 `.md` | 全ドキュメント原文 + README 索引 |
| 使い方 | コンテキストへ一括注入 | ワークスペースに展開し、AI が必要な文書を選択 |
| 適する場面 | 大きなコンテキストウィンドウ、プロジェクト全体の開発 | 常駐ワークスペース、必要なときだけ検索 |

両者は同じドキュメントから生成され、同期して更新されます。

### 入手方法

公式サイトの「AI 支援開発」ページからダウンロード、または [docs-generated ブランチ](https://github.com/ErisPulse/ErisPulse/tree/docs-generated) の `docs/ja/ai-support/skills.zip` を直接取得。
## MCP サーバー

ErisPulse はドキュメント検索用の MCP Server を提供しており、AI コーディングアシスタント（MCP 対応であればどれでも）がコードを書く際に直接 ErisPulse 公式ドキュメントを検索・閲覧できるようになります。

接続方法は2つあります：**ローカルプロセス（推奨）**または**公式オンラインエンドポイント**です。ツールセットは共通です：

| ツール | パラメータ | 説明 |
|------|------|------|
| **`search_docs`** | `query` (必須), `top_k?=5`, `lang?=zh-CN` | BM25 キーワード検索。複数のキーワードを一度に渡せます |
| **`read_document`** | `doc_path` (必須), `lang?=zh-CN` | 単一ドキュメントの完全な Markdown を読み取る |
| **`list_documents`** | `lang?=zh-CN` | 現在の言語のすべてのドキュメントのタイトル、パス、カテゴリを一覧表示 |
| **`list_languages`** | — | ドキュメントがサポートするすべての言語とドキュメント数を一覧表示 |

サポート言語：`zh-CN` / `en` / `zh-TW` / `ja` / `ru`。検索のコツ：文章全体ではなく**複数のキーワード**を使用します。たとえば `コマンド登録 イベントリッスン` は `コマンドを1つ登録する方法` よりも良い結果が得られます。

### 方法1：ローカルプロセス（推奨）

インストール後、ローカルで直接起動します：

```bash
npm i -g @erisdev/mcp-server   # グローバルインストール → epsdk-mcp コマンドが使用可能に
epsdk-mcp --server               # MCP サービスを起動；初回実行時にドキュメントを ~/.cache/erispulse-mcp/docs へ自動取得
```

グローバルインストールしなくても、`npx` で直接実行できます（インストール不要）：

```bash
npx @erisdev/mcp-server --server
```

ローカルにドキュメントディレクトリがある場合はそれを指定します（オフライン）：

```bash
ERISPULSE_DOCS_DIR=/path/to/erispulse/docs epsdk-mcp --server
```

MCP クライアントでは **stdio トランスポート**で設定します。標準的なキー値（`command` + `args` で上記の起動方法を指定；具体的な設定場所と形式は各クライアント自身の MCP 接続ドキュメントを参照）：

```json
{
  "command": "epsdk-mcp",
  "args": ["--server"]
}
```

または

```json
{
  "command": "npx",
  "args": ["@erisdev/mcp-server", "--server"]
}
```

### 方法2：公式オンラインエンドポイント

ローカルでプロセスを起動したくない場合は、公式ホスティングの [`mcp.erisdev.com`](https://mcp.erisdev.com/) に接続します。MCP クライアントでは **HTTP トランスポート**で設定します：

```json
{
  "url": "https://mcp.erisdev.com/"
}
```

サービスはデフォルトで公開されており、Token は不要ですが、IP レート制限があります（IP ごとに毎分 60 回）。公式エンドポイントはいつでも停止される可能性があるため、**本番ワークフローでは方法1（ローカルプロセス）またはセルフホスティングを推奨します**。

## よくある質問

**生成されたコードが期待どおりでない場合は？**
完全なドキュメントが提供されているか確認します；要件に入出力例や境界条件などの詳細を追加します；AI に段階的に生成させます（まずスケルトンを作り、その後機能を補完）；[examples/](../../examples/) ディレクトリのサンプルを補足コンテキストとして参考にします。

**MCP 接続後に AI が `search_docs` を呼び出さない場合は？**
クライアントがその server をロードしているか確認します（**クライアントを再起動するとツールが有効になっているのが確認できます**）；一部のクライアントでは、prompt に「ErisPulse ドキュメントツールを使って API を確認する」ことを明示的に指示する必要があります。
