# AI補助開発

ErisPulse は、最新のフレームワーク規格に基づいてコードを生成できる、2 つの補完的な AI 補助開発方法を提供します。

- **マテリアルドキュメント**：1 つの大きな Markdown ファイルに一度にコンテキストを注入し、プロジェクト全体の開発に適しています。
- **MCP サーバー**：AI が必要なときに公式ドキュメントを検索し、日常的なコード補完や API 検索に適しています。

| | マテリアルドキュメント | MCP サーバー |
|---|---|---|
| 形式 | 1 つの大きな Markdown ファイルを**一度に注入** | AI が**必要に応じて検索** |
| コンテキストコスト | 高い（token を消費） | 低い（関連する断片のみ取得） |
| 時効性 | バージョンリリースごとに更新 | 実時間（GitHub から取得 + キャッシュ） |
| 適用対象 | コンテキスト窓が大きく、プロジェクト全体の開発に適している場合 | 日常的なコード補完、API 検索 |
| クライアント | 任意の AI ツール | MCP をサポートするクライアントのみ |

これらは互いに矛盾するものではなく、大型プロジェクトの開発時には両方を同時に使用できます。マテリアルドキュメントで基本を整え、MCP で漏れを補完します。

## マテリアルドキュメント

マテリアルドキュメントは `prompts/` ディレクトリにあり、開発シナリオに応じて3種類に分かれています。

| ドキュメント | シナリオ | 説明 |
|------|------|------|
| **ErisPulse-ModuleDev.md** | モジュール開発 | イベント処理、ルーティング、ライフサイクルなど、モジュール開発の全プロセスをカバー |
| **ErisPulse-AdapterDev.md** | アダプタ開発 | モジュール開発に加え、アダプタのコアコンセプト、SendDSL、プラットフォーム適応ガイドを含む |
| **ErisPulse-Full.md** | フルスタックリファレンス | 上記すべて + 完全なユーザーガイドとAPIリファレンスのまとめ |

入手方法：`prompts/` ディレクトリから直接取得（ドキュメントと同期して更新）、または [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases) から対応バージョンをダウンロード。

### 使用方法

1. 目標に応じてドキュメントを選択（モジュール → `ModuleDev`、アダプタ → `AdapterDev`、複雑なニーズ → `Full`）
2. ドキュメントの内容をAIにコンテキストとして提供：IDE内にワークスペースとして配置、対話形式では直接貼り付け、API呼び出しでは system message として注入
3. 下記のテンプレートに従ってニーズを記述。より具体的に記述すれば、生成品質が向上します。

### ニーズ記述テンプレート

**モジュール：**

```
ErisPulse モジュール開発規格に基づき、[モジュール名] モジュールの完全なコードを生成してください。

機能説明：[コア機能]
監視する必要があるイベント：[メッセージ / コマンド / 通知 / 要求]、処理ロジック：[操作]
必要な設定項目：[キー名]：[用途]（[必須/任意]、デフォルト値：[値]）
その他の要求：[追加の制約]
```

**アダプタ：**

```
ErisPulse アダプタ開発規格に基づき、[アダプタ名] アダプタの完全なコードを生成してください。

プラットフォーム情報：[名称]、通信プロトコル：[WebSocket / WebHook / HTTPポーリング]、APIドキュメント：[アドレス]
イベント変換：プラットフォームイベント [タイプ] → OneBot12 マッピング [関係]
実装する必要がある送信メソッド：[Text / Image / Voice ...]
設定項目：[キー名]：[用途]（[必須/任意]）

## MCP サーバー

ErisPulse は、AI コードアシスタント（MCP をサポートするものすべて）がコードを書く際に、ErisPulse 公式ドキュメントを直接検索・参照できるようにするドキュメント検索用 MCP サーバーを提供しています。

接続方法は 2 つあります：**ローカルプロセス（推奨）** または **公式オンラインエンドポイント**。両方ともツールセットは同じです：

| ツール | パラメータ | 説明 |
|------|------|------|
| **`search_docs`** | `query` (必須), `top_k?=5`, `lang?=zh-CN` | BM25 キーワード検索。一度に複数のキーワードを渡すことができます |
| **`read_document`** | `doc_path` (必須), `lang?=zh-CN` | 1 つのドキュメントの完全な Markdown を読み込みます |
| **`list_documents`** | `lang?=zh-CN` | 現在の言語でサポートされているすべてのドキュメントのタイトル、パス、カテゴリを一覧表示します |
| **`list_languages`** | — | ドキュメントがサポートしているすべての言語とドキュメント数を一覧表示します |

サポート言語：`zh-CN` / `en` / `zh-TW` / `ja` / `ru`。検索のコツ：**整文ではなく、複数のキーワード**を使用してください。例えば `命令登録 イベントリスナー` の方が `どうやってコマンドを登録するか` よりも効果的です。

### 方法 1: ローカルプロセス（推奨）

インストール後にローカルで起動します：

```bash
npm i -g @erisdev/mcp-server   # グローバルインストール → epsdk-mcp コマンドが利用可能になります
epsdk-mcp --server               # MCP サービスを起動；初回実行時にドキュメントが ~/.cache/erispulse-mcp/docs に自動的にダウンロードされます
```

グローバルインストールせずに `npx` で直接実行することも可能です（インストール不要）：

```bash
npx @erisdev/mcp-server --server
```

ローカルにドキュメントディレクトリがある場合は、それを指定してインターネット接続なしで実行できます：

```bash
ERISPULSE_DOCS_DIR=/path/to/erispulse/docs epsdk-mcp --server
```

MCP クライアントで **stdio 伝送**を設定し、標準のキー/値（`command` + `args` は上記の起動方法を指します；具体的な設定位置と形式は、各クライアントの独自の MCP 接続ドキュメントを参照してください）：

```json
{
  "command": "epsdk-mcp",
  "args": ["--server"]
}
```

または

```json
{
  "command": "npx",
  "args": ["@erisdev/mcp-server", "--server"]
}
```

### 方法 2: 公式オンラインエンドポイント

ローカルでプロセスを起動したくない場合は、公式がホストしている [`mcp.erisdev.com`](https://mcp.erisdev.com/) に接続してください。MCP クライアントで **HTTP 伝送**を設定します：

```json
{
  "url": "https://mcp.erisdev.com/"
}
```

サービスはデフォルトで公開されており、Token は不要です。ただし、IP 制限（1 IP 毎分 60 回）が適用されます。公式エンドポイントはいつでも停止される可能性があるため、**本番ワークフローでは方法 1（ローカルプロセス）または自ホストを推奨します**。

## 常見問題

**生成されたコードが期待通りでない？**  
完全なドキュメントが提供されているか確認してください。要件に詳細を追加する（入出力の例、境界条件）；AI に段階的に生成させる（まず骨格を生成してから機能を補う）；[examples/](../../examples/) 目录の例を参考にして、追加のコンテキストを提供してください。

**MCP 接続後、AI が `search_docs` を呼び出していない？**  
クライアントが該当のサーバーをロードしているか確認してください（**クライアントを再起動するとツールが有効になっていることが確認できます**）；一部のクライアントでは、プロンプト内で「ErisPulse ドキュメントツールを使用して API を確認する」ことを明示的に指示する必要があります。
