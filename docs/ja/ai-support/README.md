# AI アシスト開発

ErisPulse は、事前に構築された AI 物料ドキュメントを提供しており、これを AI モデルにコンテキストとして提供することで、フレームワークの仕様に準拠したモジュールおよびアダプターのコードを生成できます。

## 物料ドキュメント

物料ドキュメントは、本ディレクトリの `prompts/` サブディレクトリに格納されており、開発シナリオに応じて3種類に分かれています：

| ドキュメント名 | 適用シナリオ | コンテンツ規模 | 用途 |
|---------|----------|---------|--------|
| **ErisPulse-ModuleDev.md** | モジュール開発 | 中程度 | モジュール開発の全工程をカバーし、ほとんどのシナリオに適しています |
| **ErisPulse-AdapterDev.md** | アダプター開発 | 中程度 | アダプター開発の全工程をカバーし、プラットフォーム適応規格を含む |
| **ErisPulse-Full.md** | 全体開発リファレンス | 大規模 | 完全な開発ドキュメントの集合。大容量のコンテキスト窓を持つモデルが必要です |

### 各ドキュメントのカバー範囲

**ModuleDev** には、以下の内容が含まれています：
- 基本概念
- イベント処理の入門
- モジュールのコア概念
- Eventラッパークラス
- Conversation 多段対話
- MessageBuilder
- ルーティングシステム
- ライフサイクル管理
- 慣性読み込みシステム
- 会話タイプの標準
- モジュールのリリースプロセス

**AdapterDev** には、上記の基礎内容に加えて、以下の内容が含まれています：
- アダプターのコア概念
- SendDSL チェーン呼び出し
- イベント変換器の設計
- イベント変換/APIレスポンス/送信メソッドの3つの技術規格
- 全てのプラットフォーム適応ガイド
- ドキュメント文字列の規格

**Full** には、上記の全ての内容に加えて、以下の内容が含まれています：
- 完全なユーザーガイド（インストール、設定、デプロイ）
- 全てのAPIリファレンス
- 知られている問題の追跡

コンテキスト窓が 128K tokens 以上のモデルでのみ推奨します。

### 最新バージョンの入手

物料ドキュメントは、フレームワークのリリースに伴い自動的に更新されます。入手方法は以下の通りです：

- `prompts/` ディレクトリから直接入手（ドキュメントと同期して更新されます）
- [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases) から対応するバージョンをダウンロード

## 使用手順

### 1. 物料ドキュメントの選択

開発の目的に応じて、適切なドキュメントを選択します：

- 機能モジュールの開発 → `ErisPulse-ModuleDev.md`
- プラットフォームアダプターの開発 → `ErisPulse-AdapterDev.md`
- 開発目標が不明または複雑な場合 → `ErisPulse-Full.md`（モデルのコンテキスト窓が十分に大きいことを確認してください）

### 2. コンテキストの提供

選択した物料ドキュメントの内容を AI に提供します。使用するツールに応じて、以下のように行います：

- **IDE内統合AI（Copilot / Cursor）**：ドキュメントをワークスペースに配置するか、対話中に直接貼り付ける
- **対話型AI（ChatGPT / Claude）**：対話の冒頭にドキュメントを貼り付け、「以下のドキュメントを知識ベースとして使用して回答してください」と指示する
- **API呼び出し**：ドキュメントを system message またはコンテキストとして注入する

### 3. 要求の記述

以下のテンプレートを使用して、要件を詳細に記述し、AIに送信します。記述が具体的であればあるほど、生成されるコードの品質が高くなります。

### 4. 生成結果の検証

AIがコードを生成した後は、以下の点を確認することをお勧めします：

1. 生成されたコードが正しい基底クラスを継承しているか（`BaseModule` または `BaseAdapter`）
2. イベントハンドラが正しいデコレータを使用しているか（`@message.on_message` 等）
3. `epsdk create module` または `epsdk create adapter` を実行してプロジェクトの骨格を作成し、生成されたコードを対応するファイルに挿入する
4. テストを実行して、機能が正常に動作しているか確認する

## 要求記述テンプレート

### モジュール要件

```
ErisPulse モジュール開発規格に基づき、[モジュール名] モジュールの完全なコードを生成してください。

機能説明：
[モジュールのコア機能を記述]

リッスンするイベント：
- イベントタイプ：[メッセージ / コマンド / 通知 / 要求]
- 処理ロジック：[イベントがトリガーされた際の処理内容を記述]

必要な設定項目：
- [設定キー名]：[用途説明]（[必須/オプション]、デフォルト値：[値]）

その他の要求：
- [追加の機能や制約]
```

### アダプター要件

```
ErisPulse アダプター開発規格に基づき、[アダプター名] アダプターの完全なコードを生成してください。

プラットフォーム情報：
- プラットフォーム名：[名称]
- 通信プロトコル：[WebSocket / WebHook / HTTP ポーリング]
- APIドキュメントのURL：[存在する場合]

イベント変換：
- プラットフォームのイベントタイプ：[プラットフォームの主要なイベントをリストアップ]
- OneBot12 とのマッピング：[プラットフォームイベントから OB12 標準へのマッピングを記述]

実装する送信メソッド：
- [テキスト / 画像 / 音声等のメッセージタイプ]：[実装が必要か]

設定項目：
- [設定キー名]：[用途説明]（[必須/オプション]）
```

## よくある質問

**推奨されるAIツールは？**

- IDE統合型：Cursor、VS Code + Copilot —— ファイルシステムを直接操作でき、プロジェクトレベルの開発に適しています
- 対話型：ChatGPT、Claude —— プロトタイプや単一ファイルの生成に適しています
- API呼び出し：バッチ生成やCI統合の場面に適しています

**生成されたコードが期待通りでない場合はどうすればよいですか？**

1. 完全かつ正しい物料ドキュメントが提供されているか確認する
2. 要求記述に詳細を追加する（具体的な入出力例、境界条件等）
3. AIに段階的に生成させる：まず骨格コードを生成し、問題なければ機能を段階的に追加する
4. [examples/](../../examples/) ディレクトリにある例コードを参照し、追加のコンテキストとして提供する

**生成品質を向上させるにはどうすればよいですか？**

- 要求にモジュール名、継承する基底クラスを明確に指定する
- 具体的なメッセージフォーマットの例を提供する（プラットフォームの元イベント → 期待する OB12 形式）
- AIにテストコードの生成も依頼する
- アダプターの場合、プラットフォームのAPIドキュメントの重要なインターフェース情報を追加で提供する
