# AI支援開発

ErisPulse は、最新のフレームワーク規格に基づいてコードを生成できる、2 種類の補完的な AI 支援開発方法を提供しています。

- **マテリアルドキュメント**：一度にコンテキストを注入できる大規模な Markdown ファイル。プロジェクト全体の開発に適しています。
- **MCP サーバー**：AI が必要なときに公式ドキュメントを検索できる仕組み。日常的なコード補完や API 検索に適しています。

| | マテリアルドキュメント | MCP サーバー |
|---|---|---|
| 形式 | 1 つの大規模な Markdown ファイル。**一度に注入** | AI が**必要なときに検索** |
| コンテキストコスト | 高い（token を消費） | 低い（関連する断片のみ取得） |
| 時効性 | バージョンリリースごとに更新 | 実時（GitHub から取得 + キャッシュ） |
| 適用場面 | コンテキストウィンドウが大きく、プロジェクト全体の開発に適している | 日常的なコード補完、API 検索 |
| クライアント | 任意の AI ツール | MCP をサポートするクライアントのみ |

これらは互いに矛盾するものではなく、大規模なプロジェクトの開発時には両方を併用できます。マテリアルドキュメントで基礎を固め、MCP で漏れを補うという使い方が可能です。

## マテリアルドキュメント

マテリアルドキュメントは `prompts/` ディレクトリにあり、開発シナリオに応じて3種類に分かれています。

| ドキュメント | シナリオ | 説明 |
|------|------|------|
| **ErisPulse-ModuleDev.md** | モジュール開発 | モジュール開発の全フローをカバー（イベント処理、ルーティング、ライフサイクルなど） |
| **ErisPulse-AdapterDev.md** | アダプタ開発 | モジュール開発の上に、アダプタのコアコンセプト、SendDSL、プラットフォーム適応ガイドを追加 |
| **ErisPulse-Full.md** | フルスタックリファレンス | 上記すべて + 完全なユーザーガイドとAPIリファレンスのまとめ |

入手方法：`prompts/` ディレクトリから直接取得（ドキュメントと同期して更新）、または [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases) から対応バージョンをダウンロード。

### 使用方法

1. 目的に応じてドキュメントを選択（モジュール → `ModuleDev`、アダプタ → `AdapterDev`、複雑な要件 → `Full`）
2. ドキュメントの内容をAIにコンテキストとして提供：IDE内にワークスペースに配置、対話形式では直接貼り付け、API呼び出しではsystem messageとして注入
3. 下記テンプレートに従って要望を記述。具体的に記述するほど生成品質が向上します。

### 要望記述テンプレート

**モジュール：**

```
ErisPulse モジュール開発規格に基づき、[モジュール名] モジュールの完全なコードを生成してください。

機能説明：[コア機能]
監視する必要のあるイベント：[メッセージ / コマンド / 通知 / 要求]、処理ロジック：[操作]
必要な設定項目：[キー名]：[用途]（[必須/任意]、デフォルト値：[値]）
その他の要件：[追加の制約]
```

**アダプタ：**

```
ErisPulse アダプタ開発規格に基づき、[アダプタ名] アダプタの完全なコードを生成してください。

プラットフォーム情報：[名称]、通信プロトコル：[WebSocket / WebHook / HTTPポーリング]、APIドキュメント：[アドレス]
イベント変換：プラットフォームイベント [種類] → OneBot12 へのマッピング [関係]
実装する必要のある送信メソッド：[テキスト / 画像 / 音声 ...]
設定項目：[キー名]：[用途]（[必須/任意]）
```

## MCP サーバー

ErisPulse は、AI コーディングアシスタント（MCP をサポートするものであればすべて）がコードを書く際に、ErisPulse 公式ドキュメントを直接検索・参照できるようにするドキュメント検索用 MCP サーバーを提供しています。

接続方法は 2 種類あります：**ローカルプロセス（推奨）**または**公式オンラインエンドポイント**。両方とも同じツールセットを使用します。

| ツール | パラメータ | 説明 |
|------|------|------|
| **`search_docs`** | `query` (必須), `top_k?=5`, `lang?=zh-CN` | BM25 キーワード検索。複数のキーワードを一度に送信できます。 |
| **`read_document`** | `doc_path` (必須), `lang?=zh-CN` | 1 つのドキュメントの完全な Markdown を読み込みます。 |
| **`list_documents`** | `lang?=zh-CN` | 現在の言語でサポートされているすべてのドキュメントのタイトル、パス、カテゴリをリストアップします。 |
| **`list_languages`** | — | ドキュメントでサポートされているすべての言語とドキュメント数をリストアップします。 |

サポート言語：`zh-CN` / `en` / `zh-TW` / `ja` / `ru`。検索のコツ：**1 文ではなく複数のキーワード**を使用してください。たとえば `命令登録 イベントリスナー` は `どうやってコマンドを登録するか` よりも効果的です。

### 方法 1：ローカルプロセス（推奨）

インストール後にローカルで起動します：

```bash
npm i -g @erisdev/mcp-server   # グローバルインストール → epsdk-mcp コマンドが利用可能になります
epsdk-mcp --server               # MCP サービスを起動；初回実行時にドキュメントが ~/.cache/erispulse-mcp/docs に自動的にダウンロードされます
```

グローバルインストールせずに `npx` で直接実行することも可能です（インストール不要）：

```bash
npx @erisdev/mcp-server --server
```

ローカルのドキュメントディレクトリがある場合は、それを指定して（インターネット接続なし）起動します：

```bash
ERISPULSE_DOCS_DIR=/path/to/erispulse/docs epsdk-mcp --server
```

MCP クライアントで **stdio 伝送**を設定し、標準のキー値（`command` と `args` は上記の起動方法を指します；具体的な設定位置と形式は、各クライアント独自の MCP 接続ドキュメントを参照してください）：

```json
{
  "command": "epsdk-mcp",
  "args": ["--server"]
}
```

または

```json
{
  "command": "npx",
  "args": ["@erisdev/mcp-server", "--server"]
}
```

### 方法 2：公式オンラインエンドポイント

ローカルでプロセスを起動したくない場合は、公式がホストしている [`mcp.erisdev.com`](https://mcp.erisdev.com/) に接続してください。MCP クライアントで **HTTP 伝送**を設定します：

```json
{
  "url": "https://mcp.erisdev.com/"
}
```

サービスはデフォルトで公開されており、Token は必要ありません。IP ごとのリクエスト制限（1 IP あたり 1 分間に 60 回）が適用されます。公式エンドポイントはいつでも停止される可能性があるため、**本番環境での作業には方法 1（ローカルプロセス）または自前ホストを推奨します**。

## 常見問題

**生成されたコードが期待通りでない？**  
完全なドキュメントを提供しているか確認してください。要求に詳細を追加してください（入出力の例、境界条件）；AI にステップごとに生成させましょう（まず骨格を生成してから機能を補う）；[examples/](../../examples/) ディレクトリの例を参考にして、コンテキストを補足してください。

**MCP 接続後に AI が `search_docs` を呼び出していない？**  
クライアントが該当サーバーをロードしているか確認してください（**クライアントを再起動するとツールが有効になることが確認できます**）；一部のクライアントでは、プロンプトに「ErisPulse ドキュメントツールを使って API を確認する」と明示的に指示する必要があります。
