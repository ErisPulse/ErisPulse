# ErisPulse ワークベンチ

> [!TIP]  
> **この記事を読む必要があるとき**：モジュールやアダプターをモジュールストアに提出する場合、モジュールに `plugin-xxx.erisdev.com` のウェブサイトアドレスを申請する場合、スクリプトや CI を使ってモジュールを自動的に提出する場合、または自分のウェブサイトに「ErisPulse アカウントでログイン」をサポートする場合に読んでください。必要なければ飛ばしてください。

[ErisPulse ワークベンチ](https://workbench.erisdev.com/) はエコシステムの**統一されたアカウント管理とクリエイター用バックエンド**です。1 つのアカウントでモジュールストア、ホスティングドメイン、およびオープンインターフェースを一括管理できます。これは純粋なオンラインサービスであり、**パッケージをインストールする必要はありません**——ウェブページを開き、ログインするだけで使用できます。

```text
GitHub / Codeberg / 雲湖 / 電子メールアドレスでログイン
            │
            ▼
      ErisPulse アカウント ──── 二段階認証（オプション）
            │
   ┌────────┼─────────────┬──────────────┐
   ▼        ▼             ▼              ▼
モジュール管理   ホスティングドメイン      アクセストークン      OAuth アプリ
（ストア）  （ウェブサイトアドレス）  （スクリプト/CI）  （サードパーティログイン）
```

## ログインとアカウント

ワークベンチは4種類のログイン方法をサポートしており、設定されていないログイン方法はログインページに表示されません。

| 方法 | 適用される場面 |
|------|---------|
| GitHub | GitHubにモジュールのコードをホストしている開発者 |
| Codeberg | Codebergにモジュールのコードをホストしている開発者 |
| 雲湖 | 雲湖プラットフォームを使用しているユーザー |
| メールアドレス | 上記のアカウントを持たないユーザー：ユーザー名 + メールアドレス + パスワード、登録時にメールで受け取った6桁の認証コードを入力する必要があります |

> [!NOTE]
> 同一アカウントは「個人情報」ページで複数のログインIDをバインドできます。異なるログイン方法でログインした後にバインドすることで、次回はいずれの方法を使っても同じアカウントにログインできます。

**二段階認証**：「個人情報」ページで、動的口令（TOTP）に基づく二段階認証を有効化できます。任意の認証アプリでQRコードをスキャンするだけで有効化できます。有効化後、ログインやモジュールの削除、ドメインの削除などの機密操作を行うには動的コードの入力が必要です。

> [!WARNING]
> 動的口令の秘密鍵は**有効化時に一度のみ表示されます**。秘密鍵を失うとログインできなくなるため、必ず安全に保管してください。

## モジュール管理

モジュールストアに収録されているすべてのモジュールとアダプターは、ワークベンチで管理されます。

### モジュールの登録

1. 左側のメニューから「新規モジュールの登録」に進みます。
2. フォームを記入します：

| 項目 | 説明 |
|------|------|
| 名前 | モジュール名。entry-point のキー名と一致する必要があります |
| タイプ | `module`（機能モジュール）または `adapter`（アダプター） |
| PyPI パッケージ名 | 例: `ErisPulse-MyModule` |
| 説明 | 10 文字以上 |
| 作者 | ストアに表示される作者名 |
| 仓库アドレス | `github.com` または `codeberg.org` 上のリポジトリ |
| カテゴリ | ツール / 娯楽 / 管理 / 通知 / AI / プラットフォーム / 分析 |
| タグ、多言語、最低 SDK バージョン | 任意 |

3. 提出後、モジュールインデックスリポジトリから配信され、**通常数分以内**にストアに表示されます。

新しく提出されたモジュールは初期状態で「未検証」です。これは公式の審査を通過していないことを意味し、ユーザーがインストールする際にリスク警告が表示されます。審査が通過すると「検証済み」に変更されます。

### 編集と一括操作

「モジュールリスト」から自分のモジュールの詳細ページに移動すると、説明、リポジトリアドレス、カテゴリ、タグなどのすべてのメタデータを変更したり、モジュールのアイコンをアップロードしたりできます。また、複数選択モードを有効にして、複数のモジュールに対して**一括認証 / 認証解除 / 削除**を行うことも可能です（一括操作では、一度だけ動的コードを入力する必要があります）。

### 所有権の認領

モジュールストアに既に存在しているが、あなたが登録していないモジュール（例：初期段階で他人が代わりに登録した場合）は、自分のアカウントに認領することができます。

- **自動認領**：モジュールリポジトリと同じ GitHub / Codeberg アカウントでログインすると、システムがリポジトリの所有者が一致していると認識し、自動的に認領されます。
- **手動認領**：モジュールの詳細ページで「このモジュールを認領する」をクリックし、理由を記入して管理者による審査を経て移転されます。

## 所有ドメイン

登録された各モジュールは、`plugin-モジュール名.erisdev.com` の形式で、モジュールのホームページ、ドキュメント、またはデモサイトを配置するための無料のウェブサイトアドレスを申請できます。

| 制限 | 数値 |
|------|------|
| 各モジュール | 2 個のドメイン |
| 各アカウント | 10 個のドメイン |
| 検証が完了していない場合 | 7 日後に解放され、ドメインは他の人に再申請される可能性があります |

### 4 つの接続方法

| 方法 | 使用方法 | 適合 |
|------|--------|------|
| **リポジトリブランチ**（推奨） | リポジトリのアドレスとブランチ名を入力し、ワークスペースがそのブランチの静的ファイルを直接読み取ります | サイトのソースコードがモジュールのリポジトリにあり、プッシュするだけで更新されます |
| **リダイレクト** | そのドメインにアクセスすると、指定した `https://` アドレスに 301 リダイレクトされます | 既に独自のウェブサイトがあり、ただ良い記憶の入口が欲しい場合 |
| **独自サーバー** | CNAME / A / AAAA レコードを追加し、独自のサーバーに指向します | 自分でサイトをデプロイしている場合 |
| 静的サイトのアップロード | zip パッケージをアップロードし、プラットフォームのオブジェクトストレージでホストします | 一時的にテスト版のみ、全面公開はされていません |

「リポジトリブランチ」のブランチ名はデフォルトで `ep-site` です。これは、サイトのブランチ名として一般的に使われる名前です。サイトのファイルをこの独立したブランチに配置することを推奨します。これにより、メインブランチのコードが汚染されません。

### 申請プロセス

1. 左側の「所有ドメイン」に進み、ドメインを割り当てたいモジュールを選択します（自分の名義のモジュールのみ選択できます）
2. プレフィックスを入力し、入力時に即時利用可能かどうかをチェックします。プレフィックスは小文字のアルファベット、数字、および中央のハイフンのみを許可します
3. 接続方法を選択し、対応する情報を入力して、申請します

**審査ルール**：各モジュールの**最初のドメインは直接有効になります**。2 番目以降のドメインは管理者の審査が必要で、審査結果はメールで通知されます。

### 所有権の検証

ドメインが自分のリポジトリやサーバーに属していないことを防ぐために、「リポジトリブランチ」と「独自サーバー」の 2 つの方法では所有権の検証が必要です：

| 方法 | 検証方法 |
|------|---------|
| リポジトリブランチ | そのブランチのルートディレクトリに `erisdev-site-verify.txt` というファイルを置き、ワークスペースから提供された検証コードを記述します |
| 独自サーバー | あなたのサーバー上に `/.well-known/erisdev-verify.txt` を提供し、上記と同じ内容を記述します |

ファイルを配置した後、ワークスペースに戻って「所有権検証完了」をクリックします。検証が完了する前は、そのドメインにアクセスすると「所有権検証を待っています」という表示ページが表示されます。

### 管理操作

各ドメインのカードには以下のような操作が可能です：

- **一時停止 / 再開**：一時停止すると、アクセス時に「サイトは一時停止されています」と表示され、コンテンツは保持されます
- **削除**：そのドメインとすべてのホストされたリソースを解放し、動的コードを入力する必要があります
- **リポジトリやブランチの変更**：変更後、再検証状態に戻り、再検証することで有効になります

## オープンインターフェース

ワークベンチは、OAuth 2.0 認証サーバとしても機能し、外部に以下の 2 つの機能を提供します。

### アクセストークン

スクリプトや CI でワークベンチの API を呼び出す場合（例：モジュールの自動提出）には、アカウントのパスワードの代わりにアクセストークンを使用します。

1. 「オープンプラットフォーム → アクセストークン」に進み、名前を入力して「トークン生成」をクリックします。
2. トークンの形式は `epat_` + 40 文字の 16 進数です。**生成時に一度だけ表示されます。**
3. リクエストでは、`Authorization: Bearer epat_…` ヘッダーにトークンを含めます。

各アカウントは最大 10 個のトークンを持つことができます。2 段階認証を有効にしたアカウントは、「動的コード不要」にチェックを入れることができます。これにより、このトークンを使ってセンシティブな API を呼び出す際、動的コードの入力を不要とします。CI の自動化に適しています。

> [!TIP]
> リクエスト本文は UTF-8 エンコードの JSON でなければなりません。Windows ターミナルのデフォルトは GBK です。このため、直接 Chinese 文字を送信するとサーバ側で拒否されます。`chcp 65001` を実行するか、リクエスト本文をファイルに保存して `curl --data-binary @body.json` を使用して送信してください。

### OAuth アプリケーション

独自のウェブサイトやツールに「ErisPulse アカウントでログイン」をサポートさせたい場合：

1. 「オープンプラットフォーム」に進み、アプリケーションを登録します。名称とコールバック URL（複数指定可能）を入力します。
2. `client_id` と `client_secret` を取得します。**秘密鍵は一度しか表示されません。** いつでもリセットできます。
3. 標準の OAuth 2.0 認可コードフローに従って接続します：

| エンドポイント | 用途 |
|------|------|
| `/oauth/authorize` | ユーザーに認可を促す |
| `/oauth/token` | 認可コードからトークンを取得 |
| `/api/userinfo` | トークンを使ってユーザー情報を取得（メールアドレスは含まれません） |

各アカウントは最大 5 個のアプリケーションを登録できます。

## よくある質問

### モジュールを提出した後、すぐにストアに表示されないのはなぜですか？

モジュールの収録はモジュールインデックスリポジトリから非同期で配信され、通常数分以内に有効になります。モジュールリストで操作ステータスを確認し、「適用済み」が表示されていれば成功です。

### ドメインの検証が一向に通らないのはなぜですか？

検証ファイルの**パスと内容**がワークベンチで表示されているものと完全に一致しているか確認してください（パスは大文字小文字を区別し、内容に余分な空白や改行がないようにしてください）。リポジトリのブランチ方式では、ファイルが**入力したブランチ**上にあるかも確認してください。

### ドメイン申請後、どのくらいで有効になりますか？

「リポジトリのブランチ」と「リダイレクト」の場合は、検証が通った後は即座に有効になります。「独自サーバー」の場合は、DNSレコードがグローバルに伝播するのを待つ必要があります。通常数分です。
