# 文档与对外写作规则

本页规范 ErisPulse 的文档行文与对外（README/发布页）写作。目标读者是文档贡献者与维护 README 的人。

## 一、文档行文

### 1. 价值先行

每篇文档的第一屏回答一个问题："读这篇我能得到什么"。按需查阅类文档用统一的 `> [!TIP]` 触发描述开头——**"什么时候需要读这篇：……不需要则跳过"**；核心必读类用 `> [!NOTE]` 标注其在阅读路径中的位置。

### 2. 实例优先于叙述

能用可运行代码块说明的，不写描述性段落。代码示例必须可直接复制运行（含 import 与最小上下文），不给 `...` 省略关键步骤。

### 3. 触发描述即检索入口

文档开头的一句"什么时候读"就是 AI 助手与搜索的匹配文本——写具体场景（"当你的适配器需要……"），不写抽象归类（"本文介绍……"）。

### 4. 结尾按意图分组

文末"下一步"链接按读者意图分组（想深入 X → 链 A；遇到问题 Y → 链 B），不放无差别目录平铺。

### 5. 变更记录写作

更新日志记录发布状态之间的净差异，不记录开发过程：同一主题多次修改更新既有条目为最终形态；版内引入又版内修复的不单列；无用户感知的内部调整不记。完整规范见 `CHANGELOG.md` 头部「写作规范」。

### 6. 版本标注规范

文档正文的版本标注只写**行为差异**，不写准入门槛：

- **正文标注行为差异**：仅在行为随版本变化时标注，且必须说清"差异是什么"——例如"X.Y.Z 起 `reload()` 默认全量重载（此前仅重载变更模块）"。读者据此判断自己的代码在新旧版本下行为是否不同
- **"本特性需要 X+"类准入标注集中到版本速查表**：不散落在各篇正文；统一收敛在 `docs/zh-CN/README.md` 的版本速查表，正文需要时链接过去即可
- **示例中的版本号用占位符**：文档示例代码里出现的版本号写 `x.y.z` 等占位形式，避免随发布频发过时（正文标注真实版本号的行为差异除外）

## 二、对外页面（README / 发布页）

### 1. 三段式骨架

1. **价值主张**：一句话说清"用它能做什么"，紧接 30 秒可验证的效果（最小示例 / 演示视频 / 截图）
2. **证明**：功能卡片、真实运行截图、生态规模——证据按说服力排序，不堆砌
3. **行动入口**：安装命令一行可复制；每条主要路径（快速上手 / 深入开发 / 生态浏览）给出明确下一步链接

### 2. 场景化而非罗列

功能列表每条回答"解决什么问题"，而非"我们有什么"。生态展示每项附一句适用场景与最小示例，不贴 logo 了事。

### 3. 语言与口径

- **主版语言**：现状——以中文（zh-CN）为文档主源，英文等其余语言由 CI 翻译流程从 zh-CN 自动生成（只改 `docs/zh-CN`，其它语言随 CI 同步）；目标——长期演进为英文主版。在目标达成前，对外页面按"中文主源、多语言翻译产物"维护，其余语言不标注"待同步"（CI 保证自动同步）
- 不在对外页面使用内部行话（模块代号、里程碑名、内部流程词）——读者是第一次见到项目的人
- 数字与承诺（版本、性能、支持范围）必须与文档正文一致，过期内容宁删勿留

### 4. 快速上手页的转化结构

`quick-start` 类页面：先给"60 秒效果"（安装 → 三行代码 → 运行结果），再展开解释；用户先看到成功，才愿意继续读。
