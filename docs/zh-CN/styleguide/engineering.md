# 工程健壮性规则

本页是 ErisPulse 源码的健壮性纪律。每条规则给出"为什么"与本仓库的真实案例；贡献代码前请过一遍本页，CI 之外的部分靠评审执行。

## 1. 异常留痕分级

`except` 不是垃圾桶。捕获异常后做什么，取决于你吞掉的是什么：

| 类别 | 判定 | 处理 |
|------|------|------|
| 探测型 | 失败后有安全默认值，且失败方向无害（如探测实例属性名回退类名） | `pass` 可接受 |
| 降级型 | 失败后走替代路径，但仍值得知道（如可选依赖缺失） | `logger.debug` 留痕 |
| 资源释放型 | 连接、文件句柄、线程、任务的关闭路径 | 至少 `logger.debug`，重复出现升级 `warning` |
| 数据写入型 | 配置落盘、消息记录、状态持久化的写入路径 | `warning` 起步——静默丢数据无法事后排查 |

**禁止双层降级**：不要把"日志调用本身"再包进 `try/except: pass`——告警在异常条件下消失等于没有告警。

反面案例（均已修复，留作范式）：

- 配置管理器 `close()` 内最后一次刷盘失败被静默吞掉——用户改了配置关进程，改动无痕迹丢失
- HTTP 客户端替换会话时旧会话 `close()` 失败被静默吞掉——连接资源泄漏
- 初始化重复调用的 `warning` 本身被 `try/except: pass` 包裹——i18n 未就绪时告警消失

## 2. 日志分级纪律

- **失败事件最低 `warning`**：重试耗尽、回滚触发、订阅方回调失败、状态重放失败——这些意味着"系统状态与预期不一致"，`debug` 级别等于对用户隐身
- **循环内失败必须节流**：清扫循环、watcher、后台 GC 里的重复异常，用"首次 warning + 后续计数/冷却"或降为 `debug` 加周期汇总，防止日志刷屏
- `trace` 只用于高频热路径的正常流水；`error` 留给已影响请求结果的失败

## 3. 行为参数集中

超时、重试次数、冷却期、轮询间隔一律定义在 `Core/constants.py`（CLI 侧行为参数同样进该文件），命名 `*_TIMEOUT_SECS` / `*_RETRY_*` / `*_COOLDOWN_SECS`，并在注释里写明使用位置。实现文件禁止出现裸数字超时（`timeout=30`、`sleep(5)`）——同一语义的裸值散落多处是漂移的起点。

**边界**：此规则约束核心仓库；第三方模块 / 适配器建议在自身模块内集中定义行为参数，不强制定位到 `Core/constants.py`。

## 4. 公共 API 契约

无前导下划线的类与方法必须同时具备：完整 docstring（参照 [注释风格规范](docstring.md)）、全部参数与返回值类型标注。内部实现（`_` 前缀）可以放宽，但一旦出现在文档或示例里即按公共标准对待。

**存量边界**：以上要求以**新增 / 触碰的文件**为准，不强制对存量代码全量回填；存量问题在检查中以基线方式呈现，文件被触碰时其存量问题升级为阻断。

## 5. 单例回引禁忌

框架组件（管理器、加载器、基类）不得持有"根 SDK 单例"的回引字段：

- 回引字段意味着组件生命周期与装配顺序耦合，一旦装配方忘记接线，功能**静默失效**而非报错——本项目曾因 `set_sdk_ref` 调用方被移除，热重载/依赖通知在六个发布版本里静默失效
- 需要根引用时：构造注入（组合根传入）或惰性解析（首次使用时导入），二选一；惰性解析永远不能"忘记调用"
- 需要他人状态时优先走事件订阅或门面，不要伸手进别人的注册表；管理器实例自有状态必须自清，不得经全局门面绕行（门面内部是单例回引，覆盖不了独立实例）

## 6. 清理与回滚纪律

- 卸载/清理路径必须幂等：半途失败重试、重复卸载都不得二次释放或抛错
- 不可逆操作（卸载、重载、删配置）前先拍快照；快照回滚是"尽力而为"语义，回滚失败必须留 `warning`
- 清理顺序：任务取消 → 连接关闭 → 外部钩子 → 注册表回收，各步独立容错，单步失败不阻断后续

## 7. 测试纪律

- 改行为必改测试；修 bug 必须先有能复现该 bug 的红测试
- 异常路径与边界（空输入、超时、重复调用、半初始化）与正常路径同等对待——回归防护网是重构的底气
- 测试允许访问内部结构，但访问点应集中：内部布局变更时迁移测试改的是 import 与路径，不是断言语义

**存量边界**：以上纪律以**新增 / 触碰的文件**为准，不强制对存量代码全量回补测试；存量覆盖缺口在检查中以基线方式呈现，文件被触碰时其存量问题升级为阻断。
