# Продвинутые темы

В этом каталоге собраны продвинутые тематические материалы фреймворка ErisPulse — управление правами доступа, канареечные релизы, многоэтапное взаимодействие, бэкенды хранения
и другие глубокие возможности; каждая статья решает конкретный класс задач.

> [!NOTE]
> Все документы в этом каталоге — тематические статьи **для изучения по мере необходимости**. Сначала прочитайте пять основных статей уровня L1 на главной странице,
> а затем возвращайтесь сюда при возникновении соответствующих задач. В начале каждой статьи указано «когда следует читать эту статью».

## Четыре обязательные статьи L2

Четыре статьи, без которых не обойтись при написании production-модулей; рекомендуется прочитать их целиком перед созданием сложных модулей (подход согласован с главной страницей документации):

- [Область видимости (scope)](scope.md) - трёхмерное управление областью видимости: доступность модулей / допуск событий / ограничения исходящих действий (включая правила детальной гранулярности на уровне методов и merge при наследовании привязок)
- [Система владения (owner)](ownership.md) - принадлежность ресурсов и автоматическое освобождение: механизм owner-контекста, полный обзор принадлежащих ресурсов, последовательность очистки при выгрузке, границы hot reload и границы дизайна
- [Управление жизненным циклом](lifecycle.md) - система событий жизненного цикла: что именно делать при загрузке, выгрузке, перезагрузке и отключении модулей / адаптеров
- [Система интерактивных сессий](interaction.md) - wait_reply / таймеры сессий / многоканальное ожидание / взаимоисключающая аренда сессий / входящие сообщения / транзакции сообщений / трассировка цепочки вызовов

## Группировка по сценариям

Группировка согласована со структурой раздела «Глубокое понимание принципов» на главной странице документации; в первом документе каждой группы отмечено, «какие подводные камни подстерегают, если этого не понимать».

**Запуск и работа** — не понимая цепочку запуска (Finder / Loader / Manager / Router), при сбое загрузки модуля остаётся лишь бессильно смотреть в логи

- [Процесс запуска и ручное управление](startup.md) - Разбор цепочки запуска (Finder/Loader/Manager/Router) и полный ручной запуск
- [Система ленивой загрузки](lazy-loading.md) - Принципы работы системы ленивой загрузки модулей, конфигурация и ленивая активация по событиям (activate_on)

**Связь и подключения** — не зная белого списка сервисных контрактов (`meta.services`), вы столкнётесь с тем, что межмодульный вызов `module.call` будет отклонён с `ServiceNotProvidedError`, и не поймёте причину

- [Межмодульное взаимодействие](module-communication.md) - Протоколирование RPC (module.call), сервисные контракты и их реестр, адресные события, воспроизведение при холодном старте, идемпотентная дедупликация событий
- [Пул соединений и широковещательная рассылка](connections.md) - Реестр соединений: рассылка, групповые подписки, межмодульная передача и переиспользование, просмотр пула соединений
- [Менеджер маршрутов](router.md) - Управление маршрутами HTTP и WebSocket (включая регистрацию с одним параметром и соглашение о кортежных ответах)

**Хранение данных** — не понимая семантики периода охлаждения после сбоя подключения, при нестабильности базы данных можно ошибочно решить, что «фреймворк сломался» (на самом деле это быстрый отказ с автоматическим переподключением после охлаждения)

- [Бэкенды хранения](storage-backends.md) - Выбор, конфигурация и переключение асинхронных нативных бэкендов хранения sqlite / mysql / postgres
- [Конструктор SQL-запросов](sql-builder.md) - Универсальный конструктор цепочечных SQL-запросов и абстракция бэкендов хранения
- [Сетевой клиент](client.md) - Единый клиент HTTP-запросов

**Сообщения и диалоги** — не зная о взаимоисключающих арендах сессий, вы получите ситуацию, когда два модуля, одновременно ожидающие ответа одного и того же пользователя, будут вытеснять аренду друг друга

- [Многошаговые диалоги Conversation](conversation.md) - Методы взаимодействия с контекстом многошагового диалога
- [Транскрипт сессий](transcript.md) - Автоматическая запись сообщений: параметры политики хранения, API переопределения во время выполнения, риски и аудит
- [Подробно о MessageBuilder](message-builder.md) - Двухрежимное использование конструктора сегментов сообщений OneBot12
- [Интернационализация (i18n)](i18n.md) - Поддержка нескольких языков, регистрация переводов и определение языка

**Тени и поэтапный выпуск** — не разобравшись с пятью барьерами изоляции и преждевременно переведя модуль в основной режим, вы рискуете: исходящие сообщения тени будут утекать к реальным пользователям

- [Теневые модули и перевод в основной режим](shadow.md) - Параллельный пробный запуск новой версии модуля с отдельным owner: перехват и учёт исходящих сообщений, сравнение diff поведения, перевод в основной режим (promote) и откат при сбое

**Исключения и справочник стандартов**

- [Система исключений и руководство по перехвату](errors.md) - Все типы исключений фреймворка, места их возникновения и рекомендации по перехвату
- [Система типов сессий](../standards/session-types.md) - Определения типов сессий, отображения (маппинг) и регистрация пользовательских типов

> [!NOTE]
> Документация **сторонних модулей экосистемы**, таких как регистрация окон Dashboard и рендеринг изображений Takumi, перенесена в каталог [Модули экосистемы](../ecosystem/README.md).
