# Продвинутые темы

В этом каталоге собраны продвинутые тематические материалы фреймворка ErisPulse — управление правами доступа, канареечные релизы, многоэтапное взаимодействие, бэкенды хранения
и другие глубокие возможности; каждая статья решает конкретный класс задач.

> [!NOTE]
> Все документы в этом каталоге — тематические статьи **для изучения по мере необходимости**. Сначала прочитайте пять основных статей уровня L1 на главной странице,
> а затем возвращайтесь сюда при возникновении соответствующих задач. В начале каждой статьи указано «когда следует читать эту статью».

## Четыре обязательные статьи уровня L2

Четыре статьи, без которых не обойтись при написании production-модулей; рекомендуется прочитать их целиком перед созданием сложных модулей (терминология согласована с главной страницей документации):

- [Область видимости (scope)](scope.md) - трёхмерное управление областью видимости: доступность модуля / допуск событий / ограничение исходящих действий (включая детализированные правила на уровне методов и merge при наследовании привязок)
- [Система владения (owner)](ownership.md) - принадлежность ресурсов и автоматическое освобождение: механизм контекста owner, полный обзор владеемых ресурсов, последовательность очистки при выгрузке и границы проектирования
- [Управление жизненным циклом](lifecycle.md) - система событий жизненного цикла: что должен делать модуль / адаптер при загрузке, выгрузке, перезагрузке и отключении
- [Система интерактивных сессий](interaction.md) - wait_reply / таймеры сессий / многоканальное ожидание / взаимоисключающие аренды сессий / почтовый ящик / транзакции сообщений / трассировка цепочки вызовов

## Группировка по сценариям

Группировка согласуется с разделом «Глубокое понимание принципов» на главной странице документации; в первом документе каждой группы указано, «какие подводные камни вас ожидают при непонимании темы».

**Запуск и работа** — если не понимать цепочку запуска (Finder / Loader / Manager / Router), то при сбое загрузки модуля останется лишь бессильно смотреть в логи

- [Процесс запуска и ручное управление](startup.md) — Разбор цепочки запуска (Finder/Loader/Manager/Router) и полный ручной запуск
- [Система ленивой загрузки](lazy-loading.md) — Принципы работы системы ленивой загрузки модулей, конфигурация и событийно-управляемая ленивая активация (activate_on)

**Коммуникация и соединения** — если не понимать белый список сервисных контрактов (`meta.services`), межмодульный вызов `module.call` будет отклонён с `ServiceNotProvidedError` без понятной причины

- [Межмодульная коммуникация](module-communication.md) — Протоколирование RPC (module.call), сервисные контракты и их реестр, адресные события, воспроизведение при холодном старте, идемпотентная дедупликация событий
- [Пул соединений и рассылка](connections.md) — Реестр соединений: широковещательная рассылка, групповые подписки, межмодульная передача и повторное использование, просмотр пула соединений
- [Менеджер маршрутов](router.md) — Управление маршрутами HTTP и WebSocket (включая регистрацию с одним параметром и соглашение о кортежных ответах)

**Хранение данных** — если не понимать семантику периода охлаждения после неудачного подключения, при нестабильности базы данных можно ошибочно решить, что «фреймворк упал» (на самом деле это быстрый отказ с автоматическим переподключением после охлаждения)

- [Бэкенды хранения](storage-backends.md) — Выбор, настройка и переключение асинхронных нативных бэкендов хранения sqlite / mysql / postgres
- [Конструктор SQL-запросов](sql-builder.md) — Универсальный цепочный конструктор SQL-запросов и абстракция бэкендов хранения
- [HTTP-клиент](http-client.md) — Унифицированный клиент HTTP-запросов

**Сообщения и диалоги** — если не понимать механизм взаимоисключающей аренды сеансов, два модуля, ожидающие ответа одного и того же пользователя, будут «выбивать» друг друга

- [Многораундовый диалог Conversation](conversation.md) — Методы взаимодействия с контекстом многораундового диалога
- [Транскрипт сеанса](transcript.md) — Автоматическая запись сообщений: регуляторы политики хранения, API переопределения во время выполнения и риски/аудит
- [Подробно о MessageBuilder](message-builder.md) — Двухрежимное использование конструктора сегментов сообщений OneBot12
- [Интернационализация (i18n)](i18n.md) — Многоязычная поддержка, регистрация переводов и определение языка

**Канареечный релиз и «теневые» модули** — если не понять пять барьеров изоляции и преждевременно перевести модуль в основной режим, исходящие сообщения теневой версии попадут к реальным пользователям

- [Теневые модули и перевод в основной режим](shadow.md) — Параллельный тестовый запуск новой версии модуля с независимым owner: перехват и учёт исходящих сообщений, diff-сравнение поведения, promote для перевода в основной режим и откат при сбое

**Исключения и справочник стандартов**

- [Система исключений и руководство по перехвату](errors.md) — Все типы исключений фреймворка, места их возникновения и рекомендации по перехвату
- [Система типов сеансов](../standards/session-types.md) — Определения типов сеансов, сопоставления и регистрация пользовательских типов

> [!NOTE]
> Документация **сторонних экосистемных модулей**, таких как регистрация окон Dashboard и рендеринг изображений Takumi, перенесена в каталог [Экосистемные модули](../ecosystem/README.md).
