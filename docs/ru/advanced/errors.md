# Система исключений и руководство по обработке

> [!NOTE]
> **Обязательное к прочтению на уровне L1** — одна из пяти ключевых статей в "Пути чтения" на главной странице, необходима для разработки модулей.

Все пользовательские исключения ErisPulse наследуются от `ErisPulseError`, исключения底层-библиотек (aiohttp, aiomysql и др.) будут перехвачены и преобразованы во внутренние исключения ErisPulse — бизнес-код **не должен зависеть от типов исключений底层-библиотек**.

{!--< tips >!--}
1. Для широкого перехвата: перехватите `ErisPulseError` (базовый класс всех исключений фреймворка)
2. Для точной обработки: перехватите по модулям (например, `ModuleCallTimeoutError`, `StorageUnreachableError`)
3. Операции с хранилищем по умолчанию не выбрасывают исключения: при сбое логируйте и возвращайте `False / None / default`; изменения состояния подключения подписывайтесь на события `storage.unreachable` / `storage.recovered`
{!--< /tips >!--}

## Обзор исключений

```text
ErisPulseError                      # Базовый класс всех исключений фреймворка
├── ClientError                     # Базовый класс исключений HTTP/WS-клиента (Core/client)
│   ├── ClientConnectionError       # Ошибка на уровне соединения: неудача DNS-разрешения, отказ в соединении, недоступность сети
│   ├── ClientTimeoutError          # Превышение времени ожидания запроса
│   └── HTTPStatusError             # Ошибка HTTP-статус-кода (например, 4xx/5xx и raise_for_status)
├── WebSocketError                  # Базовый класс исключений WebSocket (WS-соединение в Core/client)
│   └── WebSocketDisconnect         # Отключение WebSocket (общее для сервера и клиента)
├── ConnectionRegistryError         # Базовый класс исключений реестра подключений (Core/connections, 2.10+)
│   ├── ConnectionNotFoundError     # Подключение не существует/уже отключено и отменено (connections.get/close)
│   └── ConnectionPermissionError   # Закрытие чужого подключения не владельцем (закрытие доступно только создателю)
├── StorageError                    # Базовый класс исключений хранилища (Core/storage)
│   └── StorageUnreachableError     # Недоступен бэкенд хранилища (исчерпаны попытки повторного подключения: недоступна база данных/ошибка учетных данных)
├── InteractionError                # Базовый класс исключений взаимодействия (Core/Event/interaction)
│   ├── InteractionCancelled        # Отменено ожидание/аренда (wait_reply возвращает None)
│   └── SessionOccupiedError        # Сеанс занят (hold() не удалось получить аренду)
├── ModuleError                     # Базовый класс исключений модульной системы (Core/module)
│   └── ModuleCallError             # Базовый класс исключений вызова модуля
│       ├── ModuleNotAvailableError # Целевой модуль не зарегистрирован/не активен/не удалось инициализировать (включая ленивую загрузку)
│       ├── ServiceNotProvidedError # Целевой модуль не объявил этот сервис (вне белого списка meta.services)
│       └── ModuleCallTimeoutError  # Выполнение вызываемого метода превысило лимит времени (по умолчанию 30s)
├── ShadowError                     # Базовый класс исключений теневых модулей (Core/shadow)
│   ├── ShadowStateError            # Недопустимое состояние: целевой модуль не загружен/уже есть активный теневой модуль/не привязан теневой модуль (start/dismiss)
│   ├── ShadowSourceError           # Недоступен источник теневого модуля: путь не существует/отсутствует загрузчик/не удалось загрузить (start)
│   └── ShadowPromoteError          # Не удалось превратить в основной: теневой модуль не зарегистрирован/не загружен/загрузчик не поддерживает снапшот/не удалось перезагрузить (promote)
└── StrictModeError                 # Критическое нарушение строгого режима (прерывает процесс запуска, loaders/strict)
```

## Структурированные свойства

После перехвата исключения можно прочитать структурированные свойства (без необходимости разбора текстового сообщения):

| Исключение | Свойства |
|-----------|----------|
| `ClientError` (включая подклассы) | `.url` URL запроса, `.method` метод запроса, `.attempts` количество попыток (исчерпаны попытки повтора) |
| `HTTPStatusError` | `.status` код статуса, `.message` сообщение ответа |
| `WebSocketDisconnect` | `.code` код закрытия, `.reason` причина закрытия |
| `ConnectionNotFoundError` | `.connection_id` идентификатор подключения |
| `ConnectionPermissionError` | `.connection_id` идентификатор подключения, `.owner` владелец подключения |
| `StorageUnreachableError` | `.backend` имя бэкенда (sqlite/mysql/postgres), `.cooldown` время охлаждения в секундах |
| `ModuleCallError` (включая подклассы) | `.module` имя модуля, `.method` имя метода |
| `ModuleCallTimeoutError` | Наследует `.module/.method`, дополнительно `.timeout` лимит времени (сек) |
| `InteractionCancelled` | `.reason` причина отмены, `.wait_key` ключ сеанса |
| `SessionOccupiedError` | `.wait_key` ключ сеанса, `.owner` владелец |
| `StrictModeError` | `.violations` список нарушений |

```python
from ErisPulse.Core.Bases.errors import ClientError

try:
    resp = await sdk.client.post(url, json=payload)
except ClientError as e:
    print(f"Запрос не удался {e.method} {e.url}, всего попыток {e.attempts}: {e}")
```

## Описание исключений и места их возникновения

### Серия Client — `Core/client.py` / `Core/Bases/client.py`

`sdk.client` / HTTP-клиент и WebSocket-клиент при发起请求时抛出:

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ClientError` | Уровень обертки запросов | Другие ошибки клиента (исключения底层 aiohttp уже преобразованы) |
| `ClientConnectionError` | Этап установки соединения | Целевой сервис недоступен, DNS-ошибка, отказ в соединении |
| `ClientTimeoutError` | Этап выполнения запроса | Превышение времени ожидания запроса |
| `HTTPStatusError` | `raise_for_status()` | Код статуса ответа 4xx/5xx |

```python
from ErisPulse.Core.Bases.errors import ClientTimeoutError

try:
    resp = await sdk.client.get("https://api.example.com", timeout=5)
except ClientTimeoutError:
    ...
```

### Серия WebSocket — `Core/client.py` (методы `send` / `receive`)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `WebSocketError` | Методы WS-приема/отправки | Подключение уже закрыто, получен неожиданный тип сообщения,底层 WS-исключения |
| `WebSocketDisconnect` | Методы WS-приема/отправки | Противоположная сторона нормально закрыла соединение (фреймворк автоматически переподключится) |

### Серия реестра подключений — `Core/connections.py` (начиная с 2.10)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ConnectionNotFoundError` | `connections.get` / `assign` / `dismiss` / `close` | Идентификатор подключения не существует или уже отключен и отменен |
| `ConnectionPermissionError` | Вызов `conn.close()` не владельцем | Переключение модулей при закрытии чужого подключения (отправка и группировка не ограничены) |

### Серия Storage — `Core/storage` / `Core/Bases/sql_base.py`

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `StorageError` | Уровень хранилища | Базовый класс исключений, связанных с хранилищем |
| `StorageUnreachableError` | Этап создания пула | База данных недоступна / ошибка учетных данных / сетевая изоляция, исчерпаны попытки повтора |

> **Семантика неудачных операций с хранилищем**: операции KV и запросов **по умолчанию не выбрасывают исключения** — при сбое записывается ERROR-лог и возвращается `False` / `None` / `default` (чтобы избежать блокировки работы фреймворка из-за проблем с подключением). Таким образом, бизнес-код обычно **не перехватывает** `StorageUnreachableError` (он используется в основном для прямого взаимодействия с底层 хранилищем или пользовательских бэкендов). Для получения информации о состоянии подключения в режиме реального времени подписывайтесь на события жизненного цикла `storage.unreachable` / `storage.recovered` (см. [События жизненного цикла](lifecycle.md#Состояние подключения хранилища)).

Поведение при сбое подключения подробно описано в [Сертификация бэкендов хранилища → Поведение при сбое подключения](storage-backends.md#Поведение при сбое подключения).

### Взаимодействие — `Core/Event/interaction.py`

`wait_reply` / сеанс аренда / напоминания по таймеру:

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `InteractionError` | Уровень взаимодействия | Базовый класс исключений взаимодействия |
| `InteractionCancelled` | При отмене ожидания | Устанавливается на ожидаемый future (ожидающий может перехватить и получить `.reason`) |
| `SessionOccupiedError` | При неудачной аренде `hold()` | Сеанс уже занят другим владельцем (`.owner` показывает владельца) |

При отмене ожидания (выгрузка модуля / закрытие платформы / новое ожидание в том же сеансе заменяет старое), `wait_reply` **возвращает `None`**, а не выбрасывает исключение (внутри `InteractionCancelled` преобразуется); если нужно различить причины отмены, перехватывайте это исключение напрямую.

### Серия Module — `Core/module.py` (`sdk.module.call`)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ModuleError` | Модульная система | Базовый класс исключений модульной системы |
| `ModuleCallError` | `module.call()` | Базовый класс исключений вызова модуля |
| `ModuleNotAvailableError` | `module.call()` / ленивое получение атрибута | Целевой модуль не зарегистрирован / не активен / не удалось инициализировать |
| `ServiceNotProvidedError` | `module.call()` | Целевой `meta.services` не объявил этот метод (вне белого списка) |
| `ModuleCallTimeoutError` | `module.call()` | Вызываемая корутина превысила лимит времени (по умолчанию 30с) |

"Целевой модуль недоступен" в разных путях доступа:

| Путь доступа | Исключение |
|--------------|------------|
| `await sdk.module.call("X", "method")` | `ModuleNotAvailableError` (типизированный) |
| `sdk.module.X.attr` (получение атрибута при ленивой загрузке, после неудачной инициализации) | `ModuleNotAvailableError` |
| `sdk.module.X` (получение атрибута при неактивном модуле) | `AttributeError` (стандартная семантика Python, `hasattr` зависит от этой семантики) |

```python
from ErisPulse.Core.Bases.errors import ModuleNotAvailableError, ServiceNotProvidedError

try:
    history = await sdk.module.call("Chat", "get_history", session_id, n=20)
except ModuleNotAvailableError:
    ...  # Целевой модуль не существует / не активен
except ServiceNotProvidedError:
    ...  # Целевой модуль не предоставляет этот сервис
```

### Серия Shadow — `Core/shadow.py` (теневые модули)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ShadowError` | Механизм теневых модулей | Базовый класс исключений теневых модулей (объединяет все ошибки теневых модулей) |
| `ShadowStateError` | `shadow_start()` / `dismiss_shadow()` | Целевой модуль не загружен / уже есть активный теневой модуль / не привязан теневой модуль |
| `ShadowSourceError` | `shadow_start()` | Путь источника не существует / отсутствует загрузчик / класс не может быть загружен / неудачная загрузка |
| `ShadowPromoteError` | `promote_shadow()` | Теневой модуль не зарегистрирован / не загружен / загрузчик не поддерживает снапшот / не удалось перезагрузить |

### Проверка параметров внутри фреймворка (ValueError)

Параметры конструктора хранилища (пустые типы столбцов, `Insert` не dict, небезопасные типы столбцов и т.д.) выбрасывают стандартный `ValueError` — это **ошибки кодирования на этапе разработки**, нормальный бизнес-код не должен перехватывать, а должен исправить вызов.

Неудача стандартных действий адаптера **не выбрасывает исключения** — возвращается словарь с кодом результата (протокольная семантика, например, `retcode=10002` означает, что действие не реализовано) — это параллельный канал ошибок по сравнению с "выбрасыванием `ClientError`" в клиентском слое; при разработке адаптера необходимо обрабатывать оба канала.

## Рекомендации по перехвату

```python
from ErisPulse.Core import ErisPulseError  # Базовый класс уже экспортирован из Core

try:
    ...
except ErisPulseError as e:
    ...  # Общий перехват: все пользовательские исключения фреймворка
```

- При разработке модулей: перехватывайте по необходимости (см. таблицу выше), в самом внешнем блоке можно использовать `ErisPulseError` для общей защиты
- Все исключения уже экспортированы из `ErisPulse.Core` (включая `SessionOccupiedError` / `InteractionCancelled` / `StrictModeError`), также можно импортировать из `ErisPulse.Core.Bases.errors`
- Полное определение см. в `src/ErisPulse/Core/Bases/errors.py`

## Сворачивание шума при остановке

Долгоживущие процессы при остановке (или отмене фонового цикла) часто выводят в цикл событий множество бесполезных сообщений типа `Task was destroyed but it is pending!`, которые являются шумом от интерпретатора. Фреймворк встроен в **сворачивание подобного шума**: за 2 секунды подобные сообщения понижаются до TRACE и объединяются с подсчетом, выводится только один раз, в конце добавляется суффикс «(еще N подобных сообщений свернуто)». Это сознательное снижение шума — наличие суффикса сворачивания не означает, что фреймворк поглотил реальные исключения, бизнес-исключения (см. таблицу выше) выводятся полностью. Сворачивание применяется только к шуму при выходе интерпретатора, бизнес-исключения не затрагиваются. Какие уровни исключений заслуживают сохранения, а какие можно понизить/свернуть, следует руководствоваться [Правилом оставления следов исключений в инженерной надежности](../styleguide/engineering.md#1-Оставление следов исключений).

## Связанные документы

Выберите в зависимости от цели диагностики:

- **Хранилищевые операции возвращают `False` / `None`, хотите понять состояние подключения** → [Сертификация бэкендов хранилища → Поведение при сбое подключения](storage-backends.md#Поведение при сбое подключения), или подписывайтесь на события [storage.unreachable / storage.recovered](lifecycle.md#Состояние подключения хранилища)
- **`wait_reply` возвращает `None`, хотите узнать, чем был отменен** → [Система взаимодействия](interaction.md) (таблица причин отмены)
- **`module.call` выбрасывает исключение вызова модуля** → [Взаимодействие между модулями](module-communication.md)
- **Ошибки подключения / WebSocket** → [Сетевой клиент](client.md) (система ClientError) и [пул подключений и бродкаст](connections.md) (исключения реестра подключений)
