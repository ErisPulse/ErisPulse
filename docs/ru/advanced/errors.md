# Система исключений и руководство по обработке

Все пользовательские исключения ErisPulse наследуются от `ErisPulseError`, а исключения底层-библиотек (aiohttp, aiomysql и т.д.) будут перехвачены внутри фреймворка и преобразованы в соответствующие исключения ErisPulse — код бизнес-логики **не должен зависеть от типов исключений底层-библиотек**.

{!--< tips >!--}
1. Для широкого перехвата: перехватите `ErisPulseError` (базовый класс всех исключений фреймворка)
2. Для точной обработки: перехватите по модулям (например, `ModuleCallTimeoutError`, `StorageUnreachableError`)
3. Операции хранения по умолчанию не выбрасывают исключения: при сбое записывается в лог и возвращается `False / None / default`; подписывайтесь на события `storage.unreachable` / `storage.recovered` для отслеживания изменения состояния подключения
{!--< /tips >!--}

## Обзор исключений

```text
ErisPulseError                      # Базовый класс всех исключений фреймворка
├── ClientError                     # Базовый класс исключений HTTP/WS-клиента (Core/client)
│   ├── ClientConnectionError       # Ошибка на уровне соединения: сбой DNS, отклонённое соединение, недоступность сети
│   ├── ClientTimeoutError          # Ошибка таймаута запроса
│   └── HTTPStatusError             # Ошибка HTTP-статус-кода (например, 4xx/5xx и raise_for_status)
├── WebSocketError                  # Базовый класс исключений WebSocket (WS-соединение в Core/client)
│   └── WebSocketDisconnect         # Отключение WebSocket (общее для сервера/клиента)
├── StorageError                    # Базовый класс исключений хранения (Core/storage)
│   └── StorageUnreachableError     # Недоступность хранилища (исчерпаны попытки подключения: недоступна база данных/ошибка учётных данных)
├── InteractionError                # Базовый класс исключений взаимодействия (Core/Event/interaction)
│   ├── InteractionCancelled        # Отменённое ожидание/аренда (wait_reply возвращается None)
│   └── SessionOccupiedError        # Исключительная аренда сессии занята (hold() не удалось получить)
├── ModuleError                     # Базовый класс исключений модуля (Core/module)
│   └── ModuleCallError             # Базовый класс исключений вызова модуля
│       ├── ModuleNotAvailableError # Целевой модуль не зарегистрирован/не включён/не инициализирован (включая ленивую загрузку)
│       ├── ServiceNotProvidedError # Целевой модуль не объявил эту службу (вне белого списка meta.services)
│       └── ModuleCallTimeoutError  # Выполнение вызываемого метода превысило таймаут (по умолчанию 30с)
├── ShadowError                     # Базовый класс исключений теневых модулей (Core/shadow)
│   ├── ShadowStateError            # Несоответствие состояния: целевой модуль не загружен/уже активен/не привязан (start/dismiss)
│   ├── ShadowSourceError           # Недоступный источник теневого модуля: путь не существует/отсутствует загрузчик/ошибка загрузки (start)
│   └── ShadowPromoteError          # Ошибка повышения: теневой модуль не зарегистрирован/не загружен/загрузчик не поддерживает снапшоты/ошибка перезагрузки (promote)
└── StrictModeError                 # Критическое нарушение строгого режима (прерывает процесс загрузки, loaders/strict)
```

## Структурированные свойства

После перехвата исключения можно читать структурированные свойства (без необходимости парсинга текстового сообщения):

| Исключение | Свойства |
|-----------|----------|
| `ClientError` (включая подклассы) | `.url` URL-адрес запроса, `.method` метод запроса, `.attempts` количество попыток (когда исчерпаны повторы) |
| `HTTPStatusError` | `.status` код статуса, `.message` сообщение ответа |
| `WebSocketDisconnect` | `.code` код закрытия, `.reason` причина закрытия |
| `StorageUnreachableError` | `.backend` имя хранилища (sqlite/mysql/postgres), `.cooldown` время охлаждения в секундах |
| `ModuleCallError` (включая подклассы) | `.module` имя целевого модуля, `.method` имя целевого метода |
| `ModuleCallTimeoutError` | Наследует `.module/.method`, дополнительно `.timeout` лимит времени (секунды) |
| `InteractionCancelled` | `.reason` причина отмены, `.wait_key` ключ сессии |
| `SessionOccupiedError` | `.wait_key` ключ сессии, `.owner` владелец |
| `StrictModeError` | `.violations` список нарушений |

```python
from ErisPulse.Core.Bases.errors import ClientError

try:
    resp = await sdk.client.post(url, json=payload)
except ClientError as e:
    print(f"Запрос не удался {e.method} {e.url}, всего попыток {e.attempts}: {e}")
```

## Описание исключений и места возникновения

### Серия Client — `Core/client.py` / `Core/Bases/client.py`

Исключения возникают при отправке запросов через `sdk.client` / HTTP-клиент и WebSocket-клиент:

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ClientError` | Уровень обёртки запроса | Другие ошибки клиента (исключения底层 aiohttp уже преобразованы) |
| `ClientConnectionError` | Этап установки соединения | Целевой сервис недоступен, DNS-ошибка, отклонённое соединение |
| `ClientTimeoutError` | Этап выполнения запроса | Превышен лимит времени запроса |
| `HTTPStatusError` | `raise_for_status()` | Код статуса ответа 4xx/5xx |

```python
from ErisPulse.Core.Bases.errors import ClientTimeoutError

try:
    resp = await sdk.client.get("https://api.example.com", timeout=5)
except ClientTimeoutError:
    ...
```

### Серия WebSocket — `Core/client.py` (методы `send` / `receive`)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `WebSocketError` | Методы отправки/приёма WebSocket | Соединение закрыто, получен неожиданный тип сообщения,底层 WebSocket-ошибка |
| `WebSocketDisconnect` | Методы отправки/приёма WebSocket | Противоположная сторона нормально разорвала соединение (фреймворк автоматически переподключится) |

### Серия Storage — `Core/storage` / `Core/Bases/sql_base.py`

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `StorageError` | Уровень хранения | Базовый класс исключений хранения |
| `StorageUnreachableError` | Этап создания пула соединений | База данных недоступна / ошибка учётных данных / сетевая изоляция, исчерпаны попытки |

> **Семантика неудачи операций хранения**: операции KV и запросов **по умолчанию не выбрасывают** исключения — при сбое записывается в лог уровня ERROR и возвращается `False` / `None` / `default` (чтобы избежать блокировки работы фреймворка из-за проблем с подключением). Поэтому в коде бизнес-логики **обычно не перехватывается** `StorageUnreachableError` (он используется в основном при прямом взаимодействии с底层 хранилищем или при использовании пользовательских backends). Для отслеживания состояния подключения во время выполнения подписывайтесь на жизненный цикл событий `storage.unreachable` / `storage.recovered` (см. [События жизненного цикла](lifecycle.md#Состояние подключения хранилища)).

Поведение при сбое подключения см. [Backend хранилища → Поведение при сбое подключения](storage-backends.md#Поведение при сбое подключения).

### Взаимодействие — `Core/Event/interaction.py`

`wait_reply` / сеанс аренды / таймер напоминания:

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `InteractionError` | Уровень взаимодействия | Базовый класс исключений взаимодействия |
| `InteractionCancelled` | При отмене ожидания | Устанавливается на ожидаемый future (ожидание может перехватить и получить `.reason`) |
| `SessionOccupiedError` | При неудачной аренде `hold()` | Сеанс уже занят другим `owner` (`.owner` может указывать владельца) |

При отмене ожидания (деактивация модуля / закрытие платформы / новое ожидание в том же сеансе) `wait_reply` **возвращает `None`**, а не выбрасывает исключение (внутри `InteractionCancelled` преобразуется); если нужно различить причину отмены, перехватывайте его напрямую.

### Серия Module — `Core/module.py` (`sdk.module.call`)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ModuleError` | Система модулей | Базовый класс исключений модулей |
| `ModuleCallError` | `module.call()` | Базовый класс исключений вызова модуля |
| `ModuleNotAvailableError` | `module.call()` / ленивое доступ к атрибуту | Целевой модуль не зарегистрирован / не включён / инициализация не удалась |
| `ServiceNotProvidedError` | `module.call()` | Целевой `meta.services` белый список не объявил этот метод |
| `ModuleCallTimeoutError` | `module.call()` | Вызываемая корутина превысила лимит времени (по умолчанию 30с) |

"Целевой модуль недоступен" в зависимости от пути доступа:

| Путь доступа | Исключение |
|--------------|------------|
| `await sdk.module.call("X", "method")` | `ModuleNotAvailableError` (типизированное) |
| `sdk.module.X.attr` (ленивый доступ к атрибуту, после сбоя инициализации) | `ModuleNotAvailableError` |
| `sdk.module.X` (при попытке доступа к неактивированному модулю) | `AttributeError` (Python-поведение атрибутов, `hasattr` зависит от этой семантики) |

```python
from ErisPulse.Core.Bases.errors import ModuleNotAvailableError, ServiceNotProvidedError

try:
    history = await sdk.module.call("Chat", "get_history", session_id, n=20)
except ModuleNotAvailableError:
    ...  # Целевой модуль не существует / не включён
except ServiceNotProvidedError:
    ...  # Целевой модуль не предоставляет эту службу
```

### Серия Shadow — `Core/shadow.py` (теневые модули)

| Исключение | Место возникновения | Типичные сценарии |
|-----------|---------------------|------------------|
| `ShadowError` | Механизм теневых модулей | Базовый класс исключений теневых модулей (унифицированный перехват всех ошибок теневых модулей) |
| `ShadowStateError` | `shadow_start()` / `dismiss_shadow()` | Целевой модуль не загружен / уже активен / не привязан |
| `ShadowSourceError` | `shadow_start()` | Путь источника не существует / отсутствует загрузчик / класс не может быть загружен / ошибка загрузки |
| `ShadowPromoteError` | `promote_shadow()` | Теневой модуль не зарегистрирован / не загружен / загрузчик не поддерживает снапшоты / ошибка перезагрузки |

### Внутренняя проверка параметров фреймворка (ValueError)

Проверка параметров в построителе запросов хранилища (пустой тип столбца, `Insert` не dict, небезопасный тип столбца и т.д.) выбрасывает стандартный `ValueError` — это относится к **ошибкам кодирования на этапе разработки**, нормальный код бизнес-логики не должен перехватывать такие исключения, а должен исправлять вызов.

Неудача стандартных действий адаптера **не выбрасывает исключение**: возвращается словарь с `retcode` (протокольная семантика, например, `retcode=10002` означает, что действие не реализовано) — это параллельный канал ошибок по сравнению с клиентским "неудача выбрасывает `ClientError`", разработчикам адаптеров нужно обрабатывать оба канала.

## Рекомендации по перехвату

```python
from ErisPulse.Core import ErisPulseError  # Базовый класс экспортируется через Core

try:
    ...
except ErisPulseError as e:
    ...  # Общий перехват: все пользовательские исключения фреймворка
```

- При разработке модулей: перехватывайте по необходимости (см. таблицу выше), в самом внешнем уровне можно использовать `ErisPulseError` для общего перехвата
- Все исключения экспортируются через `ErisPulse.Core` (включая `SessionOccupiedError` / `InteractionCancelled` / `StrictModeError`), также можно импортировать из `ErisPulse.Core.Bases.errors`
- Полное определение см. в `src/ErisPulse/Core/Bases/errors.py`

## Скрытие шума при завершении

В процессах, работающих долго, при завершении (или отмене фонового цикла) цикл событий часто выводит множество бесполезных сообщений вроде `Task was destroyed but it is pending!`, что вызывает шум. Фреймворк встроен с **подавлением подобного шума**: сообщения одного типа в 2-секундном окне понижаются до уровня TRACE и объединяются с подсчётом, выводится только один раз, в конце добавляется суффикс «(ещё N подобных сообщений было скрыто)». Это сознательное снижение шума — появление суффикса означает, что фреймворк не скрыл настоящих исключений, все бизнес-исключения (указанные в таблице выше) выводятся полностью и без скрытия.
