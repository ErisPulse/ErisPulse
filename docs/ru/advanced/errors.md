# Система исключений и руководство по обработке

Все пользовательские исключения ErisPulse наследуются от класса `ErisPulseError`, а исключения底层 библиотек (например, aiohttp, aiomysql и т.д.) внутри фреймворка перехватываются и преобразуются в соответствующие исключения ErisPulse. В коде бизнес-логики **не требуется использовать исключения底层 библиотек**.

{!--< tips >!--}
1. Для широкого перехвата: перехватите `ErisPulseError` (базовый класс всех исключений фреймворка)
2. Для точной обработки: перехватывайте по модулям (например, `ModuleCallTimeoutError`, `StorageUnreachableError`)
3. Операции с хранилищем по умолчанию не выбрасывают исключения: при сбое запись в лог и возврат `False / None / default`
{!--< /tips >!--}

## Обзор исключений

```text
ErisPulseError                      # Базовый класс всех исключений фреймворка
├── ClientError                     # Базовый класс исключений HTTP/WS-клиента (Core/client)
│   ├── ClientConnectionError       # Ошибки на уровне соединения: неудачное разрешение DNS, отказ в подключении, недоступность сети
│   ├── ClientTimeoutError          # Тайм-аут запроса
│   └── HTTPStatusError             # Ошибки HTTP-статуса (например, 4xx/5xx и raise_for_status)
├── WebSocketError                  # Базовый класс исключений WebSocket (WS-соединение в Core/client)
│   └── WebSocketDisconnect         # Отключение WebSocket (общее для сервера/клиента)
├── StorageError                    # Базовый класс исключений хранилища (Core/storage)
│   └── StorageUnreachableError     # Недоступность хранилища (исчерпаны попытки повторного подключения: база данных недоступна/ошибка учетных данных)
├── InteractionError                # Базовый класс исключений взаимодействия (Core/Event/interaction)
├── ModuleError                     # Базовый класс исключений модульной системы (Core/module)
│   └── ModuleCallError             # Базовый класс исключений вызова модуля
│       ├── ModuleNotAvailableError # Целевой модуль не зарегистрирован/не включен/не загружен
│       ├── ServiceNotProvidedError # Целевой модуль не объявил этот сервис (вне белого списка meta.services)
│       └── ModuleCallTimeoutError  # Выполнение вызываемого метода превысило тайм-аут (по умолчанию 30s)
└── (Внутренние ошибки фреймворка)   # ValueError и другие для проверки параметров, см. ниже
```

## Описание исключений и места их возникновения

### Серия Client — `Core/client.py` / `Core/Bases/client.py`

Исключения выбрасываются при отправке запросов через `sdk.client` / HTTP-клиент и WebSocket-клиент:

| Исключение | Место возникновения | Типичные сценарии |
|------|----------|----------|
| `ClientError` | Уровень обёртки запроса | Другие клиентские ошибки (исключения底层 aiohttp уже преобразованы) |
| `ClientConnectionError` | Этап установки соединения | Недоступность целевого сервиса, ошибка DNS, отказ в подключении |
| `ClientTimeoutError` | Этап выполнения запроса | Превышение времени ожидания запроса |
| `HTTPStatusError` | `raise_for_status()` | Код ответа HTTP 4xx/5xx |

```python
from ErisPulse.Core.Bases.errors import ClientTimeoutError

try:
    resp = await sdk.client.get("https://api.example.com", timeout=5)
except ClientTimeoutError:
    ...
```

### Серия WebSocket — `Core/client.py` (`send` / `receive`)

| Исключение | Место возникновения | Типичные сценарии |
|------|----------|----------|
| `WebSocketError` | Методы WS-отправки/приёма | Соединение закрыто, получено неожиданное сообщение,底层 WS-ошибки |
| `WebSocketDisconnect` | Методы WS-отправки/приёма | Нормальное отключение от другого конца (фреймворк будет автоматически переподключаться) |

### Серия Storage — `Core/storage` / `Core/Bases/sql_base.py`

| Исключение | Место возникновения | Типичные сценарии |
|------|----------|----------|
| `StorageError` | Уровень хранилища | Базовый класс исключений, связанных с хранилищем |
| `StorageUnreachableError` | Этап создания пула подключений | База данных недоступна / ошибка учетных данных / сетевая изоляция, исчерпаны попытки повторного подключения |

> **Семантика неудачи операций с хранилищем**: операции KV и запросов **по умолчанию не выбрасывают** исключения — при сбое запись в лог и возврат `False` / `None` / `default` (чтобы избежать блокировки работы фреймворка из-за проблем с подключением). `StorageUnreachableError` используется в основном для внутренних решений кэширования и переподключения; если требуется точное определение сбоя, проверяйте возвращаемые значения.

Поведение при сбое подключения см. в разделе [Поведение при сбое подключения хранилища](storage-backends.md#连接失败行为).

### Interaction — `Core/Event/interaction.py`

`wait_reply` / аренда сессии / таймер напоминаний:

| Исключение | Место возникновения | Типичные сценарии |
|------|----------|----------|
| `InteractionError` | Уровень взаимодействия | Базовый класс исключений взаимодействия |

При отмене ожидания (выгрузка модуля / закрытие платформы / новое ожидание в рамках той же сессии) `wait_reply` **возвращает `None`**, не выбрасывая исключение; если сессия уже занята, `hold()` выбрасывает `SessionOccupiedError` (наследуется от `InteractionError`).

### Серия Module — `Core/module.py` (`sdk.module.call`)

| Исключение | Место возникновения | Типичные сценарии |
|------|----------|----------|
| `ModuleError` | Система модулей | Базовый класс исключений модульной системы |
| `ModuleCallError` | `module.call()` | Базовый класс исключений вызова модуля |
| `ModuleNotAvailableError` | `module.call()` | Целевой модуль не зарегистрирован / не включен / не загружен |
| `ServiceNotProvidedError` | `module.call()` | Целевой `meta.services` не объявил этот метод |
| `ModuleCallTimeoutError` | `module.call()` | Вызываемая корутина превысила тайм-аут (по умолчанию 30s) |

```python
from ErisPulse.Core.Bases.errors import ModuleNotAvailableError, ServiceNotProvidedError

try:
    history = await sdk.module.call("Chat", "get_history", session_id, n=20)
except ModuleNotAvailableError:
    ...  # Целевой модуль не существует / не включен
except ServiceNotProvidedError:
    ...  # Целевой модуль не предоставляет этот сервис
```

### Внутренняя проверка параметров фреймворка (ValueError)

Проверка параметров в конструкторе хранилища (пустой тип столбца, `Insert` не dict, небезопасный тип столбца и т.д.) выбрасывает стандартный `ValueError` — это относится к **ошибкам кодирования на этапе разработки**, и обычный код бизнес-логики не должен перехватывать такие исключения, а должен исправлять вызов.

## Рекомендации по перехвату исключений

```python
from ErisPulse.Core import ErisPulseError  # Базовый класс уже экспортирован из Core

try:
    ...
except ErisPulseError as e:
    ...  # Общий перехват: все пользовательские исключения фреймворка
```

- При разработке модулей: перехватывайте по необходимости (см. таблицу выше), в самом верхнем уровне можно использовать `ErisPulseError` для общего перехвата
- Все исключения экспортированы из `ErisPulse.Core`, также можно импортировать из `ErisPulse.Core.Bases.errors`
- Полное определение см. в файле `src/ErisPulse/Core/Bases/errors.py`
