# Система исключений и руководство по обработке

Все пользовательские исключения ErisPulse наследуются от `ErisPulseError`. Исключения нижележащих библиотек (aiohttp, aiomysql и т.д.) перехватываются внутри фреймворка и преобразуются в соответствующие исключения ErisPulse — код бизнес-логики **не должен зависеть от типов исключений нижележащих библиотек**.

{!--< tips >!--}
1. Для широкого обработчика: перехват `ErisPulseError` (базовый класс всех исключений фреймворка)
2. Для точного обработчика: перехват по модулю (например, `ModuleCallTimeoutError`, `StorageUnreachableError`)
3. Операции с хранилищем по умолчанию не выбрасывают исключения: при сбое записывается лог и возвращаются `False / None / default`; для отслеживания изменений состояния подключения подписывайтесь на события `storage.unreachable` / `storage.recovered`
{!--< /tips >!--}

## Обзор исключений

```text
ErisPulseError                      # Базовый класс всех исключений фреймворка
├── ClientError                     # Базовый класс исключений HTTP/WS-клиента (Core/client)
│   ├── ClientConnectionError       # Ошибки на уровне соединения: сбой разрешения DNS, отказ в подключении, недоступность сети
│   ├── ClientTimeoutError          # Ошибка таймаута запроса
│   └── HTTPStatusError             # Ошибки HTTP-статус-кодов (например, 4xx/5xx и raise_for_status)
├── WebSocketError                  # Базовый класс исключений WebSocket (WS-соединение в Core/client)
│   └── WebSocketDisconnect         # Отключение WebSocket (общее для сервера и клиента)
├── StorageError                    # Базовый класс исключений хранилища (Core/storage)
│   └── StorageUnreachableError     # Недоступность хранилища (исчерпаны попытки подключения: недоступна база данных, ошибка учетных данных)
├── InteractionError                # Базовый класс исключений взаимодействия (Core/Event/interaction)
│   ├── InteractionCancelled        # Отмена приостановленного ожидания/аренды (wait_reply возвращает None)
│   └── SessionOccupiedError        # Исключение занятости сессии (hold() не удалось получить аренду)
├── ModuleError                     # Базовый класс исключений модульной системы (Core/module)
│   └── ModuleCallError             # Базовый класс исключений вызова модуля
│       ├── ModuleNotAvailableError # Целевой модуль не зарегистрирован/не включен/не удалось инициализировать (включая ленивый доступ)
│       ├── ServiceNotProvidedError # Целевой модуль не объявил этот сервис (не в белом списке meta.services)
│       └── ModuleCallTimeoutError  # Слишком долгое выполнение вызываемого метода (по умолчанию 30 секунд)
└── StrictModeError                 # Критическое нарушение строгого режима (прерывает процесс запуска, loaders/strict)
```

## Структурированные свойства

После перехвата исключения можно прочитать структурированные свойства (без необходимости разбора текстового сообщения):

| Исключение | Свойства |
|------------|----------|
| `ClientError` (и подклассы) | `.url` URL запроса, `.method` метод запроса, `.attempts` количество попыток (когда исчерпаны попытки повтора) |
| `HTTPStatusError` | `.status` код статуса, `.message` сообщение ответа |
| `WebSocketDisconnect` | `.code` код закрытия, `.reason` причина закрытия |
| `StorageUnreachableError` | `.backend` имя хранилища (sqlite/mysql/postgres), `.cooldown` время охлаждения в секундах |
| `ModuleCallError` (и подклассы) | `.module` имя модуля, `.method` имя метода |
| `ModuleCallTimeoutError` | Наследует `.module/.method`, дополнительно `.timeout` лимит времени (в секундах) |
| `InteractionCancelled` | `.reason` причина отмены, `.wait_key` ключ сессии |
| `SessionOccupiedError` | `.wait_key` ключ сессии, `.owner` владелец |
| `StrictModeError` | `.violations` список нарушений |

```python
from ErisPulse.Core.Bases.errors import ClientError

try:
    resp = await sdk.client.post(url, json=payload)
except ClientError as e:
    print(f"Запрос не удался {e.method} {e.url}, всего попыток {e.attempts}: {e}")
```

## Описание исключений и места их возникновения

### Серия Client — `Core/client.py` / `Core/Bases/client.py`

Исключения возникают при отправке запросов через `sdk.client` / HTTP-клиент и WebSocket-клиент:

| Исключение | Место возникновения | Типичные сценарии |
|------------|---------------------|-------------------|
| `ClientError` | Уровень обертки запроса | Другие ошибки клиента (ошибки aiohttp уже преобразованы) |
| `ClientConnectionError` | Этап установки соединения | Целевой сервис недоступен, сбой DNS, отказ в подключении |
| `ClientTimeoutError` | Этап выполнения запроса | Превышение времени ожидания запроса |
| `HTTPStatusError` | `raise_for_status()` | Код статуса ответа 4xx/5xx |

```python
from ErisPulse.Core.Bases.errors import ClientTimeoutError

try:
    resp = await sdk.client.get("https://api.example.com", timeout=5)
except ClientTimeoutError:
    ...
```

### WebSocket-серия — `Core/client.py` (методы `send` / `receive`)

| Исключение | Место возникновения | Типичные сценарии |
|------------|---------------------|-------------------|
| `WebSocketError` | Методы WS `send` / `receive` | Соединение закрыто, получено неожиданное сообщение, ошибка WebSocket |
| `WebSocketDisconnect` | Методы WS `send` / `receive` | Удалённый узел нормально отключился (фреймворк автоматически переподключится) |

### Storage-серия — `Core/storage` / `Core/Bases/sql_base.py`

| Исключение | Место возникновения | Типичные сценарии |
|------------|---------------------|-------------------|
| `StorageError` | Уровень хранилища | Базовый класс ошибок хранилища |
| `StorageUnreachableError` | Этап создания пула | База данных недоступна / ошибка учетных данных / сетевая изоляция, исчерпаны попытки повтора |

> **Поведение при сбое операций с хранилищем**: операции KV и запросов по умолчанию **не выбрасывают** исключения — при сбое записывается лог уровня ERROR и возвращаются `False` / `None` / `default` (чтобы избежать блокировки работы фреймворка). Следовательно, код бизнес-логики обычно **не перехватывает** `StorageUnreachableError` (он используется в основном для прямого взаимодействия с底层存储 или пользовательских backends). Для отслеживания состояния подключения во время выполнения подписывайтесь на жизненный цикл событий `storage.unreachable` / `storage.recovered` (см. [Жизненный цикл событий](lifecycle.md#состояние-подключения-хранилища)).

Поведение при сбое подключения см. в разделе [Поведение при сбое подключения backends](storage-backends.md#поведение-при-сбое-подключения).

### Interaction — `Core/Event/interaction.py`

Связанные с `wait_reply` / аренда сессии / таймер напоминаний:

| Исключение | Место возникновения | Типичные сценарии |
|------------|---------------------|-------------------|
| `InteractionError` | Уровень взаимодействия | Базовый класс исключений взаимодействия |
| `InteractionCancelled` | При отмене приостановленного ожидания | Устанавливается на ожидаемый future (ожидающий может перехватить и получить `.reason`) |
| `SessionOccupiedError` | При неудачной аренде `hold()` | Сессия уже занята другим `owner` (`.owner` показывает владельца) |

При отмене ожидания (разгрузка модуля / закрытие платформы / новое ожидание в той же сессии заменяет старое), `wait_reply` **возвращает `None`**, а не выбрасывает исключение (внутри `InteractionCancelled` преобразуется). Если нужно различать причины отмены, перехватывайте его напрямую.

### Module-серия — `Core/module.py` (`sdk.module.call`)

| Исключение | Место возникновения | Типичные сценарии |
|------------|---------------------|-------------------|
| `ModuleError` | Модульная система | Базовый класс исключений модульной системы |
| `ModuleCallError` | `module.call()` | Базовый класс исключений вызова модуля |
| `ModuleNotAvailableError` | `module.call()` / ленивое обращение к атрибуту | Целевой модуль не зарегистрирован / не включен / инициализация не удалась |
| `ServiceNotProvidedError` | `module.call()` | Целевой модуль не объявил этот метод в белом списке `meta.services` |
| `ModuleCallTimeoutError` | `module.call()` | Вызываемая корутина превысила лимит времени (по умолчанию 30 секунд) |

"Целевой модуль недоступен" в зависимости от пути обращения:

| Путь обращения | Исключение |
|----------------|------------|
| `await sdk.module.call("X", "method")` | `ModuleNotAvailableError` (типизированное) |
| `sdk.module.X.attr` (ленивое обращение к атрибуту, после сбоя инициализации) | `ModuleNotAvailableError` |
| `sdk.module.X` (обращение к неактивному модулю) | `AttributeError` (стандартная семантика Python, `hasattr` зависит от этой семантики) |

```python
from ErisPulse.Core.Bases.errors import ModuleNotAvailableError, ServiceNotProvidedError

try:
    history = await sdk.module.call("Chat", "get_history", session_id, n=20)
except ModuleNotAvailableError:
    ...  # Целевой модуль не существует / не включен
except ServiceNotProvidedError:
    ...  # Целевой модуль не предоставляет этот сервис
```

### Проверка параметров внутри фреймворка (ValueError)

Проверка параметров в построителе запросов хранилища (пустой тип колонки, `Insert` не dict, небезопасный тип колонки и т.д.) выбрасывает стандартный `ValueError` — это относится к **ошибкам кодирования на этапе разработки**, нормальный код бизнес-логики не должен перехватывать, а должен исправлять вызов.

Неудача стандартных действий адаптера **не выбрасывает исключение**: возвращается словарь с кодом `retcode` (протокольная семантика, например, `retcode=10002` означает, что действие не реализовано) — это параллельный канал ошибок с клиентом, где "сбой выбрасывает `ClientError"`. При разработке адаптера необходимо обрабатывать оба канала.

## Рекомендации по перехвату

```python
from ErisPulse.Core import ErisPulseError  # Базовый класс экспортируется из Core

try:
    ...
except ErisPulseError as e:
    ...  # Общий обработчик: все пользовательские исключения фреймворка
```

- При разработке модуля: перехватывайте по мере необходимости (см. таблицу выше), на внешнем уровне можно использовать `ErisPulseError` как общий обработчик
- Все исключения экспортируются из `ErisPulse.Core` (включая `SessionOccupiedError` / `InteractionCancelled` / `StrictModeError`), также можно импортировать из `ErisPulse.Core.Bases.errors`
- Полное определение см. в `src/ErisPulse/Core/Bases/errors.py`
