# Пул соединений и широковещательная рассылка

> [!TIP]
> **Когда стоит читать этот документ**: когда требуется пул соединений WebSocket/SSE, групповая рассылка, межмодульная отправка или просмотр соединений. Если это не нужно — пропустите, на использование других функций это не повлияет.

> **После прочтения вы узнаете**: как три типа соединений автоматически регистрируются в реестре, API подписки на группы и широковещательной рассылки,
> межмодульное повторное использование и принадлежность права закрытия, а также семантику очистки соединений при выгрузке модуля.
>
> **В этом документе не рассматриваются**: регистрация маршрутов WebSocket / SSE и хуки жизненного цикла соединений
> (см. [Менеджер маршрутов](router.md)); клиентские HTTP-запросы (см. [Сетевой клиент](client.md)).


Соединения (серверные WebSocket / SSE / клиентские исходящие WebSocket) в ErisPulse являются **ресурсами первого класса на уровне фреймворка**:
при установке соединения они автоматически регистрируются в едином реестре, поддерживают широковещательную рассылку, подписку на бизнес-группы и межмодульную передачу/повторное использование,
а при выгрузке модуля фреймворк автоматически закрывает и освобождает их — бизнес-код больше не создаёт собственные коллекции `_ws_clients` и не сталкивается с утечками из-за забытой очистки.

> Все примеры в этом документе используют синтаксис **корневого импорта** (рекомендуется с 2.10+):
> `from ErisPulse import connections, router, client, WebSocketConnection`

## Обзор

```python
from ErisPulse import connections, router, WebSocketConnection

# Сервер: соединение регистрируется автоматически, добавление в бизнес-группу внутри handler
@router.ws("MyModule", "/ws")
async def handle(ws: WebSocketConnection):
    ws.join_group("room:1")            # именование групп полностью определяется бизнес-соглашениями
    async for msg in ws.iter_text():
        ...                             # при отключении фреймворк автоматически разрегистрирует и очищает группы

# Из любого места: широковещательная рассылка в группу (возвращает детализацию успехов/неудач)
result = await connections.broadcast({"type": "notify"}, group="room:1")
if not result.ok:
    ...                                 # result.failed: {id соединения: исключение}
```

Три типа соединений попадают в единый реестр:

| kind | Источник | Владелец (owner) | Описание |
|------|------|-----------|------|
| `server` | `@router.ws(...)` / `register_websocket(...)` | Имя модуля, зарегистрировавшего маршрут | Автоматическая разрегистрация при отключении |
| `sse` | `@router.sse(...)` / `register_sse(...)` | Имя модуля, зарегистрировавшего маршрут | Рассылка через `sse.send()` |
| `client` | `await client.ws_connect(url)` | Текущий модуль (или явный `owner=`) | Автоматическая разрегистрация при закрытии/отключении удалённой стороной; при остановке адаптера фреймворк закрывает их все |

Если автоматическая регистрация не нужна: передайте `track=False` в маршруте и `track=False` для исходящих соединений — поведение старого кода останется полностью неизменным.

## Просмотр пула соединений

```python
from ErisPulse import connections

# Просмотр пула соединений модуля ("сколько активных соединений сейчас у модуля")
conns = connections.list(namespace="Dashboard")
for conn in conns:
    print(conn.id, conn.kind, conn.groups, conn.meta)

# Фильтрация по другим измерениям (условия объединяются через AND)
connections.list(owner="MyAdapter", kind="client")
connections.list(group="tenant:acme")

# Глобальная статистика (подсчёт по каждому измерению)
stats = connections.stats()
# {'total': 5, 'by_kind': {...}, 'by_namespace': {...}, 'by_owner': {...}, 'groups': {...}}

# Счётчики аудита принадлежности (также доступно через фасад ownership)
from ErisPulse import ownership
ownership.counts("Dashboard")   # {'connections': 3, ...}
```

Читаемые сведения о каждом соединении: `conn.id` (вида `Dashboard:1a2b3c4d`), `conn.namespace`,
`conn.owner`, `conn.kind`, `conn.groups`, `conn.meta` (произвольный бизнес-словарь).

## Широковещательная рассылка и подписка

### Группы (модель подписки)

Группы — это **плоские строки**, именование полностью определяется бизнес-соглашениями (комнаты / арендаторы / темы...),
вложенные уровни выражаются через соглашения об именовании (например, `tenant:acme/room:1`), фреймворк не ограничивает формат.

Управлять можно с двух сторон:

```python
# Направление первое: соединение само присоединяется/выходит (внутри handler)
@router.ws("Chat", "/ws")
async def handle(ws: WebSocketConnection):
    ws.join_group("room:1")        # эквивалентно connections.assign(ws.id, "room:1")
    ws.leave_group("room:1")

# Направление второе: административное назначение (со стороны маршрута / других модулей)
connections.assign(conn_id, "tenant:acme")
connections.dismiss(conn_id, "tenant:acme")   # без имени группы = выход из всех групп
```

При разрыве соединения оно автоматически выходит из всех групп, бизнес-очистка не требуется.

### Широковещательная рассылка

```python
result = await connections.broadcast(
    data,                       # WS идёт через send_json; SSE через send (автоматическая JSON-сериализация)
    namespace="Dashboard",      # фильтр по пространству имён
    group="room:1",             # фильтр по группе
    kind="sse",                 # фильтр по типу соединения
    owner="MyAdapter",          # фильтр по владельцу
    ids={conn_id, ...},         # явное указание набора кандидатов (условия фильтрации всё равно действуют)
    exclude={conn_id},          # исключить некоторые соединения
    timeout=10.0,               # тайм-аут отправки для одного соединения (не общее время)
    concurrency=64,             # лимит параллельной отправки
    raise_on_error=False,       # при True при наличии неудач выбрасывается первое исключение
)
result.total      # общее число целевых соединений (до исключения)
result.sent       # список id успешно отправленных соединений
result.failed     # {id соединения: объект исключения} (тайм-аут/уже отключено/ошибка отправки)
result.excluded   # id исключённых соединений
result.ok         # доставлено ли всё
```

Между условиями фильтрации действует **AND**; сбой одного соединения не влияет на другие; соединения из `ids`, которые больше не существуют,
учитываются в `failed` (чтобы бизнес видел полную картину).

### События жизненного цикла

Регистрация/разрегистрация соединений и изменения групп порождают стандартные события жизненного цикла; Dashboard и другие компоненты могут подписываться на них для отображения в реальном времени:

```python
from ErisPulse import lifecycle

@lifecycle.on("connection.registered")
async def on_registered(data): ...
@lifecycle.on("connection.unregistered")
async def on_unregistered(data): ...
@lifecycle.on("connection.group.joined")
async def on_joined(data): ...
@lifecycle.on("connection.group.left")
async def on_left(data): ...
```

## Межмодульная передача / повторное использование

Соединения — это ресурсы, зарегистрированные фреймворком; любой модуль может получить соединение по его id и **повторно использовать** его —
не нужно создавать своё собственное и не нужно знать, кто создал соединение:

```python
from ErisPulse import connections

conn = connections.get("Dashboard:1a2b3c4d")   # при отсутствии/отключении выбрасывает ConnectionNotFoundError
await conn.send_json({"ping": 1})              # отправлять может любой модуль
conn.join_group("someone-elses-room")          # также может участвовать в группах
```

**Принадлежность и право закрытия**:

- `owner` соединения (модуль, который его создал) монопольно владеет правом закрытия. Вызов `close()` не владельцем выбрасывает
  `ConnectionPermissionError` (`from ErisPulse import ConnectionPermissionError`);
- отправка и операции с группами открыты для всех модулей, авторизация не требуется;
- при выгрузке модуля-владельца / остановке адаптера фреймворк **закрывает и разрегистрирует все** его соединения
  (серверные + исходящие); попытки отправки по уже полученным ссылкам завершатся неудачей, об этом можно узнать,
  подписавшись на событие `connection.unregistered`;
- внутренние пути освобождения фреймворка используют `close(force=True)` в обход проверки.

> Примечание об атрибуции: проверка права закрытия зависит от контекста owner во время выполнения (автоматически передаётся через
> `owner_scope` / диспетчеризацию событий / `spawn_background` и т.д.). Вызовы, которые невозможно атрибутировать контексту (неатрибутированный старый код), пропускаются,
> что гарантирует нулевые поломки; новый код, вызываемый в контексте owner, защищён.

## Исходящие соединения (сторона Client)

```python
from ErisPulse import client

ws = await client.ws_connect("wss://example.com/ws")
ws.id          # уже зарегистрировано, доступно для запросов/рассылки через connections
ws.owner       # текущий модуль (рекомендуется передавать явно, если контекст owner недоступен)

# Когда контекст owner недоступен (например, колбэки в потоках утилит), указывайте явно — только тогда выгрузка сможет автоматически освободить соединение:
ws = await client.ws_connect("wss://example.com/ws", owner="MyAdapter")
```

Как активное отключение удалённой стороной, так и локальный `close()` автоматически разрегистрируют соединение; при выгрузке модуля фреймворк закрывает
все его исходящие соединения. Дни, когда старый код создавал соединения напрямую, управлял ими по отдельности и допускал утечки из-за забытой очистки, закончились.

## Межпоточная доставка

При обращении к соединениям из дочерних потоков (рассылка / отправка / закрытие) используйте стандартные инструменты фреймворка для доставки в главный цикл,
**не пишите `run_coroutine_threadsafe` вручную**:

```python
from ErisPulse import run_main_loop, spawn_later, spawn_thread

# Блокирующее получение результата из дочернего потока:
run_main_loop(connections.broadcast({"tick": 1}, group="room:1"), timeout=5)

# Фоновый поток + отложенная задача (принадлежность owner, автоматически отменяется при выгрузке):
def push_tick():
    return connections.broadcast({"tick": 1}, group="room:1")
spawn_later(30, push_tick, owner="MyModule")
```

## Семантика выгрузки и очистки

Цепочка освобождения принадлежности при выгрузке модуля / остановке адаптера выполняет по порядку: отмену принадлежащих фоновых задач и таймеров →
**закрытие и разрегистрацию принадлежащих соединений** → вызов хуков on_cleanup → разрегистрацию маршрутов/обработчиков и других регистрационных ресурсов.
Подробнее см. [Система принадлежности (owner)](ownership.md).

> [!WARNING]
> Начиная с 2.10, выгрузка модуля закрывает зарегистрированные за ним WS/SSE/исходящие соединения. Об этом должны знать
> нижестоящие компоненты, полагающиеся на то, что "после выгрузки соединения остаются живыми"
> (например, push в старых версиях Dashboard) — это ожидаемое поведение, призванное искоренить утечки соединений.

## Обзор API

| API | Описание |
|-----|------|
| `connections.get(id)` | Получить соединение (точка входа для межмодульного доступа), при отсутствии выбрасывает `ConnectionNotFoundError` |
| `connections.list(namespace=, owner=, group=, kind=)` | Отфильтрованный запрос списка соединений |
| `connections.stats(namespace=, owner=)` | Подсчёт статистики по каждому измерению |
| `connections.assign(id, *groups)` / `dismiss(id, *groups)` | Административное добавление/удаление из групп |
| `await connections.broadcast(data, ...)` | Рассылка, возвращает `BroadcastResult` |
| `await connections.close(id, force=False)` | Закрыть и разрегистрировать (проверка прав) |
| `await connections.close_owner(owner)` | Закрыть и разрегистрировать все соединения указанного owner (вызывается в цепочке выгрузки фреймворка) |
| `conn.join_group(*groups)` / `conn.leave_group(*groups)` | Группы со стороны соединения |
| `conn.send_json / send_text / iter_text / ...` | Приём/отправка (единый интерфейс для сервера/клиента) |
| `conn.meta` | Словарь бизнес-метаданных |
| `conn.close(force=False)` | Закрыть (не владелец получает `ConnectionPermissionError`) |
