# Справочник команд CLI

Инструмент командной строки ErisPulse (`epsdk`) предоставляет функции управления проектами и пакетами.

> **Примечание:** Все команды можно подробно ознакомиться с помощью `epsdk <команда> --help`. Главная помощь `epsdk` (без команды) сгруппирована по категориям: **Проект** (init / create / run), **Управление компонентами** (install / uninstall / upgrade / list / list-remote / types), **Конфигурация и диагностика** (config / doctor / i18n), **Прочее** (self-update / version).

### install

Установка пакета модуля или адаптера ErisPulse. Если имя пакета не указано, запускается интерактивный режим установки.

**Алиас:** `i`, `add`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[package]...` | | Имя пакета для установки, можно указать несколько |
| `--upgrade` | `-U` | Обновление до последней версии при установке |
| `--pre` | | Разрешить установку предварительных версий |
| `--editable` | `-e` | Установка в режиме редактирования (требуется указать путь) |
| `--user` | | Установка в каталог site-packages пользователя |
| `--no-deps` | | Не устанавливать зависимости |
| `--target` | `-t` | Установка в указанную директорию |
| `--index-url` | | Указание URL зеркала PyPI |
| `--extra-index-url` | | Дополнительный URL зеркала PyPI (можно указывать несколько раз) |
| `--no-cache-dir` | | Отключение кэша |
| `--requirement` | `-r` | Установка из файла requirements |
| `--constraint` | `-c` | Установка из файла ограничений |
| `--force-reinstall` | | Принудительная переустановка |
| `--ignore-installed` | | Игнорировать уже установленные пакеты |
| `--compile` | | Компиляция .pyc файлов после установки |
| `--no-compile` | | Не компилировать .pyc файлы после установки |
| `--prefix` | | Установка в указанную префиксную директорию |
| `--src` | | Используемая исходная директория при установке в режиме редактирования |
| `--config-settings` | | Передача настроек сборочному бэкенду (можно указывать несколько раз) |
| `--no-binary` | | Ограничение использования бинарных пакетов (формат: `:all:`) |
| `--only-binary` | | Ограничение использования только бинарных пакетов (формат: `:all:`) |
| `--prefer-binary` | | Предпочтение бинарных пакетов |
| `--build-isolation` | | Включение изоляции сборки |
| `--no-build-isolation` | | Отключение изоляции сборки |
| `--upgrade-strategy` | | Стратегия обновления: `eager`, `only-if-needed`, `to-satisfy-only` |
| `--break-system-packages` | | Разрешить изменение пакетов Python, управляемых системным менеджером |
| `--no-uv` | | Использование pip вместо uv |

**Примеры:**

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Установка из зеркала и обновление
epsdk install Weather -U --index-url https://pypi.tuna.tsinghua.edu.cn/simple

# Установка в режиме редактирования (режим разработки)
epsdk install -e ./my-adapter
```

### uninstall

Удаление установленного модуля или адаптера ErisPulse. Если имя пакета не указано, запускается интерактивный режим удаления.

**Алиас:** `rm`, `remove`

**Параметры:**

| Параметр | Описание |
|------|------|
| `<package>...` | Имя пакета для удаления, можно указать несколько |
| `--no-uv` | Использование pip вместо uv |

**Примеры:**

```bash
# Удаление одного модуля
epsdk uninstall Weather

# Удаление нескольких модулей

```

### upgrade

Обновление установленных компонентов ErisPulse. Если имя пакета не указано, запускается интерактивное обновление всех.

**Алиас:** `up`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[package]...` | | Имя пакета для обновления, можно указать несколько |
| `--force` | `-f` | Принудительное обновление, без подтверждения |
| `--pre` | | Разрешить обновление до предварительных версий |
| `--no-uv` | | Использование pip вместо uv |

**Примеры:**

```bash
# Обновление всех пакетов
epsdk upgrade

# Обновление указанного пакета
epsdk upgrade Weather

# Принудительное обновление (без подтверждения)
epsdk upgrade -f
```

### self-update

Обновление самого SDK ErisPulse до последней версии.

**Алиас:** `su`, `update`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[version]` | | Указание целевой версии для обновления |
| `--pre` | | Разрешить обновление до предварительных версий |
| `--force` | `-f` | Принудительное обновление, без подтверждения |
| `--no-uv` | | Использование pip вместо uv |

**Примеры:**

```bash
# Обновление до последней стабильной версии
epsdk self-update

# Обновление до указанной версии
epsdk self-update 1.2.3

# Разрешить предварительные версии
epsdk self-update --pre

# Принудительное обновление
epsdk self-update -f
```

> [!NOTE]
> При установке через `uv tool install ErisPulse`, команда автоматически переходит на `uv tool upgrade ErisPulse` (при указании версии — `uv tool install ErisPulse==<версия> --force`), прямое обновление pip-ом приведет к восстановлению инвентаря uv с удалением инструментальной среды.
> На Windows обновление происходит в новом окне консоли: текущий CLI должен выйти для освобождения файлов инструментальной среды, после завершения окна перезапустите терминал.

## Команды конфигурации

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `config` | `cfg`, `conf` | `[name] [--list/-l] [--json]` | Интерактивная конфигурация адаптера/модуля |

### config

Интерактивное заполнение декларативных настроек адаптера/модуля. Визуальная форма генерируется на основе класса конфигурации (`ConfigClass` / `AccountConfigClass`), без необходимости ручного редактирования `config.toml`.

Адаптеры дополнительно поддерживают управление несколькими аккаунтами (бот-аккаунтами): добавление/редактирование/удаление аккаунтов, а также включение/отключение.

**Алиас:** `cfg`, `conf`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[name]` | | Имя цели (название платформы адаптера или модуля), пустое значение ведет к интерактивному выбору |
| `--list` | `-l` | Вывод только состояния конфигурации всех целей, без запуска визуальной формы |
| `--json` | | Вывод состояния конфигурации всех целей в формате JSON (для CI / скриптов), без запуска визуальной формы |

**Примеры:**

```bash
# Вывод состояния конфигурации всех адаптеров/модулей
epsdk config --list

# Вывод состояния конфигурации в формате JSON (для CI / скриптов)
epsdk config --json

# Интерактивный выбор цели для конфигурации
epsdk config

# Конфигурация указанного адаптера
epsdk config yunhu

# Конфигурация указанного модуля
epsdk config MyModule
```

**Описание:**

- Состояние конфигурации делится на четыре категории: `Готово` (валидация пройдена), `Незавершено` (отсутствуют обязательные поля или ошибка валидации), `Не настроено` (никогда не создавалось), `Нет конфигурации` (цель не декларирует класс конфигурации)
- Значения полей снабжены указанием источника: если конфигурация уже создана, отображается `当前:值`, если не создана — значение по умолчанию `默认:值`; пустой ввод оставляет текущее значение
- Поля с секретами (объявлены `secret`) не отображаются при вводе, пустой ввод оставляет установленное значение
- В интерактивном режиме после завершения одной формы возвращается в меню выбора (состояние обновлено), можно настроить несколько целей, пустой ввод завершает
- При неудачной валидации формы и отказе от повторного ввода текущая форма отменяется, и никакие конфигурации не записываются (избегается состояние "включено, но конфигурация не завершена")
- Сохранение немедленно записывается в `config/config.toml`, видно в Dashboard и работающем SDK; для применения новой конфигурации аккаунта в работающем адаптере перезапустите процесс
- После успешной установки адаптера через `epsdk install` / `epsdk init`, если обнаружено объявление конфигурации, автоматически запускается визуальная форма; при установке через командную строку выводится только подсказка

## Команды управления запуском

> [!TIP]
> `epsdk run` автоматически использует виртуальное окружение `.venv` в проектной директории для запуска бота
> (также можно явно указать интерпретатор через переменную окружения `ERISPULSE_PYTHON`). Команды `epsdk install` /
> `uninstall` / `upgrade` / `list` также действуют на виртуальное окружение проекта.

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `run` | `r` | `[script] [--reload] [--strict/--no-strict]` | Запуск указанного скрипта или SDK |
| `stop` | — | `[--force] [--pid PID]` | Остановка запущенного экземпляра (запущенного через `epsdk run`) |
| `restart` | — | `[--force] [--pid PID]` | Перезапуск запущенного экземпляра (остановка и перезапуск с теми же параметрами) |

### run

Запуск скрипта проекта ErisPulse или прямой запуск SDK. Поддерживает режим горячей перезагрузки.

**Алиас:** `r`

**Параметры:**

| Параметр | Описание |
|------|------|
| `[script]` | Запускаемый скрипт, если не указан, запускается SDK |
| `--reload` | Включение режима горячей перезагрузки, мониторинг изменений файлов автоматически запускает горячую перезагрузку кода компонентов (взаимодействие с системой горячей перезагрузки, без перезапуска всего процесса) |
| `--strict` / `--no-strict` | Временное включение / отключение строгого режима (только для этой сессии, не записывается в конфигурацию); по умолчанию следует `ErisPulse.framework.strict_mode` |

**Примеры:**

```bash
# Прямой запуск SDK
epsdk run

# Запуск указанного скрипта
epsdk run main.py

# Горячая перезагрузка (изменение файлов автоматически запускает горячую перезагрузку кода)
epsdk run main.py --reload

# Горячая перезагрузка SDK
epsdk run --reload

# Временный строгий режим: автосамопроверка не прошла, процесс завершается, строгость фреймворка временно повышается до минимум 1
epsdk run main.py --strict

# Временный нестрогий режим (в конфигурации включен strict_mode, но на этот раз нужно запустить)
epsdk run main.py --no-strict
```

**Автосамопроверка при запуске:** `run` перед запуском быстро проверяет разбор `config/config.toml` и обязательные настройки установленных компонентов, строгость по умолчанию следует `ErisPulse.framework.strict_mode` (если не 0, проверка не пройдена — процесс завершается, если 0 — только предупреждение и продолжение). Отсутствие файла конфигурации считается нормальным для первого запуска, только предупреждение, не ошибка. `--strict` временно включает: предварительная проверка не пройдена — процесс завершается, при этом строгость фреймворка временно повышается до минимум 1 (пропуск некорректных компонентов, через переменную окружения `ERISPULSE_FRAMEWORK_STRICT_MODE` передается в запущенный процесс, не записывается в файл конфигурации); `--no-strict` временно снижает до нестрогого. При ошибках самой самопроверки автоматически пропускается, не включает проверку сети, не блокирует запуск.

### stop

Остановка запущенного экземпляра ErisPulse (запущенного через `epsdk run` и выполненного в той же проектной директории).
При запуске `run` PID супервайзера, PID подпроцесса фреймворка и исходная команда запуска записываются в
`.erispulse/runtime.json`, `stop` использует эти данные для определения экземпляра.

**Порядок остановки:** В POSIX сначала отправляется сигнал SIGINT супервайзеру (аналогичный Ctrl+C — элегантный путь завершения —
цепочка finally автоматически останавливает подпроцесс фреймворка), при таймауте постепенно повышаются SIGTERM / SIGKILL; в Windows сигналы процессов отсутствуют, сначала останавливается подпроцесс фреймворка, затем супервайзер (чтобы супервайзер не ошибочно воспринял принудительное завершение за сбой и не перезапустил).

**Параметры:**

| Параметр | Описание |
|------|------|
| `--force` | Принудительная остановка без элегантного завершения |
| `--pid PID` | Прямое указание PID цели (переопределяет файл состояния, используется для нестандартных способов запуска) |

**Примеры:**

```bash
# Остановка запущенного экземпляра проекта
epsdk stop

# Принудительная остановка
epsdk stop --force
```

### restart

Перезапуск запущенного экземпляра ErisPulse: остановка по семантике `stop`, затем перезапуск с использованием
записанной в файле состояния
**исходной команды запуска** (передача управления текущему терминалу, новый экземпляр записывает новый файл состояния).

**Параметры:** такие же, как у `stop` (`--force` / `--pid PID`).

**Примеры:**

```bash
# Элегантный перезапуск (после обновления адаптера/модуля через pip применить изменения кода; модули в процессе работы также можно использовать
# sdk.reload_module / sdk.adapter.reload для горячей перезагрузки кода, без перезапуска)
epsdk restart
```

> [!NOTE]
> Процессы, запущенные через `python main.py` и т.д., не записывают файл состояния — такие
> процессы следует управлять системными инструментами, или использовать `epsdk stop --pid <PID>` для указания PID.

### init

Инициализация нового проекта ErisPulse. Поддерживает интерактивный и быстрый режим, начиная с версии 2.8.4, генерирует `pyproject.toml` (список зависимостей), необязательно создает виртуальное окружение `.venv` проекта и устанавливает фреймворк и адаптеры, а также поддерживает **указание произвольной директории**.

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[path]` | | Целевой путь (может включать родительскую директорию, например `../apps/mybot`; чистое имя эквивалентно `--project-name`) |
| `--project-name` | `-n` | Имя проекта |
| `--path` | | Родительская директория проекта (в сочетании с `-n` указывает место создания) |
| `--adapter` | `-a` | Предварительно выбранный адаптер для установки (можно передавать несколько раз или через запятую), при передаче пропускается запрос и выбор адаптера |
| `--quick` | `-q` | Быстрый режим, пропускает интерактивное руководство (по умолчанию создает `.venv` и устанавливает зависимости) |
| `--force` | `-f` | Принудительное перезапись существующих файлов конфигурации |
| `--here` | | Инициализация в текущей директории, без создания поддиректории |
| `--no-uv` | | Использование pip вместо uv |
| `--no-venv` | | Пропуск создания виртуального окружения и установки зависимостей |

**Примеры:**

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация (создание my_bot/ в текущей директории, с pyproject.toml + .venv)
epsdk init -q -n my_bot

# Быстрая инициализация с предустановленным адаптером (без интерактива, для скриптов / CI)
epsdk init -q -n my_bot --adapter yunhu,telegram

# Инициализация в произвольной директории (../apps/mybot)
epsdk init ../apps/mybot

# Комбинация родительской директории и имени проекта
epsdk init -n my_bot --path ../apps

# Принудительная перезапись существующих конфигураций
epsdk init -f

# Инициализация в текущей директории
epsdk init --here -n my_bot

# Создание структуры проекта без виртуального окружения
epsdk init --no-venv -n my_bot
```

Результаты init: `main.py`, `pyproject.toml` (список зависимостей), `config/config.toml` + `config.full.example`, `config/ssl/`, `logs/`, `.gitignore`, `README.md`; при выборе создания виртуального окружения дополнительно генерируется `.venv` и устанавливаются `erispulse` и выбранные адаптеры.

> [!NOTE]
> `.gitignore` представляет собой шаблон группового формата: байт-коды Python и результаты сборки, виртуальные окружения и `.env`, кэш инструментов, файлы редактора и системы, и **полностью исключает директории `config/` и `logs/`**, поскольку `config.toml` содержит токены адаптеров и другие чувствительные данные, не рекомендуется добавлять в репозиторий; для совместного использования шаблона конфигурации используйте `config.full.example`.

> [!WARNING]
> **Не используйте `uv run epsdk run` для запуска бота**. `uv run` в директории без `pyproject.toml` создает **одноразовую изолированную среду** — в ней через `epsdk install` установленные адаптеры не сохраняются. Используйте `epsdk run` в проектной директории (автоматически использует `.venv` проекта), или активируйте виртуальное окружение перед запуском.

### create

Создание шаблона проекта модуля или адаптера ErisPulse; подкоманда `pack` преобразует локальный плагин (`plugins/` директория) в публикуемый стандартный проект.

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `{module,adapter,pack}` | | Тип создаваемого проекта: `module` / `adapter` / `pack` (преобразование плагина в проект) |
| `--name` | `-n` | Название проекта (в стиле PascalCase) |
| `--description` | `-d` | Описание проекта |
| `--author` | `-a` | Имя автора |
| `--email` | `-e` | Email автора |
| `--homepage` | | URL домашней страницы проекта |
| `--output` | `-o` | Директория вывода (по умолчанию текущая директория) |
| `--force` | `-f` | Принудительная перезапись существующей директории |
| `--local` | | Создание локального плагина (`module` / `adapter` доступны): генерация структуры пакета `plugins/<name>/`, без установки через пакет |

**Примеры:**

```bash
# Интерактивное создание (вывод руководства по выбору типа и заполнению информации)
epsdk create

# Прямое создание проекта модуля
epsdk create module -n MyModule

# Создание локального плагина (в директорию `plugins/` проекта, автоматически обнаруживается при запуске)
epsdk create module -n MyModule --local

# Создание локального плагина адаптера (аналогично, без установки через пакет)
epsdk create adapter -n MyAdapter --local

# Прямое создание проекта адаптера
epsdk create adapter -n MyAdapter

# Преобразование локального плагина в публикуемый проект (интерактивный выбор плагина → дополнение метаинформации → генерация стандартного проекта)
epsdk create pack

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Указание директории вывода
epsdk create module -n MyModule -o ./projects

# Принудительная перезапись существующей директории
epsdk create module -n MyModule -f
```

## Среда диагностики

### doctor

> [!NOTE]
> Эта команда требует ErisPulse **2.7.0+**.

Диагностика текущей среды CLI, вывод отчета о здоровье. Используется для устранения проблем "почему не устанавливается / не подключается".

| Параметр | Описание |
|------|------|
| `--verbose` | Показать подробную диагностику |
| `--fix` | После диагностики попытаться автоматически исправить исправимые проблемы |

**Проверяемые элементы:**
- **Python:** версия и путь интерпретатора
- **Установочный бэкенд:** используется `uv` или `pip`
- **Целевой интерпретатор:** фактическая среда установки пакетов
- **Конфигурационный файл:** наличие `config/config.toml`
- **Конфигурация компонентов:** целостность декларативной конфигурации установленных компонентов ("установлен, но не запускается" часто из-за отсутствующих обязательных полей)
- **Соединение с PyPI:** доступность PyPI (и отображение найденных компонентов)
- **Системный прокси:** обнаружение прокси-сервера

**Автоматическое исправление (`--fix`):**
- Отсутствие `config.toml` → создание начального конфигурационного файла на основе текущего языка (аналогично `init`)
- Конфигурация компонентов "незавершена" → поочередный запуск интерактивной формы конфигурации для заполнения обязательных полей (в неинтерактивной среде советуется использовать `epsdk config <имя>`)
- Проблемы с низкой версией Python, недоступность PyPI и т.д. → только вывод рекомендаций

```bash
# Диагностика среды
epsdk doctor

# Использование алиаса
epsdk diag

# Диагностика и попытка автоматического исправления
epsdk doctor --fix
```

## Интерактивная установка

Запуск `epsdk install` без указания имени пакета ведет к интерактивной установке:

```bash
epsdk install
```

Интерактивное меню предоставляет:
1. Выбор адаптера
2. Выбор модуля
3. Пользовательская установка

## Распространенные случаи использования

### Установка модуля

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Обновление модуля
epsdk install Weather -U
```

### Вывод компонентов

```bash
# Вывод всех компонентов
epsdk list

# Только адаптеры
epsdk list -t adapters

# Только обновляемые компоненты
epsdk list -o

# Просмотр удаленных доступных компонентов
epsdk list-remote
```

### Удаление компонентов

```bash
# Удаление одного компонента
epsdk uninstall Weather

# Удаление нескольких компонентов
epsdk uninstall Yunhu Weather
```

### Конфигурация компонентов

```bash
# Вывод состояния конфигурации
epsdk config --list

# Интерактивный выбор цели для конфигурации
epsdk config

# Конфигурация указанного адаптера
epsdk config yunhu
```

### Обновление компонентов

```bash
# Обновление всех компонентов
epsdk upgrade

# Обновление указанного компонента
epsdk upgrade Weather

# Принудительное обновление
epsdk upgrade -f
```

### Запуск проекта

```bash
# Обычный запуск
epsdk run main.py

# Запуск в режиме горячей перезагрузки
epsdk run main.py --reload
```

### Смена языка

```bash
# Интерактивный выбор языка
epsdk i18n

# Прямая смена на английский
epsdk i18n en

# Вывод списка поддерживаемых языков
epsdk i18n --list
```

### Генерация типовых аннотаций

```bash
# Генерация всех типовых аннотаций
epsdk types

# Только для модулей
epsdk types --modules-only
```

### Инициализация проекта

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация
epsdk init -q -n my_bot
```

### Создание шаблона

```bash
# Интерактивное создание (вывод руководства по выбору типа и заполнению информации)
epsdk create

# Прямое создание проекта модуля
epsdk create module -n MyModule

# Прямое создание проекта адаптера
epsdk create adapter -n MyAdapter

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Принудительная перезапись существующей директории
```
