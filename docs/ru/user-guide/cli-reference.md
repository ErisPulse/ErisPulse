# Справочник команд CLI

> [!TIP]
> **Когда читать этот документ**: если вы забыли параметры какой-либо команды `epsdk`, хотите автоматизировать управление компонентами в скриптах или вам нужно управлять поведением run / stop / restart. Если вы в повседневной работе используете только `init` / `install` / `run`, достаточно запомнить одно: `epsdk <команда> --help` в любой момент покажет описание параметров, читать весь документ целиком не обязательно.

`epsdk` — это инструмент командной строки ErisPulse: инициализация проектов, установка / обновление модулей и адаптеров, интерактивная настройка компонентов, запуск и остановка бота, диагностика окружения — всё в одной команде.

> **Подсказка**: основная справка `epsdk` (без команды) сгруппирована по категориям: **Проект** (init / create / run), **Управление компонентами** (install / uninstall / upgrade / list / list-remote / types), **Конфигурация и диагностика** (config / doctor / i18n), **Прочее** (self-update / version).

### install

Установка модулей ErisPulse или пакетов адаптеров. Если имя пакета не указано, запускается интерактивный интерфейс установки.

**Псевдонимы:** `i`, `add`

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `[package]...` | | Названия пакетов для установки, можно указать несколько |
| `--upgrade` | `-U` | Обновление до последней версии при установке |
| `--pre` | | Разрешить установку пре-релизных версий |
| `--editable` | `-e` | Установка в режиме editable (требует указания пути) |
| `--user` | | Установка в пользовательский каталог site-packages |
| `--no-deps` | | Не устанавливать зависимости |
| `--target` | `-t` | Установка в указанный каталог |
| `--index-url` | | Указать адрес зеркала PyPI |
| `--extra-index-url` | | Дополнительный адрес зеркала PyPI (можно указывать несколько раз) |
| `--no-cache-dir` | | Отключить кэширование |
| `--requirement` | `-r` | Установка из файла requirements |
| `--constraint` | `-c` | Установка из файла ограничений (constraints) |
| `--force-reinstall` | | Принудительная переустановка |
| `--ignore-installed` | | Игнорировать уже установленные пакеты |
| `--compile` | | Компилировать .pyc-файлы после установки |
| `--no-compile` | | Не компилировать .pyc-файлы после установки |
| `--prefix` | | Установка в указанный каталог-префикс |
| `--src` | | Каталог исходного кода для установки в режиме editable |
| `--config-settings` | | Настройки, передаваемые бэкенду сборки (можно указывать несколько раз) |
| `--no-binary` | | Запретить использование бинарных пакетов (формат, например, `:all:`) |
| `--only-binary` | | Разрешить только бинарные пакеты (формат, например, `:all:`) |
| `--prefer-binary` | | Приоритет бинарных пакетов |
| `--build-isolation` | | Включить изоляцию сборки |
| `--no-build-isolation` | | Отключить изоляцию сборки |
| `--upgrade-strategy` | | Стратегия обновления: `eager`, `only-if-needed`, `to-satisfy-only` |
| `--break-system-packages` | | Разрешить изменение Python-пакетов, управляемых системным пакетным менеджером |
| `--no-uv` | | Использовать pip вместо uv |

**Примеры:**

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Установка с зеркала с обновлением
epsdk install Weather -U --index-url https://pypi.tuna.tsinghua.edu.cn/simple

# Установка в режиме editable (режим разработки)
epsdk install -e ./my-adapter
```

### uninstall

Удаление установленных модулей ErisPulse или пакетов адаптеров. Если имя пакета не указано, запускается интерактивный интерфейс удаления.

**Псевдонимы:** `rm`, `remove`

**Параметры:**

| Параметр | Описание |
|------|------|
| `<package>...` | Названия пакетов для удаления, можно указать несколько |
| `--no-uv` | Использовать pip вместо uv |

**Примеры:**

```bash
# Удаление одного модуля
epsdk uninstall Weather

# Удаление нескольких модулей
epsdk uninstall Yunhu Weather
```

### upgrade

Обновление установленных компонентов ErisPulse. Если имя пакета не указано, выполняется интерактивное обновление всех компонентов.

**Псевдонимы:** `up`

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `[package]...` | | Названия пакетов для обновления, можно указать несколько |
| `--force` | `-f` | Принудительное обновление без подтверждения |
| `--pre` | | Разрешить обновление до пре-релизных версий |
| `--no-uv` | | Использовать pip вместо uv |

**Примеры:**

```bash
# Обновление всех пакетов
epsdk upgrade

# Обновление указанного пакета
epsdk upgrade Weather

# Принудительное обновление (без подтверждения)
epsdk upgrade -f
```

### self-update

Обновление самого ErisPulse SDK до последней версии.

**Псевдонимы:** `su`, `update`

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `[version]` | | Указать целевой номер версии для обновления |
| `--pre` | | Разрешить обновление до пре-релизных версий |
| `--force` | `-f` | Принудительное обновление без подтверждения |
| `--no-uv` | | Использовать pip вместо uv |

**Примеры:**

```bash
# Обновление до последней стабильной версии
epsdk self-update

# Обновление до указанной версии
epsdk self-update 1.2.3

# Разрешить пре-релизные версии
epsdk self-update --pre

# Принудительное обновление
epsdk self-update -f
```

> [!NOTE]
> При установке через `uv tool install ErisPulse` эта команда автоматически переключается на `uv tool upgrade ErisPulse` (при указании версии — `uv tool install ErisPulse==<версия> --force`), поскольку прямое обновление окружения инструмента через pip будет отменено манифестом uv.
> В Windows обновление выполняется в новом окне консоли: текущий CLI должен сначала завершиться, чтобы освободить файлы окружения инструмента; после сообщения о завершении в окне просто заново откройте терминал.

Список установленных модулей и адаптеров ErisPulse.

**Псевдонимы:** `l`, `ls`

**Параметры:**

| Параметр | Краткая форма | Описание |

|------|--------|------|
| `--type` | `-t` | Указать тип: `modules`, `adapters`, `all` (по умолчанию) |
| `--refresh` | `-r` | Принудительно обновить кэш списка удалённых пакетов |

**Примеры:**

```bash
# Список всех доступных удалённых компонентов
```

## Команды конфигурации

| Команда | Псевдонимы | Параметры | Описание |
|------|------|------|------|
| `config` | `cfg`, `conf` | `[name] [--list/-l] [--json]` | Интерактивная настройка декларативных параметров адаптеров/модулей |

### config

Интерактивное заполнение декларативных параметров конфигурации адаптеров/модулей. Мастер настройки управляется классами конфигурации (`ConfigClass` / `AccountConfigClass`), объявленными адаптером/модулем: форма генерируется и проверяется автоматически, без необходимости вручную писать config.toml.

Адаптеры дополнительно поддерживают управление несколькими аккаунтами (bot-аккаунтами): добавление/редактирование/удаление аккаунтов, а также переключатели включения/отключения.

**Псевдонимы:** `cfg`, `conf`

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `[name]` | | Имя цели (платформа адаптера или имя модуля); если оставить пустым, запускается интерактивный выбор |
| `--list` | `-l` | Только показать состояние конфигурации всех целей, без запуска мастера |
| `--json` | | Вывести в JSON все цели и состояние их конфигурации (для использования в CI / скриптах), без запуска мастера |

**Примеры:**

```bash
# Просмотр состояния конфигурации всех адаптеров/модулей
epsdk config --list

# Вывод состояния конфигурации в JSON (для CI / скриптов)
epsdk config --json

# Интерактивный выбор цели для настройки
epsdk config

# Прямая настройка указанного адаптера
epsdk config yunhu

# Прямая настройка указанного модуля
epsdk config MyModule
```

**Примечания:**

- Состояние конфигурации делится на четыре уровня: `готово` (проверка пройдена), `требует доработки` (отсутствуют обязательные поля или проверка не пройдена), `не настроено` (никогда не генерировалось), `нет конфигурации` (цель не объявляет класс конфигурации)
- Значения полей снабжены указанием источника: для существующей конфигурации отображается `(текущее: значение)`, при отсутствии конфигурации — значение по умолчанию из схемы `(по умолчанию: значение)`; нажатие Enter сохраняет это значение
- Поля-секреты (с объявлением `secret`) при вводе не отображаются на экране; нажатие Enter сохраняет уже установленное значение
- В режиме интерактивного выбора после завершения одного мастера происходит возврат в меню выбора (состояние обновлено), можно настраивать несколько целей подряд; пустой ввод — выход
- Если проверка глобальной формы не пройдена и вы отказываетесь от повторного заполнения, текущий мастер прерывается и никакая конфигурация не записывается (чтобы избежать «полуготового» состояния «включено, но конфигурация неполная»)
- После сохранения изменения немедленно записываются в `config/config.toml` и видны как в Dashboard, так и в работающем SDK; чтобы работающий адаптер применил новую конфигурацию аккаунтов, достаточно перезапустить процесс
- После успешной установки адаптера через `epsdk install` (интерактивную установку) или `epsdk init` при обнаружении объявления конфигурации автоматически запускается этот мастер; при установке с указанием имени пакета прямо в командной строке выводится только подсказка о конфигурации

## Команды управления запуском

> [!TIP]
> `epsdk run` автоматически обнаруживает и использует виртуальное окружение `.venv` в каталоге проекта для запуска бота
> (интерпретатор можно также явно указать через переменную окружения `ERISPULSE_PYTHON`). `epsdk install` /
> `uninstall` / `upgrade` / `list` также работают с виртуальным окружением проекта.

| Команда | Псевдонимы | Параметры | Описание |
|------|------|------|------|
| `run` | `r` | `[script] [--reload] [--strict/--no-strict]` | Запуск указанного скрипта или SDK |
| `stop` | — | `[--force] [--pid PID]` | Остановка работающего экземпляра (запущенного через `epsdk run`) |
| `restart` | — | `[--force] [--pid PID]` | Перезапуск работающего экземпляра (остановка, затем запуск с исходными параметрами) |

### run

Запуск скрипта проекта ErisPulse или непосредственный запуск SDK. Поддерживается режим горячей перезагрузки.

**Псевдонимы:** `r`

**Параметры:**

| Параметр | Описание |
|------|------|
| `[script]` | Запускаемый файл скрипта; если не указан, запускается SDK |
| `--reload` | Включить режим горячей перезагрузки: отслеживание изменений файлов автоматически запускает горячую перезагрузку кода на уровне компонентов (взаимодействует с системой горячей перезагрузки, без перезапуска всего процесса) |
| `--strict` / `--no-strict` | Временно включить / выключить строгий режим (действует только для текущего запуска, конфигурация не изменяется); по умолчанию следует за `ErisPulse.framework.strict_mode` |

**Примеры:**

```bash
# Прямой запуск SDK
epsdk run

# Запуск указанного файла скрипта
epsdk run main.py

# Запуск в режиме горячей перезагрузки (изменения файлов автоматически запускают горячую перезагрузку кода)
epsdk run main.py --reload

# Режим горячей перезагрузки SDK
epsdk run --reload

# Временный строгий режим: при провале предзапускаемой самопроверки происходит выход, уровень строгости фреймворка в этот раз повышается минимум до 1
epsdk run main.py --strict

# Временный мягкий режим (в конфигурации включён strict_mode, но в этот раз нужно просто запуститься)
epsdk run main.py --no-strict
```

**Предзапускаемая самопроверка:** перед запуском `run` быстро проверяет, можно ли разобрать `config/config.toml`, и полноту обязательной конфигурации установленных компонентов; строгость по умолчанию следует за `ErisPulse.framework.strict_mode` (при значении не 0 провал проверки приводит к выходу, при 0 — только предупреждение и продолжение). Отсутствие файла конфигурации считается нормальным первым запуском: выводится только подсказка, без признания провала. `--strict` временно включает: при провале предварительной проверки происходит выход, при этом уровень строгости фреймворка в этот раз повышается минимум до 1 (несоответствующие компоненты пропускаются; передаётся в запускаемый процесс через переменную окружения `ERISPULSE_FRAMEWORK_STRICT_MODE`, файл конфигурации не изменяется); `--no-strict` наоборот временно понижает до мягкого режима. При внутренней ошибке самой самопроверки она автоматически пропускается; сетевых проверок не содержит и запуску не мешает.

### stop

Остановка работающего экземпляра ErisPulse (запущенного через `epsdk run` и выполняющегося в том же каталоге проекта).
При запуске `run` записывает PID процесса-супервизора, PID текущего дочернего процесса фреймворка и исходную команду запуска в
`.erispulse/runtime.json`; `stop` по этим данным находит экземпляр.

**Порядок остановки:** в POSIX сначала процессу-супервизору отправляется SIGINT (тот же корректный путь завершения, что и Ctrl+C —
цепочка finally автоматически завершает дочерний процесс фреймворка), при таймауте выполняется эскалация до SIGTERM / SIGKILL; в Windows нет
семантики сигналов процессов, поэтому сначала завершается дочерний процесс фреймворка, затем процесс-супервизор (чтобы супервизор не принял принудительное завершение за сбой
и не перезапустил процесс).

**Параметры:**

| Параметр | Описание |
|------|------|
| `--force` | Пропустить корректную остановку, немедленно принудительно завершить |
| `--pid PID` | Непосредственно указать PID целевого процесса (переопределяет файл состояния запуска; для нестандартных способов запуска) |

**Примеры:**

```bash
# Остановка работающего экземпляра текущего проекта
epsdk stop

# Принудительное завершение
epsdk stop --force
```

### restart

Перезапуск работающего экземпляра ErisPulse: сначала выполняется остановка в соответствии с семантикой `stop`, затем запуск с
**исходной командой запуска**, записанной в файле состояния (экземпляр запускается на переднем плане в текущем терминале; новый экземпляр записывает новый файл состояния запуска).

**Параметры:** те же, что у `stop` (`--force` / `--pid PID`).

**Примеры:**

```bash
# Корректный перезапуск (применить код после обновления адаптера/модуля через pip; работающие модули также можно
# перезагрузить на уровне кода через sdk.reload_module / sdk.adapter.reload, без перезапуска)
epsdk restart
```

> [!NOTE]
> Способы запуска в обход `epsdk run`, например `python main.py`, не записывают файл состояния запуска — такие
> процессы управляйте системными средствами или укажите PID через `epsdk stop --pid <PID>`.

| `init` | — | `[path] [--project-name/-n <name>] [--path <dir>] [--adapter/-a <name>] [--quick/-q] [--force/-f] [--here] [--no-uv] [--no-venv]` | Инициализация проекта ErisPulse |
| `create` | — | `{module,adapter,pack} [--name/-n <name>] [--description/-d <desc>] [--author/-a <name>] [--email/-e <mail>] [--homepage <url>] [--output/-o <dir>] [--force/-f] [--local]` | Создание каркаса модуля/адаптера; `pack` преобразует локальный плагин в публикуемый проект |

### init

Инициализация нового проекта ErisPulse. Поддерживаются интерактивный и быстрый режимы; начиная с 2.8.4 генерируется `pyproject.toml` (манифест зависимостей), опционально создаётся виртуальное окружение проекта `.venv` с установкой фреймворка и адаптеров, а также поддерживается **указание произвольного каталога**.

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `[path]` | | Целевой путь (может включать родительские каталоги, например `../apps/mybot`; чистое имя эквивалентно `--project-name`) |
| `--project-name` | `-n` | Название проекта |
| `--path` | | Родительский каталог проекта (в сочетании с `-n` задаёт место создания) |
| `--adapter` | `-a` | Предварительно выбранные адаптеры для установки (можно передавать повторно или через запятую); при указании пропускает опрос и выбор адаптеров |
| `--quick` | `-q` | Быстрый режим, пропуск интерактивного мастера (по умолчанию создаёт `.venv` и устанавливает зависимости) |
| `--force` | `-f` | Принудительно перезаписать существующие файлы конфигурации |
| `--here` | | Инициализация в текущем каталоге, без создания подкаталога |
| `--no-uv` | | Использовать pip вместо uv |
| `--no-venv` | | Пропустить создание виртуального окружения и установку зависимостей |

**Примеры:**

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация (в текущем каталоге создаётся my_bot/ с pyproject.toml + .venv)
epsdk init -q -n my_bot

# Быстрая инициализация с предустановкой адаптеров (без взаимодействия, для скриптов / CI)
epsdk init -q -n my_bot --adapter yunhu,telegram

# Инициализация в произвольном каталоге (../apps/mybot)
epsdk init ../apps/mybot

# Комбинация родительского каталога и имени проекта
epsdk init -n my_bot --path ../apps

# Принудительная перезапись существующей конфигурации
epsdk init -f

# Инициализация в текущем каталоге
epsdk init --here -n my_bot

# Только структура проекта, без создания виртуального окружения
epsdk init --no-venv -n my_bot
```

Результат init: `main.py`, `pyproject.toml` (манифест зависимостей), `config/config.toml` + `config.full.example`, `config/ssl/`, `logs/`, `.gitignore`, `README.md`; при выборе создания виртуального окружения дополнительно создаётся `.venv`, в который устанавливаются `erispulse` и выбранные адаптеры.

> [!NOTE]
> `.gitignore` — это шаблон с группами: байткод Python и артефакты сборки, виртуальные окружения и `.env`, кэш инструментов, файлы редакторов и системы, причём **каталоги времени выполнения `config/` и `logs/` исключены целиком** — в `config.toml` содержатся чувствительные данные вроде токенов адаптеров, добавлять его в репозиторий не рекомендуется; для передачи каркаса конфигурации используйте `config.full.example`.

> [!WARNING]
> **Не запускайте бота командой `uv run epsdk run`**. При выполнении `uv run` в каталоге без `pyproject.toml` создаётся **одноразовое изолированное окружение** — установленные в нём через `epsdk install` адаптеры не сохраняются. Используйте `epsdk run` внутри каталога проекта (автоматически используется `.venv` проекта) или сначала активируйте виртуальное окружение, а затем запускайте.

### create

Создание каркасного проекта модуля или адаптера ErisPulse; подкоманда `pack` преобразует локальный плагин (каталог `plugins/`) в стандартный публикуемый проект.

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `{module,adapter,pack}` | | Тип создаваемого: `module` / `adapter` / `pack` (плагин → проект)|
| `--name` | `-n` | Название проекта (PascalCase) |
| `--description` | `-d` | Описание проекта |
| `--author` | `-a` | Имя автора |
| `--email` | `-e` | Email автора |
| `--homepage` | | URL домашней страницы проекта |
| `--output` | `-o` | Каталог вывода (по умолчанию текущий каталог) |
| `--force` | `-f` | Принудительно перезаписать существующий каталог |
| `--local` | | Создать локальный плагин (доступно для `module` / `adapter`): генерируется структура пакета `plugins/<name>/`, установка без упаковки |

**Примеры:**

```bash
# Интерактивное создание (выбор типа и заполнение информации с подсказками)
epsdk create

# Прямое создание проекта Module
epsdk create module -n MyModule

# Создание локального плагина (размещается в каталоге plugins/ проекта, автоматически обнаруживается при запуске)
epsdk create module -n MyModule --local

# Создание локального плагина адаптера (аналогично, разработка без упаковки)
epsdk create adapter -n MyAdapter --local

# Прямое создание проекта Adapter
epsdk create adapter -n MyAdapter

# Преобразование локального плагина в публикуемый проект (интерактивный выбор плагина → заполнение метаданных → генерация стандартного проекта)
epsdk create pack

# Полный набор параметров
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Указать каталог вывода
epsdk create module -n MyModule -o ./projects

# Принудительно перезаписать существующий каталог
epsdk create module -n MyModule -f
```

## Команды type-заглушек

| Команда | Псевдонимы | Параметры | Описание |
|------|------|------|------|
| `types` | `t`, `stub` | `[--output/-o <path>] [--force] [--adapters-only] [--modules-only]` | Генерация type-заглушек для включения автодополнения в IDE |

### types

Сканирует установленные модули и адаптеры ErisPulse и генерирует для них type-заглушки `.pyi`, что обеспечивает точное автодополнение кода и поддержку проверки типов в IDE.

**Псевдонимы:** `t`, `stub`

**Параметры:**

| Параметр | Краткая форма | Описание |
|------|--------|------|
| `--output` | `-o` | Путь вывода (по умолчанию `ep-stubs/` в текущем каталоге) |
| `--force` | | Принудительно перезаписать существующие файлы заглушек |
| `--adapters-only` | | Генерировать type-заглушки только для адаптеров |
| `--modules-only` | | Генерировать type-заглушки только для модулей |

> **Примечание:** `--adapters-only` и `--modules-only` взаимоисключающи; при одновременном указании применяется последняя опция.

**Примеры:**

```bash
# Генерация type-заглушек для всех установленных модулей и адаптеров
epsdk types

# Только заглушки адаптеров
epsdk types --adapters-only

# Вывод в указанный каталог
epsdk types -o ./typings

# Принудительно перезаписать существующие файлы
epsdk types --force
```

## Диагностика окружения

### doctor

> [!NOTE]
> Для этой команды требуется ErisPulse **2.7.0+**.

Диагностика текущего окружения выполнения CLI с выводом отчёта о состоянии. Предназначена для поиска проблем вида «почему не устанавливается / не подключается».

| Параметр | Описание |
|------|------|
| `--verbose` | Показать подробную диагностическую информацию |
| `--fix` | После диагностики попытаться автоматически исправить устранимые проблемы |

**Проверяемые пункты**:
- **Python**: версия и путь интерпретатора
- **Бэкенд установки**: используется `uv` или `pip`
- **Целевой интерпретатор**: Python-окружение, в которое фактически устанавливаются пакеты
- **Файл конфигурации**: существует ли `config/config.toml`
- **Конфигурация компонентов**: полнота декларативной конфигурации установленных компонентов («установилось, но не запускается» чаще всего из-за отсутствия обязательных полей)
- **Доступность PyPI**: доступен ли PyPI (и отображается количество найденных компонентов)
- **Системный прокси**: обнаружен ли прокси

**Автоисправление (`--fix`)**:
- Отсутствие `config.toml` → генерация начального файла конфигурации на текущем языке (тот же источник, что и при создании проекта через `init`)
- Конфигурация компонента «требует доработки» → последовательный запуск интерактивного мастера настройки для заполнения обязательных полей (в неинтерактивной среде выводится подсказка использовать `epsdk config <имя>`)
- Слишком старая версия Python, недоступность PyPI и другие проблемы, требующие ручного вмешательства → только рекомендации по действиям

```bash
# Диагностика окружения
epsdk doctor

# Использование псевдонима
epsdk diag

# Диагностика с попыткой автоисправления
epsdk doctor --fix
```

## Интерактивная установка

Запуск `epsdk install` без указания имени пакета открывает интерактивную установку:

```bash
epsdk install
```

Интерактивный интерфейс предоставляет:
1. Выбор адаптеров
2. Выбор модулей
3. Пользовательскую установку

## Частые сценарии использования

### Установка модулей

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Обновление модуля
epsdk install Weather -U
```

### Список компонентов

```bash
# Список всех компонентов
epsdk list

# Только адаптеры
epsdk list -t adapters

# Только компоненты с доступными обновлениями
epsdk list -o

# Просмотр доступных удалённых компонентов
epsdk list-remote
```

### Удаление компонентов

```bash
# Удаление одного компонента
epsdk uninstall Weather

# Удаление нескольких компонентов
epsdk uninstall Yunhu Weather
```

### Настройка компонентов

```bash
# Просмотр состояния конфигурации
epsdk config --list

# Интерактивный выбор цели для настройки
epsdk config

# Настройка указанного адаптера
epsdk config yunhu
```

### Обновление компонентов

```bash
# Обновление всех компонентов
epsdk upgrade

# Обновление указанного компонента
epsdk upgrade Weather

# Принудительное обновление
epsdk upgrade -f
```

### Запуск проекта

```bash
# Обычный запуск
epsdk run main.py

# Режим горячей перезагрузки
epsdk run main.py --reload
```

### Смена языка

```bash
# Интерактивный выбор языка
epsdk i18n

# Прямое переключение на английский
epsdk i18n en

# Список поддерживаемых языков
epsdk i18n --list
```

### Генерация type-заглушек

```bash
# Генерация всех type-заглушек
epsdk types

# Только заглушки модулей
epsdk types --modules-only
```

### Инициализация проекта

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация
epsdk init -q -n my_bot
```

### Создание каркаса

```bash
# Интерактивное создание (выбор типа и заполнение информации с подсказками)
epsdk create

# Прямое создание проекта Module
epsdk create module -n MyModule

# Прямое создание проекта Adapter
epsdk create adapter -n MyAdapter

# Полный набор параметров
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Принудительно перезаписать существующий каталог
epsdk create module -n MyModule -f
```

## Что дальше

- **Компоненты установлены, нужно заполнить конфигурацию**: используйте интерактивный мастер `epsdk config` или посмотрите [описание файла конфигурации](configuration.md) для ручного редактирования
- **Код написан, нужно автодополнение в IDE**: выполните `epsdk types`, подробнее в [генерации type-заглушек](../getting-started/ide-completion.md)
- **Бот не запускается**: сначала выполните диагностику окружения `epsdk doctor` (см. [диагностику окружения](#диагностика-окружения)); для долгосрочного развёртывания см. [руководство по развёртыванию](deployment.md)
