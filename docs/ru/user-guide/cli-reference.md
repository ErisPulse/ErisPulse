# Справочник команд CLI

Инструмент командной строки ErisPulse (`epsdk`) предоставляет функции управления проектами и пакетами.

> **Совет:** Детальное описание параметров для всех команд можно получить с помощью `epsdk <команда> --help`.

---

|------|------|------|------|
| `install` | `i`, `add` | `[пакет]... [--upgrade/-U] [--pre] [-e ПУТЬ] [--user] [--no-deps] [-t КАТАЛОГ] [--index-url URL] [--extra-index-url URL] [--no-cache-dir] [-r ФАЙЛ] [-c ФАЙЛ] [--force-reinstall] [--ignore-installed] [--compile/--no-compile] [--prefix КАТАЛОГ] [--src КАТАЛОГ] [--config-settings НАСТРОЙКИ] [--no-binary ФОРМАТ] [--only-binary ФОРМАТ] [--prefer-binary] [--build-isolation/--no-build-isolation] [--upgrade-strategy {eager,only-if-needed,to-satisfy-only}] [--break-system-packages] [--no-uv]` | Установка модуля/адаптера |

### install

Установка пакета модуля или адаптера ErisPulse. Если имя пакета не указано, запускается интерактивный режим установки.

**Алиас:** `i`, `add`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[пакет]...` | | Имя пакета для установки, можно указать несколько |
| `--upgrade` | `-U` | Обновление до последней версии при установке |
| `--pre` | | Разрешить установку предварительных версий |
| `--editable` | `-e` | Установка в режиме редактирования (требуется указать путь) |
| `--user` | | Установка в каталог site-packages пользователя |
| `--no-deps` | | Не устанавливать зависимости |
| `--target` | `-t` | Установка в указанный каталог |
| `--index-url` | | Указание URL-адреса зеркала PyPI |
| `--extra-index-url` | | Дополнительный URL-адрес зеркала PyPI (можно указать несколько) |
| `--no-cache-dir` | | Отключение кэша |
| `--requirement` | `-r` | Установка из файла requirements |
| `--constraint` | `-c` | Установка из файла ограничений |
| `--force-reinstall` | | Принудительная переустановка |
| `--ignore-installed` | | Игнорировать уже установленные пакеты |
| `--compile` | | Компиляция .pyc файлов после установки |
| `--no-compile` | | Не компилировать .pyc файлы после установки |
| `--prefix` | | Установка в указанный префиксный каталог |
| `--src` | | Каталог исходного кода для установки в режиме редактирования |
| `--config-settings` | | Передача настроек конфигурации сборщику (можно указать несколько) |
| `--no-binary` | | Ограничение использования бинарных пакетов (формат: `:all:`) |
| `--only-binary` | | Ограничение использования только бинарных пакетов (формат: `:all:`) |
| `--prefer-binary` | | Предпочтение бинарных пакетов |
| `--build-isolation` | | Включение изоляции сборки |
| `--no-build-isolation` | | Отключение изоляции сборки |
| `--upgrade-strategy` | | Стратегия обновления: `eager`, `only-if-needed`, `to-satisfy-only` |
| `--break-system-packages` | | Разрешить изменение пакетов, управляемых системным пакетным менеджером |
| `--no-uv` | | Использование pip вместо uv |

**Примеры:**

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Установка из зеркала и обновление
epsdk install Weather -U --index-url https://pypi.tuna.tsinghua.edu.cn/simple

# Установка в режиме редактирования (режим разработки)
epsdk install -e ./my-adapter
```

### uninstall

Удаление установленного модуля или адаптера ErisPulse. Если имя пакета не указано, запускается интерактивный режим удаления.

**Алиас:** `rm`, `remove`

**Параметры:**

| Параметр | Описание |
|------|------|
| `<пакет>...` | Имя пакета для удаления, можно указать несколько |
| `--no-uv` | Использование pip вместо uv |

**Примеры:**

```bash
# Удаление одного модуля
epsdk uninstall Weather

# Удаление нескольких модулей
epsdk uninstall Yunhu Weather
```

### upgrade

Обновление установленных компонентов ErisPulse. Если имя пакета не указано, запускается интерактивное обновление всех.

**Алиас:** `up`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[пакет]...` | | Имя пакета для обновления, можно указать несколько |
| `--force` | `-f` | Принудительное обновление, без подтверждения |
| `--pre` | | Разрешить обновление до предварительных версий |
| `--no-uv` | | Использование pip вместо uv |

**Примеры:**

```bash
# Обновление всех пакетов
epsdk upgrade

# Обновление указанного пакета
epsdk upgrade Weather

# Принудительное обновление (без подтверждения)
epsdk upgrade -f
```

### self-update

Обновление самого SDK ErisPulse до последней версии.

**Алиас:** `su`, `update`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[версия]` | | Указание целевой версии для обновления |
| `--pre` | | Разрешить обновление до предварительных версий |
| `--force` | `-f` | Принудительное обновление, без подтверждения |
| `--no-uv` | | Использование pip вместо uv |

**Примеры:**

```bash
# Обновление до последней стабильной версии
epsdk self-update

# Обновление до указанной версии
epsdk self-update 1.2.3

# Разрешить предварительные версии
epsdk self-update --pre

# Принудительное обновление
epsdk self-update -f
```

> [!NOTE]
> При установке с помощью `uv tool install ErisPulse` команда автоматически заменяется на `uv tool upgrade ErisPulse` (при указании версии: `uv tool install ErisPulse==<версия> --force`), прямое обновление инструмента pip приведет к сбросу среды uv. Обновление на Windows происходит в новом окне консоли: текущий CLI должен сначала завершиться, чтобы освободить файл среды инструмента, после завершения окно подсказывает перезапуск терминала.

| Команда | Алиас | Параметры | Описание |

### list

Вывод списка установленных модулей и адаптеров ErisPulse.

**Алиас:** `l`, `ls`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `--type` | `-t` | Указание типа: `modules`, `adapters`, `all` (по умолчанию) |
| `--outdated` | `-o` | Вывод только обновляемых пакетов |

**Примеры:**

```bash
# Вывод всех установленных компонентов
epsdk list

# Вывод только модулей
epsdk list -t modules

# Вывод только адаптеров
epsdk list -t adapters

# Вывод только обновляемых пакетов
epsdk list -o
```

### list-remote

Вывод списка доступных удалённых модулей и адаптеров ErisPulse.

**Алиас:** `lsr`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `--type` | `-t` | Указание типа: `modules`, `adapters`, `all` (по умолчанию) |
| `--refresh` | `-r` | Принудительное обновление кэша удалённых пакетов |

**Примеры:**

```bash
# Вывод всех доступных удалённых компонентов
epsdk list-remote

# Вывод только удалённых модулей
epsdk list-remote -t modules

# Обновление кэша и вывод
epsdk list-remote -r
```

## Команды для настройки

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `config` | `cfg`, `conf` | `[имя] [--list/-l] [--json]` | Интерактивная настройка декларативных параметров адаптера/модуля |

### config

Интерактивное заполнение декларативных параметров конфигурации адаптера/модуля. Визуальный интерфейс генерируется на основе объявленного класса конфигурации (`ConfigClass` / `AccountConfigClass`) адаптера/модуля и выполняет проверку, без необходимости ручного написания `config.toml`.

Адаптеры дополнительно поддерживают управление несколькими аккаунтами (бот аккаунт): добавление/редактирование/удаление аккаунтов, а также включение/отключение.

**Алиас:** `cfg`, `conf`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[имя]` | | Имя цели (название платформы адаптера или модуля), оставьте пустым для выбора |
| `--list` | `-l` | Вывод только состояния конфигурации всех целей, без запуска интерфейса |
| `--json` | | Вывод состояния конфигурации всех целей в формате JSON (для CI / скриптов), без запуска интерфейса |

**Примеры:**

```bash
# Просмотр состояния конфигурации всех адаптеров/модулей
epsdk config --list

# Вывод состояния конфигурации в JSON (для CI / скриптов)
epsdk config --json

# Интерактивный выбор цели для настройки
epsdk config

# Непосредственная настройка указанного адаптера
epsdk config yunhu

# Непосредственная настройка указанного модуля
epsdk config MyModule
```

**Описание:**

- Состояние конфигурации делится на четыре уровня: `Готово` (проверка пройдена), `Незавершено` (отсутствуют обязательные поля или проверка не пройдена), `Не настроено` (никогда не генерировалось), `Без конфигурации` (цель не объявляет класс конфигурации)
- Значения полей снабжены пометками источника: уже настроенные отображаются как `（Текущее:значение）`, ненастраиваемые отображаются как `（По умолчанию:значение）`; просто нажмите Enter для сохранения значения
- Поля с секретами (объявлены как `secret`) не отображают ввод, нажатие Enter сохраняет установленное значение
- В режиме интерактивного выбора, после завершения одного интерфейса возвращается в меню выбора (состояние обновлено), можно настроить несколько целей подряд, оставьте пустым для выхода
- При неудачной валидации формы и отказе от повторного заполнения, текущий интерфейс завершается и никакие настройки не записываются (избегается состояние "включено, но конфигурация неполная")
- После сохранения конфигурация немедленно записывается в `config/config.toml`, доступна в Dashboard и работающем SDK; для применения новых настроек аккаунта в работающем адаптере необходимо перезапустить процесс
- `epsdk install` (интерактивная установка) и `epsdk init` при успешной установке адаптера, если обнаружено объявление конфигурации, автоматически запускает этот интерфейс; при установке по имени пакета в командной строке выводится только подсказка о конфигурации

## Команды управления запуском

> [!TIP]
> `epsdk run` автоматически обнаружит и использует виртуальное окружение `.venv` в директории проекта для запуска робота
> (также можно явно указать интерпретатор с помощью переменной окружения `ERISPULSE_PYTHON`). `epsdk install` /
> `uninstall` / `upgrade` / `list` также применяются к виртуальному окружению проекта.

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `run` | `r` | `[скрипт] [--reload]` | Запуск указанного скрипта или SDK |

### run

Запуск скрипта проекта ErisPulse или запуск SDK напрямую. Поддержка горячей перезагрузки.

**Алиас:** `r`

**Параметры:**

| Параметр | Описание |
|------|------|
| `[скрипт]` | Файл скрипта для запуска, если не указан, запускается SDK |
| `--reload` | Включение горячей перезагрузки, автоматический перезапуск при изменении файлов |

**Примеры:**

```bash
# Запуск SDK
epsdk run

# Запуск указанного файла скрипта
epsdk run main.py

# Горячая перезагрузка (перезапуск при изменении файла)
epsdk run main.py --reload

# Горячая перезагрузка SDK
epsdk run --reload
```

## Команды управления проектами

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `init` | — | `[путь] [--project-name/-n <имя>] [--path <каталог>] [--quick/-q] [--force/-f] [--here] [--no-uv] [--no-venv]` | Инициализация проекта ErisPulse |
| `create` | — | `{module,adapter,pack} [--name/-n <имя>] [--description/-d <описание>] [--author/-a <имя>] [--email/-e <почта>] [--homepage <сайт>] [--output/-o <каталог>] [--force/-f] [--local]` | Создание шаблона модуля/адаптера; `pack` преобразует локальный плагин в публикуемый проект |

### init

Инициализация нового проекта ErisPulse. Поддержка интерактивного и быстрого режимов, начиная с версии 2.8.4 генерируются `pyproject.toml` (список зависимостей), необязательно создание виртуального окружения `.venv` и установка фреймворка и адаптеров, а также поддержка **указания произвольного каталога**.

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[путь]` | | Целевой путь (может включать родительский каталог, например `../apps/mybot`; имя без пути эквивалентно `--project-name`) |
| `--project-name` | `-n` | Имя проекта |
| `--path` | | Родительский каталог проекта (в сочетании с `-n` указывает местоположение создания) |
| `--quick` | `-q` | Быстрый режим, пропуск интерактивного мастера (по умолчанию создает `.venv` и устанавливает зависимости) |
| `--force` | `-f` | Принудительное перезапись существующих файлов конфигурации |
| `--here` | | Инициализация в текущем каталоге, без создания подкаталога |
| `--no-uv` | | Использование pip вместо uv |
| `--no-venv` | | Пропуск создания виртуального окружения и установки зависимостей |

**Примеры:**

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация (создание my_bot/ в текущем каталоге, с pyproject.toml + .venv)
epsdk init -q -n my_bot

# Инициализация в произвольном каталоге (../apps/mybot)
epsdk init ../apps/mybot

# Комбинация родительского каталога и имени проекта
epsdk init -n my_bot --path ../apps

# Принудительная перезапись конфигурационных файлов
epsdk init -f

# Инициализация в текущем каталоге
epsdk init --here -n my_bot

# Только создание структуры проекта, без виртуального окружения
epsdk init --no-venv -n my_bot
```

Результат инициализации: `main.py`, `pyproject.toml` (список зависимостей), `config/config.toml` + `config.full.example`, `config/ssl/`, `logs/`, `.gitignore`, `README.md`; при выборе создания виртуального окружения дополнительно генерируется `.venv` и в него устанавливаются `erispulse` и выбранные адаптеры.

> [!NOTE]
> `.gitignore` представляет собой шаблон группировки: байтовые коды и результаты сборки Python, виртуальные окружения и `.env`, кэш инструментов, файлы редактора и системы, и **полностью исключает каталоги `config/` и `logs/`** — `config.toml` содержит токены адаптеров и другие чувствительные данные, не рекомендуется добавлять в репозиторий; для совместного использования шаблона конфигурации используйте `config.full.example`.

> [!WARNING]
> **Не используйте `uv run epsdk run` для запуска робота**. `uv run` при выполнении в каталоге без `pyproject.toml` создает **одноразовое изолированное окружение** — в котором пакеты, установленные через `epsdk install`, не сохраняются. Используйте `epsdk run` в каталоге проекта (автоматически использует `.venv`), или активируйте виртуальное окружение перед запуском.

### create

Создание шаблона модуля или адаптера ErisPulse; подкоманда `pack` преобразует локальный плагин (`plugins/` каталог) в публикуемый стандартный проект.

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `{module,adapter,pack}` | | Тип создаваемого объекта: `module` / `adapter` / `pack` (плагин в проект) |
| `--name` | `-n` | Имя проекта (в стиле PascalCase) |
| `--description` | `-d` | Описание проекта |
| `--author` | `-a` | Имя автора |
| `--email` | `-e` | Email автора |
| `--homepage` | | URL-адрес проекта |
| `--output` | `-o` | Каталог вывода (по умолчанию текущий каталог) |
| `--force` | `-f` | Принудительная перезапись существующего каталога |
| `--local` | | Создание локального плагина (`module` / `adapter` доступно): генерация структуры пакета `plugins/<имя>/`, установка без упаковки |

**Примеры:**

```bash
# Интерактивное создание (ввод параметров)
epsdk create

# Прямое создание проекта модуля
epsdk create module -n MyModule

# Создание локального плагина (в каталоге `plugins/`, автоматически обнаруживается при запуске)
epsdk create module -n MyModule --local

# Создание локального адаптера плагина (аналогично, без упаковки для разработки)
epsdk create adapter -n MyAdapter --local

# Прямое создание проекта адаптера
epsdk create adapter -n MyAdapter

# Преобразование локального плагина в публикуемый проект (выбор плагина → заполнение метаданных → генерация стандартного проекта)
epsdk create pack

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Указание каталога вывода
epsdk create module -n MyModule -o ./projects

# Принудительная перезапись существующего каталога
epsdk create module -n MyModule -f
```

## Команды для языковых настроек

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `i18n` | `language`, `lang` | `[язык] [--list/-l]` | Просмотр или смена языка отображения CLI |

### i18n

Просмотр текущего языка CLI, вывод списка поддерживаемых языков, смена языка отображения. Если параметр не указан, запускается интерактивное меню выбора.

**Алиас:** `language`, `lang`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `[язык]` | | Код языка для смены (например, `zh-CN`, `en`, `ja`, `ru`) |
| `--list` | `-l` | Вывод списка всех поддерживаемых языков |

**Примеры:**

```bash
# Интерактивный выбор языка
epsdk i18n

# Смена на английский
epsdk i18n en

# Смена на японский
epsdk i18n ja

# Вывод списка поддерживаемых языков
epsdk i18n --list
```

## Команды для генерации типовых аннотаций

| Команда | Алиас | Параметры | Описание |
|------|------|------|------|
| `types` | `t`, `stub` | `[--output/-o <путь>] [--force] [--adapters-only] [--modules-only]` | Генерация файлов типовых аннотаций для поддержки автодополнения IDE |

### types

Сканирование установленных модулей и адаптеров ErisPulse и генерация файлов `.pyi` типовых аннотаций, чтобы обеспечить точное автодополнение и проверку типов в IDE.

**Алиас:** `t`, `stub`

**Параметры:**

| Параметр | Короткий | Описание |
|------|--------|------|
| `--output` | `-o` | Путь вывода (по умолчанию `ep-stubs/` в текущем каталоге) |
| `--force` | | Принудительная перезапись существующих файлов аннотаций |
| `--adapters-only` | | Генерация только аннотаций для адаптеров |
| `--modules-only` | | Генерация только аннотаций для модулей |

> **Примечание:** `--adapters-only` и `--modules-only` взаимоисключаются, при одновременном указании применяется последний.

**Примеры:**

```bash
# Генерация аннотаций для всех установленных модулей и адаптеров
epsdk types

# Генерация только аннотаций для адаптеров
epsdk types --adapters-only

# Вывод в указанный каталог
epsdk types -o ./typings

# Принудительная перезапись файлов
epsdk types --force
```

## Глобальные параметры

Следующие параметры применимы ко всем командам:

## Диагностика окружения

### doctor

> [!NOTE]
> Эта команда требует ErisPulse **2.7.0+**.

Диагностика текущей среды CLI, вывод отчета о состоянии. Используется для решения проблем "почему не устанавливается / не подключается".

| Параметр | Описание |
|------|------|
| `--verbose` | Показать подробную диагностику |

**Проверяемые элементы:**
- **Python:** версия и путь интерпретатора
- **Инсталлятор:** используется `uv` или `pip`
- **Целевой интерпретатор:** среда Python, куда фактически установлены пакеты
- **Конфигурационный файл:** наличие `config/config.toml`
- **Доступность PyPI:** возможность подключения к PyPI (и отображение количества найденных компонентов)
- **Системный прокси:** обнаружение прокси-сервера

```bash
# Диагностика среды
epsdk doctor

# Использование алиаса
epsdk diag
```

## Интерактивная установка

При запуске `epsdk install` без указания имени пакета запускается интерактивный режим установки:

```bash
epsdk install
```

Интерфейс предоставляет:
1. Выбор адаптера
2. Выбор модуля
3. Настраиваемую установку

## Общие примеры использования

### Установка модуля

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Обновление модуля
epsdk install Weather -U
```

### Вывод списка компонентов

```bash
# Вывод всех компонентов
epsdk list

# Вывод только адаптеров
epsdk list -t adapters

# Вывод только обновляемых компонентов
epsdk list -o

# Просмотр удалённых доступных компонентов
epsdk list-remote
```

### Удаление компонентов

```bash
# Удаление одного компонента
epsdk uninstall Weather

# Удаление нескольких компонентов
epsdk uninstall Yunhu Weather
```

### Настройка компонентов

```bash
# Просмотр состояния конфигурации
epsdk config --list

# Интерактивный выбор цели для настройки
epsdk config

# Настройка указанного адаптера
epsdk config yunhu
```

### Обновление компонентов

```bash
# Обновление всех компонентов
epsdk upgrade

# Обновление указанного компонента
epsdk upgrade Weather

# Принудительное обновление
epsdk upgrade -f
```

### Запуск проекта

```bash
# Обычный запуск
epsdk run main.py

# Запуск в режиме горячей перезагрузки
epsdk run main.py --reload
```

### Смена языка

```bash
# Интерактивный выбор языка
epsdk i18n

# Прямая смена на английский
epsdk i18n en

# Вывод списка поддерживаемых языков
epsdk i18n --list
```

### Генерация типовых аннотаций

```bash
# Генерация всех типовых аннотаций
epsdk types

# Генерация только модульных аннотаций
epsdk types --modules-only
```

### Инициализация проекта

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация
epsdk init -q -n my_bot
```

### Создание шаблона

```bash
# Интерактивное создание (ввод параметров)
epsdk create

# Прямое создание проекта модуля
epsdk create module -n MyModule

# Прямое создание проекта адаптера
epsdk create adapter -n MyAdapter

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Принудительная перезапись существующего каталога
epsdk create module -n MyModule -f
```
