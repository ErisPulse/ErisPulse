# Справочник команд CLI

> [!TIP]
> **Когда нужно читать это**: когда вы забыли параметры команды `epsdk`, хотите добавить управление компонентами в скрипт или хотите управлять поведением `run` / `stop` / `restart`. Для повседневного использования `init` / `install` / `run` достаточно помнить одну команду: `epsdk <команда> --help` — всегда можно посмотреть описание параметров, не читая всю статью.

`epsdk` — это инструмент командной строки ErisPulse: инициализация проекта, установка / обновление модулей и адаптеров, интерактивная настройка компонентов, запуск и остановка роботов, диагностика среды — все это делается одной командой.

> **Подсказка**: основная помощь `epsdk` (без команды) группируется по категориям: **Проект** (`init` / `create` / `run`), **Управление компонентами** (`install` / `uninstall` / `upgrade` / `list` / `list-remote` / `types`), **Конфигурация и диагностика** (`config` / `doctor` / `i18n`), **Другое** (`self-update` / `version`).

### install

Установка пакета модуля или адаптера ErisPulse. Если не указано имя пакета, переходит в интерактивный режим установки.

**Алиас:** `i`, `add`

> **Связь с проектом uv** (2.11.1+): в проекте, управляемом uv (существует `uv.lock` или `[tool.uv]`), `install` / `upgrade` / `uninstall` автоматически переходят на `uv add` / `uv remove` — зависимости синхронизируются в `pyproject.toml` и `uv.lock`, `uv sync` больше не удаляет компоненты, установленные через `epsdk`; в случае сбоя автоматически возвращается к uv pip / pip. Параметры, не поддерживаемые uv, такие как `--user`, работают через pip. Порядок разрешения целевой среды: `ERISPULSE_PYTHON` → `UV_PROJECT_ENVIRONMENT` → `.venv` проекта → `UV_PYTHON` → `VIRTUAL_ENV` → текущий интерпретатор (команда `epsdk doctor` может показать полную цепочку принятия решений).

**Параметры:**

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `[package]...` | | Имя пакета, который нужно установить, можно указать несколько |
| `--upgrade` | `-U` | При установке обновить до последней версии |
| `--pre` | | Разрешить установку предварительных версий |
| `--editable` | `-e` | Установить в режиме редактирования (требуется указать путь) |
| `--user` | | Установить в каталог site-packages пользователя |
| `--no-deps` | | Не устанавливать зависимости |
| `--target` | `-t` | Установить в указанную директорию |
| `--index-url` | | Указать URL зеркала PyPI |
| `--extra-index-url` | | Дополнительный URL зеркала PyPI (можно указывать несколько раз) |
| `--no-cache-dir` | | Отключить кэш |
| `--requirement` | `-r` | Установка из файла requirements |
| `--constraint` | `-c` | Установка из файла ограничений |
| `--force-reinstall` | | Принудительная переустановка |
| `--ignore-installed` | | Игнорировать уже установленные пакеты |
| `--compile` | | Компилировать файлы .pyc после установки |
| `--no-compile` | | Не компилировать файлы .pyc после установки |
| `--prefix` | | Установить в указанную префиксную директорию |
| `--src` | | Используемая директория исходного кода при установке в режиме редактирования |
| `--config-settings` | | Передать настройки конфигурации сборочному бэкенду (можно указывать несколько раз) |
| `--no-binary` | | Ограничить использование бинарных пакетов (формат как `:all:`) |
| `--only-binary` | | Ограничить использование только бинарных пакетов (формат как `:all:`) |
| `--prefer-binary` | | Предпочитать бинарные пакеты |
| `--build-isolation` | | Включить изоляцию сборки |
| `--no-build-isolation` | | Отключить изоляцию сборки |
| `--upgrade-strategy` | | Стратегия обновления: `eager`, `only-if-needed`, `to-satisfy-only` |
| `--break-system-packages` | | Разрешить изменение системных пакетов, управляемых пакетным менеджером |
| `--no-uv` | | Использовать pip вместо uv |

**Примеры:**

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Установка из зеркала и обновление
epsdk install Weather -U --index-url https://pypi.tuna.tsinghua.edu.cn/simple

# Установка в режиме редактирования (для разработки)
epsdk install -e ./my-adapter
```

### uninstall

**Алиас:** `rm`, `remove`

**Параметры:**

| Параметр | Описание |
|----------|----------|
| `<package>...` | Имя пакета, который нужно удалить, можно указать несколько |
| `--no-uv` | Использовать pip вместо uv |

**Примеры:**


### upgrade

Обновление установленных компонентов ErisPulse. Если не указано имя пакета, переходит в интерактивный режим обновления всего.

**Алиас:** `up`

**Параметры:**

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `[package]...` | | Имя пакета, который нужно обновить, можно указать несколько |
| `--force` | `-f` | Принудительное обновление, без подтверждения |
| `--pre` | | Разрешить обновление до предварительных версий |
| `--no-uv` | | Использовать pip вместо uv |

**Примеры:**

```bash
# Обновление всех пакетов
epsdk upgrade

# Обновление указанного пакета
epsdk upgrade Weather

# Принудительное обновление (без подтверждения)
epsdk upgrade -f
```

### self-update

Обновление самого ErisPulse SDK до последней версии.

**Алиас:** `su`, `update`

**Параметры:**

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `[version]` | | Указать номер целевой версии |
| `--pre` | | Разрешить обновление до предварительных версий |
| `--force` | `-f` | Принудительное обновление, без подтверждения |
| `--no-uv` | | Использовать pip вместо uv |

**Примеры:**

```bash
# Обновление до последней стабильной версии
epsdk self-update

# Обновление до указанной версии
epsdk self-update 1.2.3

# Разрешить предварительные версии
epsdk self-update --pre

# Принудительное обновление
epsdk self-update -f
```

> [!NOTE]
> При установке через `uv tool install ErisPulse` команда автоматически переходит на `uv tool upgrade ErisPulse` (при указании версии — `uv tool install ErisPulse==<версия> --force`), прямое обновление pip инструмента будет отменено списком uv. На Windows обновление происходит в новом окне консоли: текущий CLI должен быть завершен, чтобы освободить файлы среды инструмента, после завершения обновления перезапустите терминал.

## Команды конфигурации

| Команда | Алиас | Параметры | Описание |
|---------|-------|-----------|----------|
| `config` | `cfg`, `conf` | `[name] [--list/-l] [--json]` | Интерактивная конфигурация адаптера/модуля |

### config

Интерактивное заполнение конфигурационных параметров адаптера/модуля. Визуальный интерфейс генерируется на основе класса конфигурации (ConfigClass / AccountConfigClass), автоматически генерируя формы и проверяя ввод, без необходимости ручного редактирования config.toml.

Адаптеры дополнительно поддерживают управление несколькими учетными записями (бот-аккаунтами): добавление/редактирование/удаление учетных записей, а также включение/отключение.

**Алиас:** `cfg`, `conf`

**Параметры:**

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `[name]` | | Имя цели (название платформы адаптера или модуля), оставить пустым для интерактивного выбора |
| `--list` | `-l` | Вывести только состояние конфигурации всех целей, не вводя в интерфейс |
| `--json` | | Вывести в формате JSON все цели и их состояние конфигурации (для CI / скриптов), не вводя в интерфейс |

**Примеры:**

```bash
# Показать состояние конфигурации всех адаптеров/модулей
epsdk config --list

# Вывести состояние конфигурации в формате JSON (для CI / скриптов)
epsdk config --json

# Интерактивный выбор цели для конфигурации
epsdk config

# Непосредственная конфигурация указанного адаптера
epsdk config yunhu

# Непосредственная конфигурация указанного модуля
epsdk config MyModule
```

**Описание:**

- Состояние конфигурации делится на четыре категории: `Готово` (валидация пройдена), `Незавершено` (отсутствуют обязательные поля или ошибка валидации), `Не настроено` (никогда не создавалось), `Без конфигурации` (цель не декларирует класс конфигурации)
- Значения полей снабжены метками источника: уже настроенные отображаются как `（当前:值）`, не настроенные отображаются как `（默认:值）`; нажатие Enter сохраняет текущее значение
- Ввод секретных полей (объявленных как `secret`) не отображается, нажатие Enter сохраняет установленное значение
- В интерактивном режиме после завершения одного интерфейса возвращается в меню выбора (состояние обновлено), можно настроить несколько целей, нажатие Enter завершает
- При неудачной валидации формы и отказе от повторного ввода текущий интерфейс завершается, и никакие изменения не записываются (избегается создание "включенного, но незавершенного" состояния)
- После сохранения конфигурация сразу записывается в `config/config.toml`, видна в Dashboard и запущенном SDK; для применения новых учетных записей в запущенном адаптере перезапустите процесс
- После успешной установки адаптера через `epsdk install` / `epsdk init`, если обнаружен класс конфигурации, автоматически запускается интерфейс конфигурации; при установке через командную строку без интерактивного выбора выводится только подсказка о конфигурации

## Команды управления запуском

> [!TIP]
> `epsdk run` автоматически обнаружит и использует виртуальное окружение `.venv` в каталоге проекта (также можно явно указать интерпретатор через переменную окружения `ERISPULSE_PYTHON`). Команды `epsdk install` / `uninstall` / `upgrade` / `list` также действуют на виртуальное окружение проекта.

| Команда | Алиас | Параметры | Описание |
|---------|-------|-----------|----------|
| `run` | `r` | `[script] [--reload] [--strict/--no-strict]` | Запуск указанного скрипта или SDK |
| `stop` | — | `[--force] [--pid PID]` | Остановка запущенного экземпляра (запущенного через `epsdk run`) |
| `restart` | — | `[--force] [--pid PID]` | Перезапуск запущенного экземпляра (остановка, затем перезапуск с теми же параметрами) |

### run

Запуск проекта ErisPulse или SDK. Поддерживает режим горячей перезагрузки.

**Алиас:** `r`

**Параметры:**

| Параметр | Описание |
|----------|----------|
| `[script]` | Запускаемый скрипт, если не указан, запускается SDK |
| `--reload` | Включить режим горячей перезагрузки: отслеживание изменений файлов и автоматическая перезагрузка компонентов (без перезапуска всего процесса); по умолчанию игнорирует директории `.venv`/`.git` (можно настроить через `ErisPulse.framework.watch_ignore_dirs`), директории плагинов обрабатываются точными плагин-наблюдателями |
| `--strict` / `--no-strict` | Временно включить / отключить строгий режим (только для текущего запуска, не записывается в конфигурацию); по умолчанию следует `ErisPulse.framework.strict_mode` (если не 0, проверка не пройдена — завершение, если 0 — только предупреждение) |

**Примеры:**

```bash
# Простой запуск SDK
epsdk run

# Запуск указанного скрипта
epsdk run main.py

# Горячая перезагрузка (изменения файлов автоматически перезапускают код)
epsdk run main.py --reload

# Горячая перезагрузка для SDK
epsdk run --reload

# Временный строгий режим: предварительная проверка завершается с ошибкой, строгость фреймворка повышается как минимум до 1
epsdk run main.py --strict

# Временный нестрогий режим (в конфиге включен strict_mode, но хочется запустить без проверок)
epsdk run main.py --no-strict
```

**Предварительная проверка:** `run` выполняет быструю проверку парсинга `config/config.toml` и обязательных конфигураций установленных компонентов, строгость по умолчанию следует `ErisPulse.framework.strict_mode` (если не 0, проверка не пройдена — завершение, если 0 — только предупреждение). Отсутствие конфигурационного файла считается нормальным для первого запуска, только предупреждение, не ошибка. `--strict` временно включает: предварительная проверка завершается с ошибкой, а уровень строгости фреймворка повышается как минимум до 1 (пропуск несоответствующих компонентов, через `ERISPULSE_FRAMEWORK_STRICT_MODE` передается в запущенный процесс, не записывается в конфигурационный файл); `--no-strict` временно понижает до нестрогого. Ошибки самой проверки автоматически пропускаются, не включает проверку сети, не блокирует запуск.

> **Структура наблюдения `--reload`** (начиная с 2.11.1): `epsdk run --reload` запускается как "надзирательный процесс + перезагрузочный подпроцесс". Горячая перезагрузка, вызванная сохранением `.py` файлов, выполняется внутри подпроцесса (исключительный, последовательный, объединение штормов); синтаксические ошибки на стороне модуля отклоняются предварительной проверкой, старый экземпляр продолжает обслуживание. При `sdk.hard_restart()` подпроцесс завершается с кодом 42, надзирательный процесс отображает причину и автоматически запускает новый подпроцесс — обновление фреймворка происходит немедленно.

### stop

Остановка запущенного экземпляра ErisPulse (запущенного через `epsdk run` и запущенного в том же каталоге проекта). При запуске `run` PID надзирательного процесса, PID фреймворка и исходная команда записываются в `.erispulse/runtime.json`, `stop` использует это для определения экземпляра.

**Порядок остановки:** в POSIX сначала отправляется сигнал SIGINT надзирательному процессу (тот же путь для элегантного завершения, как при Ctrl+C — цепочка finally автоматически останавливает фреймворк-подпроцесс), при таймауте постепенно повышается до SIGTERM / SIGKILL; в Windows нет семантики сигналов процесса, сначала останавливается фреймворк-подпроцесс, затем надзирательный процесс (чтобы избежать ошибочного перезапуска из-за сильного убийства).

**Параметры:**

| Параметр | Описание |
|----------|----------|
| `--force` | Принудительно остановить без элегантной остановки |
| `--pid PID` | Указать PID цели (переопределяет файл состояния, для нестандартных способов запуска) |

**Примеры:**

```bash
# Остановка текущего проекта
epsdk stop

# Принудительная остановка
epsdk stop --force
```

### restart

Перезапуск запущенного экземпляра ErisPulse: остановка по семантике `stop`, затем перезапуск с исходной командой из файла состояния (перехватывает терминал, новый экземпляр записывает новый файл состояния).

**Параметры:** такие же, как у `stop` (`--force` / `--pid PID`).

**Примеры:**

```bash
# Элегантный перезапуск (после обновления адаптера/модуля через pip, чтобы код применился; модули в процессе можно обновить через `sdk.reload_module` / `sdk.adapter.reload` кодом, без перезапуска)
epsdk restart
```

> [!NOTE]
> Процессы, запущенные через `python main.py` и другие способы, не использующие `epsdk run`, не записывают файл состояния — такие процессы нужно управлять системными инструментами или использовать `epsdk stop --pid <PID>` с указанием PID.

| Команда | Алиас | Параметры | Описание |
|---------|-------|-----------|----------|
| `init` | — | `[path] [--project-name/-n <name>] [--path <dir>] [--adapter/-a <name>] [--quick/-q] [--force/-f] [--here] [--no-uv] [--no-venv]` | Инициализация проекта ErisPulse |
| `create` | — | `{module,adapter,pack} [--name/-n <name>] [--description/-d <desc>] [--author/-a <name>] [--email/-e <mail>] [--homepage <url>] [--output/-o <dir>] [--force/-f] [--local]` | Создание шаблона модуля/адаптера; `pack` преобразует локальный плагин в проект для публикации |

### init

Инициализация нового проекта ErisPulse. Поддерживает интерактивный и быстрый режим, начиная с 2.8.4 создает `pyproject.toml` (список зависимостей), опционально создает виртуальное окружение `.venv` и устанавливает фреймворк и адаптеры, поддерживает **указание произвольного каталога**.

**Параметры:**

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `[path]` | | Целевой путь (может включать родительские каталоги, например `../apps/mybot`; чистое имя эквивалентно `--project-name`) |
| `--project-name` | `-n` | Имя проекта |
| `--path` | | Родительский каталог проекта (в сочетании с `-n` указывает место создания) |
| `--adapter` | `-a` | Предварительно выбранный адаптер (можно передавать несколько раз или через запятую), при передаче пропускает опрос и выбор адаптера |
| `--quick` | `-q` | Быстрый режим, пропускает интерактивное руководство (по умолчанию создает `.venv` и устанавливает зависимости) |
| `--force` | `-f` | Принудительно перезаписать существующие конфигурационные файлы |
| `--here` | | Инициализация в текущем каталоге, не создавая подкаталог |
| `--no-uv` | | Использовать pip вместо uv |
| `--no-venv` | | Пропустить создание виртуального окружения и установку зависимостей |

**Примеры:**

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация (создает my_bot/ в текущем каталоге с pyproject.toml + .venv)
epsdk init -q -n my_bot

# Быстрая инициализация с предустановленными адаптерами (без интерактива, для скриптов / CI)
epsdk init -q -n my_bot --adapter yunhu,telegram

# Инициализация в произвольном каталоге (../apps/mybot)
epsdk init ../apps/mybot

# Комбинация родительского каталога и имени проекта
epsdk init -n my_bot --path ../apps

# Принудительная перезапись конфигурации
epsdk init -f

# Инициализация в текущем каталоге
epsdk init --here -n my_bot

# Создание только структуры проекта, без виртуального окружения
epsdk init --no-venv -n my_bot
```

Результаты `init`: `main.py`, `pyproject.toml` (список зависимостей), `config/config.toml` + `config.full.example`, `config/ssl/`, `logs/`, `.gitignore`, `README.md`; при выборе создания виртуального окружения дополнительно генерируются `.venv` и устанавливаются `erispulse` и выбранные адаптеры.

> [!NOTE]
> `.gitignore` — это шаблон с группировкой: байтовые файлы и результаты сборки Python, виртуальные окружения и `.env`, кэш инструментов, файлы редактора и системы, и **полностью исключает каталоги `config/` и `logs/`**, поскольку `config.toml` содержит токены адаптеров и другие чувствительные данные, не рекомендуется добавлять в репозиторий; для совместного использования шаблона конфигурации используйте `config.full.example`.

> [!WARNING]
> **Не используйте `uv run epsdk run` для запуска робота**. `uv run` при выполнении в каталоге без `pyproject.toml` создает **одноразовое изолированное окружение** — в котором адаптеры, установленные через `epsdk install`, не будут сохраняться. Используйте `epsdk run` в каталоге проекта (автоматически использует `.venv`), или сначала активируйте виртуальное окружение, а затем запустите.

### create

Создание шаблона для модуля или адаптера ErisPulse; подкоманда `pack` преобразует локальный плагин (`plugins/` каталог) в стандартный проект для публикации.

**Параметры:**

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `{module,adapter,pack}` | | Тип создаваемого проекта: `module` / `adapter` / `pack` (преобразование плагина в проект) |
| `--name` | `-n` | Имя проекта (в стиле PascalCase) |
| `--description` | `-d` | Описание проекта |
| `--author` | `-a` | Имя автора |
| `--email` | `-e` | Email автора |
| `--homepage` | | URL домашней страницы проекта |
| `--output` | `-o` | Каталог вывода (по умолчанию текущий каталог) |
| `--force` | `-f` | Принудительно перезаписать существующий каталог |
| `--local` | | Создать локальный плагин (доступно для `module` / `adapter`): генерирует структуру `plugins/<name>/`, без упаковки и установки |

**Примеры:**

```bash
# Интерактивное создание (выводит выбор типа и заполнение информации)
epsdk create

# Прямое создание проекта модуля
epsdk create module -n MyModule

# Создание локального плагина (в каталог `plugins/`, автоматически обнаруживается при запуске)
epsdk create module -n MyModule --local

# Создание локального плагина адаптера (аналогично, без упаковки для разработки)
epsdk create adapter -n MyAdapter --local

# Прямое создание проекта адаптера
epsdk create adapter -n MyAdapter

# Преобразование локального плагина в публикуемый проект (интерактивный выбор плагина → заполнение метаинформации → генерация стандартного проекта)
epsdk create pack

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Указать каталог вывода
epsdk create module -n MyModule -o ./projects

# Принудительная перезапись существующего каталога
epsdk create module -n MyModule -f
```

### types

Сканирование установленных модулей и адаптеров ErisPulse, генерация `.pyi` файлов аннотаций типов, чтобы в IDE получить точное автодополнение и проверку типов.

## Диагностика среды

### doctor

> [!NOTE]
> Эта команда требует ErisPulse **2.7.0+**.

Диагностика текущей среды CLI, вывод отчета о состоянии. Используется для устранения проблем типа "почему не устанавливается / не подключается".

| Параметр | Описание |
|----------|----------|
| `--verbose` | Показать подробную диагностику |
| `--fix` | После диагностики попытаться автоматически исправить исправимые проблемы |

**Проверяемые пункты**:
- **Python**: версия и путь интерпретатора
- **Установочный бэкенд**: используется `uv` или `pip`
- **Целевой интерпретатор**: среда, в которую фактически установлены пакеты
- **Конфигурационный файл**: существует ли `config/config.toml`
- **Конфигурация компонентов**: полнота обязательных настроек установленных компонентов ("установлен, но не запускается" часто из-за отсутствующих обязательных полей)
- **Загрязнение конфигурации** (2.11.1+): сканирование остатков от предыдущих обновлений (тени состояния, привязанные к старой версии, отдельные конфигурационные секции), обнаруженные ключи предупреждаются
- **Доступность PyPI**: можно ли получить доступ к PyPI (и сколько найдено компонентов)
- **Системный прокси**: обнаружен ли прокси

**Автоматическое исправление (`--fix`)**:
- Отсутствует `config.toml` → создать начальный конфигурационный файл (такой же, как при `init`)
- Конфигурация компонентов "незавершена" → поочередно запускать интерактивный конфигурационный интерфейс для заполнения обязательных полей (в неинтерактивной среде предупреждение о необходимости использовать `epsdk config <имя>`)
- Загрязнение конфигурации → перечислить источники и удалить по подтверждению (без потерь данных в tomlclass, сохраняются комментарии и порядок)
- Проблемы с версией Python, недоступностью PyPI и т.д. — только рекомендации по действиям

```bash
# Диагностика среды
epsdk doctor

# Алиас
epsdk diag

# Диагностика и попытка автоматического исправления
epsdk doctor --fix
```

## Интерактивная установка

Запуск `epsdk install` без указания имени пакета ведет к интерактивной установке:

```bash
epsdk install
```

Интерфейс предоставляет:
1. Выбор адаптера
2. Выбор модуля
3. Настройка установки

## Распространенные способы использования

### Установка модуля

```bash
# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Обновление модуля
epsdk install Weather -U
```

### Вывод списка компонентов

```bash
# Вывести все компоненты
epsdk list

# Вывести только адаптеры
epsdk list -t adapters

# Вывести только обновляемые компоненты
epsdk list -o

# Посмотреть доступные удаленные компоненты
epsdk list-remote
```

### Удаление компонентов

```bash
# Удалить один компонент
epsdk uninstall Weather

# Удалить несколько компонентов
epsdk uninstall Yunhu Weather
```

### Настройка компонентов

```bash
# Показать состояние конфигурации
epsdk config --list

# Интерактивный выбор для настройки
epsdk config

# Настройка указанного адаптера
epsdk config yunhu
```

### Обновление компонентов

```bash
# Обновить все компоненты
epsdk upgrade

# Обновить указанный компонент
epsdk upgrade Weather

# Принудительное обновление
epsdk upgrade -f
```

### Запуск проекта

```bash
# Обычный запуск
epsdk run main.py

# Запуск с горячей перезагрузкой
epsdk run main.py --reload
```

### Смена языка

```bash
# Интерактивный выбор языка
epsdk i18n

# Прямая смена на английский
epsdk i18n en

# Вывести список поддерживаемых языков
epsdk i18n --list
```

### Генерация аннотаций типов

```bash
# Генерация всех аннотаций типов
epsdk types

# Генерация только аннотаций модулей
epsdk types --modules-only
```

### Инициализация проекта

```bash
# Интерактивная инициализация
epsdk init

# Быстрая инициализация
epsdk init -q -n my_bot
```
