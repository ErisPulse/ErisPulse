# Описание файла конфигурации
> В этом документе будет рассказано о файлах конфигурации фреймворка. Если сторонний модуль требует настройки, обратитесь к документации модуля.

ErisPulse использует файл конфигурации в формате TOML `config/config.toml` для управления конфигурацией проекта.

## Расположение файла конфигурации

Файл конфигурации находится в папке `config/` в корне проекта:

```
project/
├── config/
│   └── config.toml
├── main.py
```

## Обработка ошибок при загрузке конфигурации

Фреймворк при загрузке `config.toml` различает три состояния ошибок и предоставляет **действенные диагностические сообщения**, а не просто переключается на значения по умолчанию:

| Состояние ошибки | Условия возникновения | Поведение фреймворка |
|---------|---------|---------|
| Файл отсутствует | `config.toml` не существует | При первом запуске используется пустая конфигурация (без предупреждений) |
| Ошибка синтаксиса TOML | Файл существует, но формат неправильный (например, отсутствуют кавычки, незакрытые скобки) | Выводится **номер строки/столбца и причина ошибки**, и сообщается, что переключено на значения по умолчанию |
| Ошибка доступа/другие ошибки | Нет прав на чтение, ошибки ввода-вывода и т.д. | Выводится **ясная причина**, и сообщается, что переключено на значения по умолчанию |

Например, если вы случайно написали `port = 8000` (пропущены кавычки для строки), в логе появится что-то вроде:

```
[ERROR] [Config] Синтаксическая ошибка в файле конфигурации config/config.toml (строка 3, столбец 1): ...
[WARNING] [Config] Переключено на значения по умолчанию, ваши настройки не применились — исправьте и перезапустите
```

Таким образом, вы сможете сразу найти проблему на уровне `INFO`, а не задаваться вопросом "почему мои изменения не применились".

> **Изменение конфигурационного файла во время работы?** Если вы вручную отредактируете `config.toml` во время работы робота и внесёте синтаксическую ошибку, фреймворк при следующей попытке записи (объединения конфигурации) выведет сообщение «Конфигурационный файл повреждён (ошибка синтаксиса, строка X), невозможно объединить и записать — исправьте файл конфигурации и перезапустите», а не запутанное «Не удалось записать». Изменённые параметры будут сохранены, не будут потеряны.

## Перекрытие с помощью переменных окружения

Фреймворк поддерживает **перекрытие** параметров `ErisPulse.*` с помощью переменных окружения (подходит для Docker / контейнеризации / CI-развертывания, без необходимости изменять `config.toml`).

Правила именования: путь с точкой `ErisPulse.<section>.<key>` преобразуется в верхний регистр, `.` заменяется на `_`, и добавляется префикс `ERISPULSE_`:

| Параметр | Переменная окружения | Пример значения |
|--------|---------|--------|
| `ErisPulse.server.port` | `ERISPULSE_SERVER_PORT` | `9000` |
| `ErisPulse.server.host` | `ERISPULSE_SERVER_HOST` | `0.0.0.0` |
| `ErisPulse.logger.level` | `ERISPULSE_LOGGER_LEVEL` | `DEBUG` |
| `ErisPulse.framework.strict_mode` | `ERISPULSE_FRAMEWORK_STRICT_MODE` | `false` |

Описание поведения:
- **Наивысший приоритет**: переменные окружения перекрывают «файл конфигурации» и «значения по умолчанию», типы автоматически преобразуются (`bool` / `int` / `float` / список, разделённый запятыми / строка)
- **Непостоянное хранение**: перекрытие действует только во время выполнения, не записывается обратно в `config.toml`
- **Поддержка горячей перезагрузки**: изменение переменных окружения во время работы с перезагрузкой конфигурации по слушателю вступает в силу

```bash
# Пример развертывания в Docker: без изменения config.toml, просто перекрытие порта
ERISPULSE_SERVER_PORT=9000 docker compose up -d
```

> Примечание: параметры фреймворка, такие как `ErisPulse.server.port`, читаются через API `get_server_config()` и подвержены влиянию переменных окружения.

## Горячая перезагрузка конфигурации

Начиная с версии 2.7.0, фреймворк предоставляет **системную поддержку горячей перезагрузки конфигурации**. После внешнего изменения `config.toml` (фоновый watcher проверяет каждые 5 секунд) или вызова кодом `setConfig()` все компоненты автоматически реагируют:

| Компонент | Поддерживаемые параметры для горячей перезагрузки | Поведение |
|------|----------------|------|
| **Логгер Logger** | `logger.level` / `log_files` / `memory_limit` / `format` | Автоматически перезаписывает (с обнаружением изменений) |
| **Система команд CommandHandler** | `event.command.prefix` / `case_sensitive` / `allow_space_prefix` / `must_at_bot` | Действует с первой следующей командой |
| **Адаптеры и параллелизм** | `framework.handler_max_concurrency` | Сигналы о невалидности кэша, пересоздание по новым значениям |
| **Активный сборщик мусора** | `framework.proactive_gc_interval` | Каждый цикл перечитывает, поддерживает изменение/отключение во время выполнения |
| **Конфигурация модулей/адаптеров** | Собственные параметры | Вызывает обратный вызов `on_config_update(old, new)` |

**Параметры, требующие перезапуска** (небезопасно переключать во время выполнения, при изменении выводится предупреждение «Требуется перезапуск процесса для применения»):

| Параметр | Причина |
|------|------|
| `router.cors.*` / `router.security.*` | Промежуточные слои записываются в FastAPI при запуске службы, небезопасно переключать во время выполнения |
| `storage.use_global_db` | SQLite-дескриптор уже открыт во время выполнения, безопасно переключить путь нельзя |

> **Ошибка при редактировании и сохранении?** Если при редактировании `config.toml` возникает кратковременная синтаксическая ошибка, фреймворк **сохраняет последнюю корректную конфигурацию** и выводит диагностическое сообщение, не распространяя пустую конфигурацию среди компонентов (чтобы `on_config_update` не получал пустые значения и не возвращался к значениям по умолчанию).

## Полный пример конфигурации

```toml
[ErisPulse.server]
host = "0.0.0.0"
port = 8000
ssl_certfile = ""
ssl_keyfile = ""

[ErisPulse.logger]
level = "INFO"
format = "rich"
log_files = []
memory_limit = 1000

[ErisPulse.framework]
enable_lazy_loading = true
uninit_timeout = 30
strict_mode = 0

[ErisPulse.framework.strict_mode_exceptions]
modules = []
adapters = []

[ErisPulse.storage]
use_global_db = false

[ErisPulse.event.command]
prefix = "/"
case_sensitive = true
allow_space_prefix = false
must_at_bot = false

[ErisPulse.event.message]
ignore_self = true

[ErisPulse.i18n]
language = "auto"
```

## Конфигурация сервера

```toml
[ErisPulse.server]
host = "0.0.0.0"
port = 8000
ssl_certfile = "/path/to/cert.pem"
ssl_keyfile = "/path/to/key.pem"
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| host | string | 0.0.0.0 | Адрес прослушивания, 0.0.0.0 означает все интерфейсы |
| port | integer | 8000 | Порт прослушивания |
| ssl_certfile | string | пусто | Путь к файлу SSL-сертификата |
| ssl_keyfile | string | пусто | Путь к файлу SSL-приватного ключа |

## Конфигурация логирования

```toml
[ErisPulse.logger]
level = "INFO"
log_files = ["app.log", "debug.log"]
memory_limit = 1000
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| level | string | INFO | Уровень логирования: TRACE, DEBUG, INFO, WARNING, ERROR, CRITICAL (TRACE — самый низкий уровень, выводит подробную отладочную информацию фреймворка) |
| format | string | rich | Формат вывода логов, по умолчанию используется rich для цветного вывода |
| log_files | массив | пустой | Список файлов для вывода логов |
| memory_limit | integer | 1000 | Количество записей логов, хранящихся в памяти |

## Конфигурация фреймворка

```toml
[ErisPulse.framework]
enable_lazy_loading = true
uninit_timeout = 30
strict_mode = 0

[ErisPulse.framework.strict_mode_exceptions]
modules = []
adapters = []
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| enable_lazy_loading | boolean | true | Включить ли ленивую загрузку модулей |
| uninit_timeout | integer | 30 | Общее время ожидания при корректном завершении (секунды), после чего принудительно завершается. 0 означает отсутствие таймаута |
| strict_mode | integer | 0 | Уровень строгого режима, см. раздел «Строгий режим» ниже |

### Строгий режим

Строгий режим управляет стратегией обработки компонентов, которые нарушают правила или не загружаются на этапе загрузки. Современные модули/адаптеры должны наследовать соответствующие базовые классы (`BaseModule`/`BaseAdapter`), компоненты, не наследующие базовые классы, влияют на контекстную систему фреймворка и очистку по умолчанию, что может привести к утечке ресурсов.

> **Изменение в 2.5.2**: уровень по умолчанию изменён с `1` (пропуск) на `0` (снисходительный), чтобы уменьшить количество проблем при первом использовании новыми пользователями. Компоненты, не наследующие базовые классы, будут предупреждаться и попытаться загрузиться, а не отклоняться напрямую. Чтобы восстановить старое поведение, явно установите `strict_mode = 1`.

| Уровень | Название | Поведение |
|------|------|------|
| 0 | Снисходительный (по умолчанию) | Нарушения только предупреждаются, компоненты, не наследующие базовые классы, всё ещё будут попытаться загрузиться (для совместимости со старыми компонентами) |
| 1 | Строгий-пропуск | Отклоняются компоненты, не наследующие базовые классы, и пропускаются, остальное запускается нормально |
| 2 | Строгий-фатальный | Все нарушения (не наследование базовых классов, сбой загрузки, сбой регистрации, сбой инициализации и т.д.) превращаются в фатальные, при проверке запуска собираются и выводятся списки нарушений, затем запуск прерывается |

На всех уровнях ошибки, возникающие на этапах загрузки/регистрации/инициализации, будут пропущены. Разница заключается в следующем:

- **0 → 1**: единственное изменение поведения — компоненты, не наследующие базовые классы, сначала будут загружаться, а затем пропускаться.
- **1 → 2**: все нарушения (не наследование базовых классов, сбой загрузки, сбой регистрации, сбой инициализации и т.д.) повышаются до фатальных, при точке проверки запуска собираются и выводятся списки нарушений, затем запуск прерывается.

#### Список исключений

Если некоторые компоненты временно не могут быть обновлены (например, из-за зависимых старых модулей), вы можете добавить их в список исключений, и компоненты, перечисленные в этом списке, будут обрабатываться как в снисходительном режиме, продолжая загрузку, даже если они нарушают правила:

```toml
[ErisPulse.framework.strict_mode_exceptions]
modules = ["SeTu", "SomeLegacyModule"]
adapters = ["OldAdapter"]
```

> Когда компонент отклоняется строгим режимом, в логе будет чётко указано, как восстановить загрузку (добавить в список исключений или понизить уровень).

## Конфигурация хранения

```toml
[ErisPulse.storage]
use_global_db = false
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| use_global_db | boolean | false | Использовать ли глобальную базу данных (внутри пакета) вместо проектной базы данных. При `true` все проекты используют общую базу данных SQLite внутри пакета ErisPulse; `false` (по умолчанию) означает, что каждый проект использует независимую базу данных в папке `config/` |

## Конфигурация событий

### Конфигурация команд

```toml
[ErisPulse.event.command]
prefix = "/"
case_sensitive = false
allow_space_prefix = false
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| prefix | string | / | Префикс команды |
| case_sensitive | boolean | true | Регистр чувствителен (различаются ли `/Help` и `/help` как разные команды) |
| allow_space_prefix | boolean | false | Разрешён ли пробел в качестве префикса |
| must_at_bot | boolean | false | Должна ли команда вызываться только с упоминанием бота (в личных сообщениях ограничения не действуют) |

### Конфигурация сообщений

```toml
[ErisPulse.event.message]
ignore_self = true
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| ignore_self | boolean | true | Игнорировать ли собственные сообщения бота |

## Конфигурация международизации

```toml
[ErisPulse.i18n]
language = "auto"
```

| Параметр | Тип | Значение по умолчанию | Описание |
|---------|------|---------|------|
| language | string | auto | Язык отображения встроенных текстов фреймворка. Установите `auto` для автоматического определения языка системы, можно также установить конкретный код: `zh-CN`, `zh-TW`, `en`, `ja`, `ru` |

## Конфигурация модулей

Каждый модуль может определить свою собственную конфигурацию в файле конфигурации:

```toml
[MyModule]
api_url = "https://api.example.com"
timeout = 30
enabled = true
```

Чтение и запись конфигурации в модуле:

```python
from ErisPulse import sdk

# Чтение конфигурации
config = sdk.config.getConfig("MyModule", {})
api_url = config.get("api_url", "https://default.api.com")

# Запись конфигурации во время выполнения (отложенная запись)
sdk.config.setConfig("MyModule.timeout", 60)

# Немедленная запись в файл
sdk.config.setConfig("MyModule.timeout", 60, immediate=True)
```

> `setConfig` по умолчанию использует отложенную запись (примерно каждые 5 секунд пакетно сохраняется в файл), установка `immediate=True` немедленно сохраняет. Изменения конфигурации запускают событие жизненного цикла `config.set`.
