# Создание первого бота

В этом руководстве мы создадим простой бота ErisPulse с нуля.

## Шаг 1: Создание проекта

Используйте CLI-инструмент для инициализации проекта:

```bash
# Интерактивная инициализация
epsdk init

# Или быстрая инициализация
epsdk init -q -n my_first_bot
```

Следуйте инструкциям для завершения настройки, рекомендуется выбрать:
- Имя проекта: my_first_bot
- Уровень логирования: INFO
- Сервер: конфигурация по умолчанию
- Адаптер: выберите нужную платформу (например, Yunhu)

## Шаг 2: Просмотр структуры проекта

Структура инициализированного проекта:

```
my_first_bot/
├── config/
│   └── config.toml
├── main.py
└── requirements.txt
```

## Шаг 3: Написание первого команды

Откройте `main.py` и напишите простой обработчик команды:

```python
from ErisPulse import sdk
from ErisPulse.Core.Event import command

@command("hello", help="Отправить приветственное сообщение")
async def hello_handler(event):
    """Обработка команды hello"""
    user_name = event.get_user_nickname() or "Друг"
    await event.reply(f"Привет, {user_name}! Я бот ErisPulse.")

@command("ping", help="Проверить, работает ли бот онлайн")
async def ping_handler(event):
    """Обработка команды ping"""
    await event.reply("Pong! Бот работает нормально.")

async def main():
    """Основная функция входа"""
    print("Запуск ErisPulse...")
    
    # keep_running=True (по умолчанию): фреймворк блокируется для поддержания работы, пока не получен сигнал о закрытии (например, Ctrl+C)
    await sdk.run(keep_running=True)

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

### Параметр `keep_running`

`sdk.run(keep_running)` управляет тем, блокирует ли фреймворк работу:

- **`keep_running=True` (по умолчанию)**: `run()` будет постоянно блокироваться, пока не получен сигнал о закрытии (например, Ctrl+C), подходит для чистых приложений бота.
- **`keep_running=False`**: `run()` сразу вернется после завершения инициализации, **фреймворк не будет выгружен** — запущенные адаптеры/модули продолжат обрабатывать события сообщений в качестве фоновых задач, вы можете продолжить выполнение собственной логики, пока цикл событий не завершится, после чего фреймворк закроется. Например:

```python
async def main():
    await sdk.run(keep_running=False)   # Сразу вернется после инициализации
    # Фреймворк уже работает в фоне, здесь можно продолжить делать другие вещи
    while True:
        await asyncio.sleep(3600)
        print("Проверка раз в час")
```

> Помимо двух режимов `run()`, существуют и другие способы более точного управления жизненным циклом, такие как ручное управление через `init()`/`uninit()`, отдельное запуск/остановка адаптеров/маршрутизаторов и т.д., см. [Запуск и ручное управление](../advanced/startup.md).

## Шаг 4: Запуск бота

```bash
# Обычный запуск
epsdk run main.py

# Режим разработки (поддерживает горячую перезагрузку)
epsdk run main.py --reload
```

## Описание кода

### Декоратор команды

```python
@command("hello", help="Отправить приветственное сообщение")
```

- `hello`: имя команды, вызываемой пользователем через `/hello`
- `help`: справка по команде, отображаемая в команде `/help`

### Параметры события

```python
async def hello_handler(event):
```

Параметр `event` — это объект Event, который содержит:
- Содержимое сообщения: `event.get_text()`
- Информация об отправителе: `event.get_user_id()`, `event.get_user_nickname()`
- Информация о платформе: `event.get_platform()`
- Информация о группе: `event.get_group_id()`
- Необработанные данные: `event.get_raw()`

> Описание всех методов объекта Event см. в [Подробном описании класса-обертки Event](../developer-guide/modules/event-wrapper.md).

### Отправка ответа

```python
await event.reply("Содержимое ответа")
```

`event.reply()` — это удобный метод для отправки сообщения отправителю.

## Часто задаваемые вопросы

### Команда не отвечает?

1. Проверьте, правильно ли настроен адаптер, убедитесь, что в `config/config.toml` статус адаптера установлен в `true`
2. Просмотрите выходные данные логов терминала, убедитесь, что нет ошибок (особенно логов уровня `ERROR`)
3. Убедитесь, что префикс команды правильный (по умолчанию `/`), его можно просмотреть в файле конфигурации в разделе `[ErisPulse.event.command]`
4. Убедитесь, что название команды написано правильно, обратите внимание на настройки чувствительности к регистру

### Как изменить префикс команды?

Добавьте в `config.toml`:

```toml
[ErisPulse.event.command]
prefix = "!"
case_sensitive = false
```

### Как поддерживать несколько платформ?

ErisPulse использует стандарт OneBot12 для унификации форматов событий разных платформ, обработчики, зарегистрированные через `@command` и `@message`, автоматически будут получать события со всех платформ. С помощью `event.get_platform()` можно определить платформу источника:

```python
@command("hello")
async def hello_handler(event):
    platform = event.get_platform()
    
    if platform == "yunhu":
        await event.reply("Привет! Из Yunhu")
    elif platform == "telegram":
        await event.reply("Hello! From Telegram")
    else:
        await event.reply("Привет!")
```

> Дополнительные советы по адаптации к нескольким платформам см. в [Примерах типичных задач](common-tasks.md#многоплатформенная-адаптация).
