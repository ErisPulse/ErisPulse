# Документация ErisPulse

ErisPulse — это асинхронный модульный робот-фреймворк, основанный на событийном подходе. Бизнес-логику нужно писать только один раз, а с помощью адаптеров развертывать на различных платформах, таких как QQ, Telegram, Kook, Yunhu и других. В комплекте предоставляется система плагинов, горячая перезагрузка и полный набор инструментов для разработчиков.

> **Впервые используете?** Начните с [5-минутного краткого руководства](docs/ru/quick-start.md) — от установки до запуска первого робота, всё пошагово.

| [Тень и градация](advanced/shadow.md) (shadow) | Как можно протестировать новую версию модуля, не влияя на основную? | Теневой модуль получает копии, исходящие сообщения записываются, переход к основному происходит только после подтверждения |
| [Хранилище](advanced/storage-backends.md) (storage-backends) | Где хранятся данные, как можно менять хранилище? | Одна и та же API хранения, sqlite / mysql / postgres переключаются через конфигурацию |

## Справочник по расширенным функциям по версиям

При необходимости проверки совместимости версий или при работе с унаследованным проектом, чтобы узнать, с какой версии появилась та или иная возможность, используйте следующую таблицу (список изменений в корне репозитория [CHANGELOG.md](https://github.com/ErisPulse/ErisPulse/blob/main/CHANGELOG.md) служит основой для определения версий):

| Версия | Введённые возможности |
|------|-----------|
| **2.7** | Базовая платформа для продакшена: стандартизированный базовый класс OneBot12 (`ApiDSL` / `BaseConverter`), систематизированная горячая перезагрузка конфигурации, элегантное завершение работы и обработка сигналов SIGTERM/SIGHUP, перекрытие переменных окружения, хуки обратных вызовов жизненного цикла, ленивая загрузка Web-стека; в 2.7.1 исправлены проблемы с надежностью записи конфигурации и управлением поколениями GC |
| **2.8** | Основа для прав и коммуникации: трёхмерная система области действия (scope), инфраструктура интерактивных сессий (аренда / контрольные точки / транзакции сообщений / ящик сессии transcript), модульный RPC-протокол (сервисные контракты `module.call` / `meta.services` / направленные события emit(to=)), асинхронное хранение данных с несколькими бэкендами (sqlite / mysql / postgres, не блокирует работу при ошибках подключения), очистка прав собственности, сохранение комментариев в конфигурации; последующие версии 2.8.x улучшают CLI-скелет, подкоманды и т.д. |
| **2.9** | Основная линия улучшений "опыта разработки модулей" (EPRFC-2026-001): декларативные параметры команд (`args=` / `options=`) и управление командами (`cooldown=` / `rate_limit=`), единая инъекция зависимостей (`Depends`), право промежуточных обработчиков на отклонение событий, встроенный ORM (автоматическое миграция + сопоставление отношений), модули-теневые для постепенного перехода в продакшн, трассировка и диагностика цепочки принятия решений при распространении, официальная поддержка Python 3.14 |
| **2.10** | Ресурсы связи первого класса (реестр `connections`: трансляции / деление по бизнес-группам / повторное использование между модулями / автоматическая очистка при отключении), корневой импортный контракт (все основные API доступны через `from ErisPulse import`), завершение системы прав собственности, перекрытие стратегии сохранения ящика сессии в режиме выполнения; в 2.10.2 адаптированы локальные каталоги плагинов адаптера (`plugins/`) + `epsdk create pack` + безопасная запись конфигурации с помощью tomlclass |
| **2.11** (dev) | Замкнутый цикл разработки "изменить код → увидеть результат": горячая перезагрузка по умолчанию с полной семантикой (предварительная проверка синтаксиса + проверка идентичности кода + повторная перезагрузка зависимых компонентов), ленивая загрузка в спящем режиме (`dormant_after`), горячая перезагрузка кода адаптера на уровне кода (`sdk.adapter.reload`), синтаксический сахар для командной последовательности `.got()`, управление в режиме выполнения командами `epsdk stop` / `restart` |

## Способы разработки

ErisPulse поддерживает два способа разработки:

- **Разработка модуля (рекомендуется)**: создание отдельного пакета модуля, устанавливаемого через менеджер пакетов, удобно для распространения и управления.
- **Встраиваемая разработка**: непосредственное написание обработчиков в проекте, подходит для быстрого прототипирования. Подробнее см. [Руководство](docs/ru/quick-start.md).
