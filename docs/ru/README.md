# Документация ErisPulse

ErisPulse — это фреймворк для асинхронных модульных роботов, основанный на событийном подходе: бизнес-код пишется один раз, а адаптеры позволяют развернуть робота на QQ, Telegram, Kook, Yunhu и других платформах. Встроенные плагины, горячая перезагрузка и полный набор инструментов для разработки — всё это работает из коробки.

> **Впервые используете?** Начните с [5-минутного краткого руководства](docs/ru/quick-start.md) — от установки до запуска первого робота, всё покрыто.

**Общая таблица понятий**

Когда неясно, какой подсистемой управляет какая задача, ориентируйтесь по этой таблице:

| Подсистема | Отвечает на вопрос | Краткое правило |
|------------|-------------------|----------------|
| [Коммуникация](advanced/module-communication.md) (module-communication) | Как модули могут вызывать друг друга, как отправлять события? | Для вызова между модулями используйте `module.call`; если другая сторона объявила `meta.services`, можно вызывать только методы из белого списка |
| [Права доступа](advanced/scope.md) (scope) | Кто может использовать модуль, кто может вызывать события, какие действия разрешены? | Три контрольные точки — привязка модуля, допуск идентификации, ограничение исходящих действий, все регулируются пользовательскими настройками |
| [Принадлежность](advanced/ownership.md) (ownership) | Что происходит с соединениями, таймерами, подписками после выгрузки модуля? | Кто зарегистрировал, тот и владеет; при выгрузке ресурсы автоматически очищаются |
| [Ленивая загрузка и сон](advanced/lazy-loading.md) (lazy-loading) | Когда модуль загружается, и куда уходит, когда бездействует? | Модуль активируется по событиям `activate_on`, переходит в сон по `dormant_after` |
| [Взаимодействие](advanced/interaction.md) (interaction) | Как ждать следующего ответа пользователя, как реализовать многошаговый сбор? | `wait_reply` ждёт одно сообщение, `.got()` цепочкой собирает несколько, сессионные локи гарантируют отсутствие конфликтов |
| [Теневой запуск](advanced/shadow.md) (shadow) | Как можно протестировать новую версию модуля без влияния на основной поток? | Теневой модуль получает копию сообщений, исходящие сообщения только записываются, `promote` переводит в основной поток только после ручного подтверждения |
| [Хранилище](advanced/storage-backends.md) (storage-backends) | Где хранятся данные, как менять хранилище? | Одна и та же API-обёртка, переключение между sqlite / mysql / postgres через конфигурацию |

## Справочник по продвинутым функциям по версиям

Для определения версий, где появилась та или иная функция, или для понимания, с какой версии появилась та или иная возможность, ориентируйтесь по этой таблице (согласно [CHANGELOG.md](https://github.com/ErisPulse/ErisPulse/blob/main/CHANGELOG.md) в корне репозитория).

| Версия | Введённые возможности |
|--------|----------------------|
| **2.7** | База для продакшена: стандартизированный базовый класс OneBot12 (`ApiDSL` / `BaseConverter`), систематизированная горячая перезагрузка конфигурации, элегантное завершение и обработка сигналов SIGTERM/SIGHUP, перекрытие конфигурации через переменные окружения, хуки обратных вызовов жизненного цикла, ленивая загрузка Web-стека; в 2.7.1 исправлена надёжность записи конфигурации и управление сборкой мусора |
| **2.8** | Архитектура прав и коммуникации: трёхмерная система областей видимости (scope), инфраструктура взаимодействия сессий (локи / контрольные точки / транзакции сообщений / почтовый ящик transcript), протокол RPC между модулями (`module.call` / `meta.services` / `emit(to=)`), многохранилищная асинхронная поддержка (sqlite / mysql / postgres, не блокирует фреймворк при сбое подключения), очистка принадлежности, сохранение комментариев в конфигурации; в версиях 2.8.x улучшена поддержка CLI, скелетов, подкоманд |
| **2.9** | Основная линия улучшения разработки модулей (EPRFC-2026-001): декларативные аргументы команд (`args=` / `options=`) и управление командами (`cooldown=` / `rate_limit=`), единая система внедрения зависимостей (`Depends`), право отмены событий через middleware, встроенный ORM (автомиграция + отношение), теневые модули и серый запуск, трассировка и диагностика цепочки принятия решений, официальная поддержка Python 3.14 |
| **2.10** | Соединения как первоклассный ресурс (`connections` — реестр: эфемерная рассылка / бизнес-группы / передача и повторное использование между модулями / автоматическая очистка при выгрузке), корневой импорт (`from ErisPulse import`), завершение системы принадлежности, возможность перезаписи политик сохранения почтового ящика в runtime; в 2.10.2 добавлена поддержка локальных папок адаптеров (`plugins/`) + `epsdk create pack` + tomlclass с безвозвратной записью конфигурации |
| **2.11** (dev) | Замкнутый цикл разработки «изменение кода → видеть результат»: горячая перезагрузка с полным семантическим обновлением (предварительная проверка синтаксиса + проверка идентичности кода + каскадная перезагрузка зависимостей), ленивая загрузка и сон (`dormant_after`), горячая перезагрузка кода адаптеров (`sdk.adapter.reload`), синтаксический сахар `.got()` для командных потоков, управляющие команды `epsdk stop` / `restart` |

## Способы разработки

ErisPulse поддерживает два способа разработки:

- **Разработка модулей** (рекомендуется): создание отдельного пакета модуля, устанавливаемого через менеджер пакетов, удобно для распространения и управления.
- **Встраиваемая разработка**: написание обработчиков прямо в проекте, подходит для быстрой разработки прототипов. Подробнее см. [5-минутное краткое руководство](docs/ru/quick-start.md).
