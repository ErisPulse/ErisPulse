# Сравнение: ErisPulse и NoneBot2

> [!TIP]
> **Когда нужно читать эту статью**: Когда вы пишете код в Python-фреймворке для ботов и выбираете между NoneBot2 и ErisPulse. Если не пишете код, пропустите.

Одним предложением о различиях:

- **NoneBot2**: Самый развитый по экосистеме асинхронный фреймворк для ботов, с хорошо отработанной моделью обработки событий, накопленным сообществом на протяжении десяти лет
- **ErisPulse**: SDK для ботов, основанный на унифицированной модели событий OneBot12, один обработчик (handler) естественным образом работает на разных платформах, модульная горячая перезагрузка и экосистемные сервисные контракты — встроенные возможности

Оба являются фреймворками для "разработки кода", а не готовыми продуктами, которые можно просто установить и использовать.

## Сравнение архитектур

| Параметр | ErisPulse | NoneBot2 |
|---|---|---|
| Межплатформенность | Unified Event Model OneBot12 встроен в ядро, обработчики не должны знать о различиях платформ | Каждый адаптер имеет свою модель событий, межплатформенность достигается с помощью плагинов абстракции сообщений (например, alconna) |
| Плагин-система | Модуль = PyPI-пакет + установка через `epsdk` CLI + индекс [Marketplace](https://www.erisdev.com/#market) | Плагин = PyPI-пакет (`nonebot-plugin-*`), поиск по веб-сайту магазина, установка через pip |
| API отправки | SendDSL — цепочка отправки: упоминание, ответ, повтор, таймаут, массовая отправка — всё в одной строке | `send` на стороне Matcher / API каждого адаптера, абстракция сообщений предоставляется плагинами |
| Горячая перезагрузка | Горячая перезагрузка на уровне модуля/адаптера, изменения применяются сразу, процесс не перезапускается | Перезагрузка всего процесса в dev-режиме (перезапуск при изменении файлов) |
| Интеграция с ИИ | Фреймворк не имеет прямой зависимости от ИИ; объявление сервисного контракта модуля делает его автоматически инструментом для [QvQChat](../ecosystem/qvqchat.md); [ApiMCP](../ecosystem/apimcp.md) позволяет открыть робота для клиентов MCP, таких как Claude | Комбинируется по требованию с помощью плагинов сообщества |
| Инструменты управления | Официальная веб-панель [Dashboard](../ecosystem/dashboard.md), `epsdk` CLI, мобильное приложение ErisPulse-App | Веб-интерфейсы сообщества, nb-cli |
| Характеристики для продакшена | Трёхмерная область видимости, автоматическая сдача прав, градиентные модули-тени, RPC-контракты между модулями | Внедрение зависимостей, система хуков, решения сообщества |
| Хранение данных | Единый API для KV + SQL (переключение между sqlite/mysql/postgres по настройке) | Каждый плагин выбирает свою схему хранения |

## Когда выбрать что

**Выберите NoneBot2**: вам нужны конкретные плагины, уже существующие в его экосистеме; или команда уже глубоко знакома с его моделью событий. Количество плагинов — это явное преимущество, все остальные различия можно компенсировать кодом, но экосистему нельзя.

**Выберите ErisPulse**: ваша главная задача — согласованность на разных платформах (единая модель событий + 16 адаптеров для платформ); вы хотите разработки с возможностью "изменения кода без перезапуска"; вы хотите, чтобы модульные возможности напрямую попали в инструментарий ИИ, а не отдельно подключались к LLM.

> [!NOTE]
> Сравнение составлено на основе открытых документов обеих сторон. Объективный факт — значительно более обширная экосистема плагинов и сообщество у NoneBot2; при принятии решений, пожалуйста, обращайтесь к [официальной документации](https://nonebot.dev/) другой стороны.
