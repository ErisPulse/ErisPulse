# Внести вклад в ErisPulse

> **Для тех, кто впервые участвует в разработке**
> Открытые проекты никогда не поддерживаются только несколькими ключевыми разработчиками, которые совершают «большие действия». Чаще всего, это накопление множества небольших изменений — исправление опечатки, перевод фразы, исправление небольшого бага — все это помогает ErisPulse продвигаться вперед. Поэтому не стоит оценивать, достаточно ли ваш вклад значимым. Если вы готовы отправить PR, вы уже являетесь частью этого процесса.

## Как вы можете участвовать

Вклад не ограничивается написанием основного кода. Следующие действия помогают улучшить ErisPulse:

- **Улучшение документации** — исправление опечаток, улучшение запутанных описаний, дополнение описанием проблем, с которыми вы столкнулись. Это самый низкий порог входа, и вы можете начать в любой момент.
- **Добавление переводов** — фреймворк поддерживает 5 языков (zh-CN / en / zh-TW / ja / ru), и мы приветствуем дополнения для мест, где переводы отсутствуют или неточны.
- **Исправление багов** — выберите проблему, с которой вы знакомы, в [Issues](https://github.com/ErisPulse/ErisPulse/issues), воспроизведите её и исправьте.
- **Написание примеров** — соберите свой опыт использования в примеры кода, чтобы другие могли использовать их как справочник.
- **Разработка модулей / адаптеров** — добавьте фреймворку поддержку новых платформ или возможностей. Это сложнее, но и более удовлетворительно.

> Если вы не уверены, с чего начать, напишите об этом в [Discussions](https://github.com/ErisPulse/ErisPulse/discussions), и разработчики помогут вам найти подходящее направление.

## Первое отправление PR

Если вы ещё не отправляли PR, рекомендуем сначала прочитать [Практическое руководство по первому вкладу](first-contribution.md). В нём описывается полный процесс от форка репозитория до слияния PR. Если возникнут вопросы, вы можете задать их в Issue или Discussions.

## Разработка среда

Полное руководство по разработке находится в корневом каталоге [CONTRIBUTING.md](../../../CONTRIBUTING.md). Быстрый старт:

```bash
git clone -b Develop/v2 https://github.com/ErisPulse/ErisPulse.git
cd ErisPulse
uv sync                       # Синхронизация среды разработки
uv run pytest -m unit         # Запуск юнит-тестов
uv run ruff check .           # Проверка кода
```

## Процесс отправки

Проще говоря: форкните репозиторий → создайте ветку на основе `Develop/v2` → исправьте и запустите тесты → отправьте PR в `Develop/v2`.

Несколько важных моментов:

- PR отправляйте в ветку **`Develop/v2`**, не трогайте `main` или `Pre-Release/v2`
- Перед отправкой убедитесь, что `pytest` / `ruff` / `basedpyright` проходят (предупреждения `reportAny` / `Unknown*` в проверке типов относятся к «постепенному улучшению типов», и не блокируют слияние)
- Если вы изменили функционал, добавьте запись в `CHANGELOG.md`
- Если вы добавили методы к публичному API, не забудьте добавить документационные комментарии (см. [стандарт здесь](../styleguide/docstring.md))

## Вклад в модули или адаптеры

Если вы планируете создать новый модуль или адаптер, рекомендуем сначала в [Issues](https://github.com/ErisPulse/ErisPulse/issues) с помощью шаблона «Новый адаптер или модуль» кратко описать свою идею. Не нужно писать очень подробно, достаточно объяснить суть — разработчики помогут вам упорядочить мысли и согласовать стандарты разработки, чтобы всё прошло гладко.

Использование инструмента-стартапа поможет быстро начать:

```bash
epsdk create    # Выберите module или adapter, сгенерируйте структуру проекта
```

Затем ознакомьтесь с [Руководством по разработке модулей](../developer-guide/modules/getting-started.md) или [Руководством по разработке адаптеров](../developer-guide/adapters/getting-started.md). После завершения вы также можете [опубликовать на PyPI и в магазине модулей](../developer-guide/publishing.md).

> Модули и адаптеры обычно находятся в отдельных репозиториях, не нужно объединять их с основным репозиторием. Проекты в каталоге `examples/` можно использовать как примеры.
