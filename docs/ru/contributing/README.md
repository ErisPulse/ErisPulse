# Вклад в ErisPulse

> **Для тех, кто впервые вносит свой вклад**
> Открытые проекты никогда не поддерживаются только несколькими ключевыми разработчиками, которые совершают «большие действия». Чаще всего, это накопление бесчисленных мелких изменений — опечатка, перевод, небольшой исправленный баг — все это помогает ErisPulse продвигаться вперёд. Поэтому не стоит оценивать, насколько значим ваш вклад. Если вы готовы отправить PR, вы уже являетесь частью этого процесса.

## Как вы можете участвовать

Вклад — это не только написание кода ядра. Вот несколько способов, как вы можете помочь улучшить ErisPulse:

- **Улучшение документации** — исправление опечаток, улучшение запутанных описаний, добавление информации о проблемах, с которыми вы столкнулись. Это самый простой способ начать.
- **Дополнение переводов** — фреймворк поддерживает 5 языков (zh-CN / en / zh-TW / ja / ru), если вы заметили недостающие или неточные переводы, пожалуйста, добавьте их.
- **Исправление ошибок** — выберите проблему, с которой вы знакомы, в [Issues](https://github.com/ErisPulse/ErisPulse/issues), воспроизведите и исправьте её.
- **Написание примеров** — соберите свой опыт использования в примеры кода, которые помогут другим.
- **Разработка модулей / адаптеров** — добавьте поддержку новых платформ или возможностей. Это более сложный путь, но и более удовлетворяющий.

> Если вы не уверены, с чего начать, напишите об этом в [Discussions](https://github.com/ErisPulse/ErisPulse/discussions), и разработчики помогут вам найти подходящее направление.

## Первый PR

Если вы ещё не отправляли PR, рекомендуем сначала прочитать [Практическое руководство по первому вкладу](first-contribution.md). В нём описан полный процесс от форка репозитория до слияния PR. При возникновении вопросов можно обратиться в Issue или Discussions.

## Рабочая среда разработки

Полное руководство по разработке см. в файле [CONTRIBUTING.md](../../../CONTRIBUTING.md) в корневой директории. Быстрый старт:

```bash
git clone -b Develop/v2 https://github.com/ErisPulse/ErisPulse.git
cd ErisPulse
uv sync                       # Синхронизация среды разработки
uv run pytest -m unit         # Запуск юнит-тестов
uv run ruff check .           # Проверка кода
```

## Процесс отправки

Проще говоря: fork репозитория → создание ветки на основе `Develop/v2` → запуск тестов после изменений → отправка PR в `Develop/v2`.

Несколько важных моментов:

- PR следует отправлять в ветку **`Develop/v2`**, не изменяйте напрямую `main` или `Pre-Release/v2`
- Перед отправкой убедитесь, что `pytest` / `ruff` / `basedpyright` прошли успешно (предупреждения типа `reportAny` / `Unknown*` в проверке типов относятся к «постепенному улучшению типов» и не блокируют слияние)
- Если вы изменили функциональность, оставьте запись в `CHANGELOG.md`
- Если вы добавили методы к публичному API, не забудьте добавить документацию (см. [стандарт здесь](../styleguide/docstring.md))

## Вклад в модули или адаптеры

Если вы планируете создать новый модуль или адаптер, рекомендуется сначала в [Issues](https://github.com/ErisPulse/ErisPulse/issues) с помощью шаблона "Новый адаптер или модуль" кратко описать свою идею. Не нужно писать что-то очень подробное, достаточно просто объяснить суть — разработчики помогут вам сформулировать идею и согласовать стандарты разработки, чтобы всё шло гладко.

Для быстрого старта можно использовать инструмент шаблонизации:

```bash
epsdk create    # Выберите module или adapter, чтобы сгенерировать полную структуру проекта
```

Затем ознакомьтесь с руководством по [началу разработки модулей](../developer-guide/modules/getting-started.md) или [началу разработки адаптеров](../developer-guide/adapters/getting-started.md). После завершения вы также можете [опубликовать модуль в PyPI и в каталог модулей](../developer-guide/publishing.md).

> Модули и адаптеры обычно находятся в отдельных репозиториях, а не в основном. Примеры проектов в папке `examples/` можно использовать в качестве справки.
