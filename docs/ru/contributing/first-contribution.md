# Практическое руководство по первому вкладу

> Первый Pull Request может вызывать некоторые сомнения — это нормально. В этом руководстве процесс разбит на несколько маленьких шагов, просто следуйте за ним. Если возникнут какие-либо проблемы, вы можете задать их в Issues или Discussions — никто не скажет ничего плохого, если ваш вопрос покажется вам «слишком базовым»; все больше интересуются тем, что вы делаете прогресс.

В качестве примера мы используем добавление ключа перевода i18n, так как это вносит наименьшие изменения и проще всего запустить. Однако для других типов вкладов подходит та же логика.

## Подготовка

Прежде чем начать, вам необходимо подготовить:

- Аккаунт GitHub
- Установленный локально [uv](https://docs.astral.sh/uv/) (менеджер пакетов ErisPulse)
- Python 3.10+

## 1. Fork и клонирование репозитория

Перейдите в [репозиторий ErisPulse](https://github.com/ErisPulse/ErisPulse), нажмите кнопку **Fork** в правом верхнем углу, чтобы скопировать его в свой аккаунт, затем клонируйте локально (замените «ваше_имя_пользователя» на реальное имя пользователя):

```bash
git clone -b Develop/v2 https://github.com/ваше_имя_пользователя/ErisPulse.git
cd ErisPulse
```

Добавьте upstream-адрес, чтобы в будущем удобно было синхронизироваться с главным репозиторием:

```bash
git remote add upstream https://github.com/ErisPulse/ErisPulse.git
```

## 2. Установка среды разработки

```bash
uv sync                       # Установка зависимостей и создание .venv
```

Проверьте, что среда работает нормально:

```bash
uv run pytest -m unit -q      # Тесты должны пройти успешно
```

## 3. Создание ветки функций

Всегда переключайтесь на ветку `Develop/v2`:

```bash
git checkout Develop/v2
git pull upstream Develop/v2   # Сначала синхронизируйте с последним кодом
git checkout -b docs/add-hello-translation
```

Название ветки может быть любым, главное, чтобы было понятно, что вы делаете.

## 4. Внесение изменений

В качестве примера возьмем добавление ключа перевода, предположим, нужно добавить строку `mymodule.hello`.

Правило только одно: **при добавлении ключа перевода нужно сразу добавить 5 языков (zh-CN / en / zh-TW / ja / ru)**, иначе пользователи других языков увидят отсутствие перевода.

Откройте 5 файлов в `src/ErisPulse/Core/i18n/locales/` и добавьте в каждый по одной строке:

```python
# zh_cn.py
"mymodule.hello": "你好",
# en.py
"mymodule.hello": "Hello",
# zh_tw.py
"mymodule.hello": "你好",
# ja.py
"mymodule.hello": "こんにちは",
# ru.py
"mymodule.hello": "Привет",
```

> Если в этом изменении участвуют новые публичные методы, не забудьте добавить к ним документационные комментарии, см. [Руководство по документационным комментариям](../styleguide/docstring.md).

## 5. Локальная проверка

```bash
uv run ruff check .            # Проверка кода по стилю
uv run basedpyright src/ErisPulse   # Проверка типов (нужна, только если вы меняли исходный код) - вы можете столкнуться с сотнями предупреждений (просто проигнорируйте их, это нормально...)
uv run pytest -m unit -q       # Запуск тестов
```

Должны пройти все три проверки. Предупреждения `reportAny` / `Unknown*` в проверке типов относятся к «постепенному улучшению типов» и не остановят слияние.

> Если вы меняете модули ядра (Bases / runtime / config / loaders), рекомендуется сразу добавить соответствующие тестовые случаи для удобства дальнейшего сопровождения.

## 6. Обновление CHANGELOG

Откройте файл `CHANGELOG.md`, найдите версию, которая все еще находится в разработке, и добавьте запись в соответствующую категорию:

```markdown
### Optimization

- Added `mymodule.hello` translation keys to `Core/i18n/locales` (zh-CN / en / zh-TW / ja / ru)
```

## 7. Коммит и отправка изменений

```bash
git add .
git commit -m "i18n: add mymodule.hello translation"
git push origin docs/add-hello-translation
```

## 8. Создание Pull Request

После отправки GitHub предложит перейти на страницу **Compare & pull request**:

1. Убедитесь, что целевая ветка — **`Develop/v2`** (не выбирайте `main`)
2. Отметьте тип изменений и кратко опишите, что вы сделали
3. Создайте запрос, дождитесь проверки от сопровождающих

Оставлять комментарии по рецензии — это нормально и не значит, что вы сделали плохо — просто внесите изменения по предложению и отправьте еще раз. После прохождения проверки ваши изменения официально попадут в `Develop/v2`, и они будут доступны в следующей версии.

## Вклад в модули или адаптеры

Модули и адаптеры — это небольшие пакеты с полной структурой, проще всего начать с помощью scaffolding-инструмента:

```bash
epsdk create    # Выберите module или adapter
```

После генерации просто следуйте этой документации:

- [Начало работы с модулем](../developer-guide/modules/getting-started.md)
- [Начало работы с адаптером](../developer-guide/adapters/getting-started.md)
- [Публикация в PyPI и модуле магазина](../developer-guide/publishing.md)

> Рекомендуется перед началом разработки сообщить о своих планах в [Issues](https://github.com/ErisPulse/ErisPulse/issues) с шаблоном «New adapter or module», сопровождающие смогут помочь с интеграцией в стандарты и избежать некоторых распространенных ошибок.

Модули и адаптеры обычно хранятся в отдельных репозиториях, их не нужно помещать в основной репозиторий. Папки `examples/example-module/` и `examples/example-adapter/` предназначены для справки.

## Возможные проблемы

**Сколько ждать, пока посмотрят PR?**
Обычно в течение нескольких дней. Сопровождающие оставят комментарии по рецензии, вам нужно будет внести правки и отправить еще раз.

**В коде проверки ошибки?**
Сначала попробуйте `uv run ruff check . --fix`, это автоматически исправит большинство ошибок.

**Возникли конфликты с главным репозиторием?**
Выполните `git pull upstream Develop/v2`, разрешите конфликты и отправьте изменения.

**Можно ли сразу сделать в `main`?**
Нет, все изменения проходят через `Develop/v2`, а уже сопровождающие выпускают их в `main`.
