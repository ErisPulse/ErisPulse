## Обзор стандартов

ErisPulse использует OneBot12 в качестве стандарта основных событий и на его основе расширяет и уточняет его.

### Основные принципы

1.  **Совместимость**: Все стандарты должны быть совместимы со стандартом OneBot12
2.  **Расширяемость**: Платформенные функции расширяются через префиксы, чтобы избежать конфликтов
3.  **Согласованность**: Ключевые поля, такие как временные метки и форматы ID, должны обрабатываться единообразно
4.  **Отслеживаемость**: Сохранение исходных данных для отладки и устранения неполадок

## Зачем нужны стандарты?

### 1. Обеспечение кроссплатформенной совместимости

Форматы событий разных платформ различаются, стандартизированная конвертация обеспечивает:
- Код модулей нужно писать только один раз, чтобы он работал на всех платформах
- Логика обработки событий остается согласованной
- Снижение затрат на разработку и обслуживание

### 2. Стандартизация интерфейсов API

Единый формат ответов API обеспечивает:
- Модули могут обрабатывать ошибки API согласованно
- Информация об ошибках унифицирована и понятна
- Структура возвращаемых данных согласована

### 3. Повышение качества кода

Стандарты помогают:
- Поддерживать согласованность стиля кода
- Уменьшать конфликты именования
- Повышать читаемость кода

## Преимущества следования стандартам

### Для разработчиков адаптеров

- Четкие правила конвертации
- Единый формат ответов
- Легкая отладка и тестирование

### Для разработчиков модулей

- Согласованный интерфейс событий
- Предсказуемое поведение API
- Упрощенная разработка для разных платформ

### Для конечных пользователей

- Стабильное поведение системы
- Унифицированный формат сообщений
- Хорошая совместимость

## Чек-лист соответствия стандартам

### Конвертация событий

- [ ] Все стандартные поля корректно отображены
- [ ] Платформенные поля добавлены с префиксом
- [ ] Временные метки конвертированы в 10-значное значение в секундах
- [ ] Исходные данные сохранены в {platform}_raw
- [ ] Исходный тип события сохранен в {platform}_raw_type
- [ ] Сегменты сообщений имеют сгенерированный alt_message
- [ ] События запроса содержат поле request_id

### Ответы API

- [ ] Содержит поле status
- [ ] Содержит поле retcode
- [ ] Содержит поле data
- [ ] Содержит поле message_id
- [ ] Содержит поле message
- [ ] Код возврата соответствует спецификации OneBot12

### Именование методов отправки

- [ ] Используется верхний регистр (PascalCase)
- [ ] Возвращает объект Task
- [ ] Модификаторы методов возвращают self
- [ ] Именование параметров соответствует спецификациям

### Операции запроса

- [ ] Класс HandleRequest реализует _do_accept / _do_reject
- [ ] Операции возвращают стандартный формат ответа API
- [ ] Для неподдерживаемых операций возвращается retcode=10002
