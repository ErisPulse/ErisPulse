## Обзор стандартов

ErisPulse использует OneBot12 в качестве основного стандарта событий и расширяет его на основе этого стандарта.

### Основные принципы

1. **Совместимость**: Все стандарты должны быть совместимы со стандартом OneBot12
2. **Расширяемость**: Функции, специфичные для платформы, расширяются с помощью префиксов, чтобы избежать конфликтов
3. **Согласованность**: Ключевые поля, такие как временные метки и форматы ID, должны обрабатываться единообразно
4. **Отслеживаемость**: Сохранение исходных данных для отладки и устранения проблем

## Зачем нужны стандарты?

### 1. Обеспечение совместимости между платформами

Форматы событий на разных платформах различаются, стандартизированное преобразование гарантирует:
- Модульный код нужно писать только один раз, чтобы он работал на всех платформах
- Логика обработки событий остается одинаковой
- Снижение затрат на разработку и обслуживание

### 2. Нормализация интерфейсов API

Единый формат ответа API гарантирует:
- Модули могут последовательно обрабатывать ошибки API
- Информация об ошибках унифицирована и легко понятна
- Структура возвращаемых данных едина

### 3. Повышение качества кода

Стандарты помогают:
- Сохранять единообразный стиль кода
- Сокращать конфликты имен
- Повышать читаемость кода

## Преимущества соблюдения стандартов

### Для разработчиков адаптеров

- Четкие правила преобразования
- Единый формат ответа
- Легкость отладки и тестирования

### Для разработчиков модулей

- Единый интерфейс событий
- Предсказуемое поведение API
- Упрощение разработки для кроссплатформенных систем

### Для конечных пользователей

- Стабильное поведение системы
- Единый формат сообщений
- Хорошая совместимость

## Проверочный список соблюдения стандартов

### Преобразование событий

- [ ] Все стандартные поля корректно сопоставлены
- [ ] Платформо-специфичные поля добавлены с префиксом
- [ ] Временные метки преобразованы в 10-значные секундные значения
- [ ] Исходные данные сохранены в {platform}_raw
- [ ] Тип исходного события сохранен в {platform}_raw_type
- [ ] Сегменты сообщений alt_message сгенерированы
- [ ] События запроса содержат поле request_id

### Ответы API

- [ ] Содержит поле status
- [ ] Содержит поле retcode
- [ ] Содержит поле data
- [ ] Содержит поле message_id
- [ ] Содержит поле message
- [ ] Коды возврата соответствуют спецификации OneBot12

### Назначение методов отправки

- [ ] Используется стиль PascalCase
- [ ] Возвращает объект Task
- [ ] Модифицирующие методы возвращают self
- [ ] Имена параметров соответствуют стандарту

### Действия запроса

- [ ] Класс HandleRequest реализован с _do_accept / _do_reject
- [ ] Действия возвращают стандартный формат ответа API
- [ ] Не поддерживаемые действия возвращают retcode=10002
