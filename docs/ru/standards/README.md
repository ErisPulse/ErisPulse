## Обзор стандарта

ErisPulse использует OneBot12 в качестве основного стандарта событий и расширяет и уточняет его.

### Основные принципы

1. **Совместимость**: Все стандарты должны быть совместимы со стандартом OneBot12
2. **Расширяемость**: Функции, специфичные для платформы, расширяются с помощью префиксов, чтобы избежать конфликтов
3. **Согласованность**: Ключевые поля, такие как временные метки и форматы ID, должны обрабатываться единообразно
4. **Отслеживаемость**: Сохраняются исходные данные для отладки и устранения проблем

## Почему необходим стандарт?

### 1. Обеспечение совместимости между платформами

Форматы событий на разных платформах различаются, стандартизированный перевод обеспечивает:
- Код модуля нужно писать только один раз, чтобы он работал на всех платформах
- Логика обработки событий остается одинаковой
- Снижение затрат на разработку и обслуживание

### 2. Стандартизация API-интерфейсов

Единый формат ответа API обеспечивает:
- Модуль может последовательно обрабатывать ошибки API
- Информация об ошибках единообразна и легко понимаема
- Структура возвращаемых данных остается одинаковой

### 3. Повышение качества кода

Стандартные правила помогают:
- Сохранять единообразный стиль кода
- Уменьшать конфликты имен
- Повышать читаемость кода

## Преимущества соблюдения стандартов

### Для разработчиков адаптеров

- Чёткие правила преобразования
- Единый формат ответов
- Лёгкость отладки и тестирования

### Для разработчиков модулей

- Единый интерфейс событий
- Предсказуемое поведение API
- Упрощение разработки для разных платформ

### Для конечных пользователей

- Стабильное поведение системы
- Единый формат сообщений
- Хорошая совместимость

## Стандартный контрольный список

### Преобразование событий

- [ ] Все стандартные поля корректно сопоставлены
- [ ] Платформенно-специфичные поля имеют префикс
- [ ] Временные метки преобразованы в 10-значные секундные
- [ ] Исходные данные сохранены в {platform}_raw
- [ ] Тип исходного события сохранен в {platform}_raw_type
- [ ] Альтернативное сообщение (alt_message) сегмента сообщения сгенерировано
- [ ] Запрос-события содержат поле request_id

### Ответы API

- [ ] Содержит поле status
- [ ] Содержит поле retcode
- [ ] Содержит поле data
- [ ] Содержит поле message_id
- [ ] Содержит поле message
- [ ] Коды возврата соответствуют спецификации OneBot12

### Именование методов отправки

- [ ] Используется стиль PascalCase
- [ ] Возвращает объект Task
- [ ] Методы-модификаторы возвращают self
- [ ] Именование параметров соответствует стандарту

### Операции запросов

- [ ] Класс HandleRequest реализует _do_accept / _do_reject
- [ ] Операции возвращают стандартный формат ответа API
- [ ] Не поддерживаемые операции возвращают retcode=10002
