## Общее описание

ErisPulse использует OneBot12 в качестве основного стандарта событий и расширяет и уточняет его.

### Основные принципы

1. **Совместимость**: Все стандарты должны быть совместимы со стандартом OneBot12
2. **Расширяемость**: Платформенные функции расширяются с помощью префиксов, чтобы избежать конфликтов
3. **Единообразие**: Ключевые поля, такие как временные метки и форматы ID, должны обрабатываться единообразно
4. **Отслеживаемость**: Сохраняются исходные данные для отладки и устранения проблем

## Почему нужен стандарт?

### 1. Обеспечение совместимости между платформами

Форматы событий на разных платформах различаются, стандартизированный перевод обеспечивает:
- Модульный код нужно писать только один раз, чтобы он работал на всех платформах
- Логика обработки событий остается одинаковой
- Снижение затрат на разработку и сопровождение

### 2. Стандартизация интерфейсов API

Единый формат ответа API обеспечивает:
- Модули могут последовательно обрабатывать ошибки API
- Информация об ошибках унифицирована и легко понимается
- Структура возвращаемых данных остается одинаковой

### 3. Повышение качества кода

Стандартные правила помогают:
- Сохранять единообразный стиль кода
- Снижать количество конфликтов имен
- Повышать читаемость кода

## Преимущества соблюдения стандартов

### Для разработчиков адаптеров

- Четкие правила преобразования
- Единый формат ответов
- Легкость отладки и тестирования

### Для разработчиков модулей

- Единый интерфейс событий
- Предсказуемое поведение API
- Упрощенная разработка для разных платформ

### Для конечных пользователей

- Стабильное поведение системы
- Единый формат сообщений
- Хорошая совместимость

## Стандартная контрольная проверка

### Преобразование событий

- [ ] Все стандартные поля корректно сопоставлены
- [ ] Платформенные специфичные поля имеют префикс
- [ ] Временные метки преобразованы в 10-значные секундные значения
- [ ] Исходные данные сохранены в {platform}_raw
- [ ] Тип исходного события сохранён в {platform}_raw_type
- [ ] Сгенерировано поле alt_message для сегментов сообщений
- [ ] В запросных событиях присутствует поле request_id

### Ответы API

- [ ] Присутствует поле status
- [ ] Присутствует поле retcode
- [ ] Присутствует поле data
- [ ] Присутствует поле message_id
- [ ] Присутствует поле message
- [ ] Коды возврата соответствуют спецификации OneBot12

### Именование методов отправки

- [ ] Используется паскаль-нотация (PascalCase)
- [ ] Возвращается объект Task
- [ ] Модифицирующие методы возвращают self
- [ ] Имена параметров соответствуют стандарту

### Операции запросов

- [ ] Класс HandleRequest реализует _do_accept / _do_reject
- [ ] Операции возвращают стандартный формат ответа API
- [ ] Операции, не поддерживаемые платформой, возвращают retcode=10002
