# Стандартизированный формат возврата адаптера ErisPulse

## 1. Описание  
Почему существует этот стандарт?

Для обеспечения единообразия в ответах интерфейсов отправки сообщений на разных платформах и совместимости с OneBot12, адаптер ErisPulse использует стандартную структуру ответа для отправки сообщений, определённую в OneBot12.

Однако протокол ErisPulse имеет некоторые специфические определения:
- 1. В базовых полях поле message_id обязательно, но в стандарте OneBot12 такого поля нет.
- 2. В ответе необходимо добавить поле {platform_name}_raw, которое используется для хранения необработанных данных ответа.

## 2. Базовая структура ответа
Все ответы на действия должны содержать следующие базовые поля:

| Имя поля | Тип данных | Обязательно | Описание |
|-------|---------|------|------|
| status | string | Да | Статус выполнения, должно быть "ok" или "failed" |
| retcode | int64 | Да | Код возврата, следует правилам кодов возврата OneBot12 |
| data | any | Да | Данные ответа, содержит результат запроса при успехе, null при ошибке |
| message_id | string | Да | Идентификатор сообщения, используется для идентификации сообщения, если нет, пустая строка |
| message | string | Да | Сообщение об ошибке, пустая строка при успехе |
| {platform_name}_raw | any | Нет | Необработанные данные ответа |

Необязательные поля:
| Имя поля | Тип данных | Обязательно | Описание |
|-------|---------|------|------|
| echo | string | Нет | Если в запросе присутствует поле echo, возвращается в том же виде |

## 3. Полный перечень полей

### 3.1 Общие поля

#### Пример успешного ответа
```json
{
    "status": "ok",
    "retcode": 0,
    "data": {
        "message_id": "1234",
        "time": 1632847927.599013
    },
    "message_id": "1234",
    "message": "",
    "echo": "1234",
    "telegram_raw": {...}
}
```

#### Пример неудачного ответа
```json
{
    "status": "failed",
    "retcode": 10003,
    "data": null,
    "message_id": "",
    "message": "Отсутствует обязательный параметр: user_id",
    "echo": "1234",
    "telegram_raw": {...}
}
```

### 3.2 Спецификация кодов возврата

#### 0 Успех (OK)
- 0: Успех (OK)

#### 1xxxx Ошибка запроса действия (Request Error)
| Код ошибки | Название ошибки | Описание |
|-------|-------|------|
| 10001 | Bad Request | Недопустимый запрос действия |
| 10002 | Unsupported Action | Запрос действия не поддерживается |
| 10003 | Bad Param | Недопустимый параметр запроса действия |
| 10004 | Unsupported Param | Параметр запроса действия не поддерживается |
| 10005 | Unsupported Segment | Тип сегмента сообщения не поддерживается |
| 10006 | Bad Segment Data | Недопустимые параметры сегмента сообщения |
| 10007 | Unsupported Segment Data | Параметры сегмента сообщения не поддерживаются |
| 10101 | Who Am I | Не указан аккаунт бота |
| 10102 | Unknown Self | Неизвестный аккаунт бота |

#### 2xxxx Ошибка обработчика действия (Handler Error)
| Код ошибки | Название ошибки | Описание |
|-------|-------|------|
| 20001 | Bad Handler | Ошибка реализации обработчика действия |
| 20002 | Internal Handler Error | Временная ошибка обработчика действия |

#### 3xxxx Ошибка выполнения действия (Execution Error)
| Диапазон кодов ошибки | Тип ошибки | Описание |
|-----------|---------|------|
| 31xxx | Database Error | Ошибка базы данных |
| 32xxx | Filesystem Error | Ошибка файловой системы |
| 33xxx | Network Error | Ошибка сети |
| 34xxx | Platform Error | Ошибка платформы бота |
| 35xxx | Logic Error | Ошибка логики действия |
| 36xxx | I Am Tired | Реализация решила бастовать |

#### Зарезервированные сегменты ошибок
- 4xxxx, 5xxxx: Зарезервированные сегменты, не должны использоваться
- 6xxxx～9xxxx: Другие сегменты ошибок, доступны для пользовательских реализаций

## 4. Требования к реализации
1. Все ответы должны содержать поля status, retcode, data и message
2. При наличии непустого поля echo в запросе ответ должен содержать поле echo с тем же значением
3. Коды возврата должны строго соответствовать спецификации OneBot12
4. Сообщения об ошибках (message) должны быть понятными для человека

## 5. Расширение спецификации

ErisPulse расширяет структуру ответа OneBot12 следующим образом:

### 5.1 Обязательное поле `message_id`

В спецификации OneBot12 поле `message_id` находится внутри объекта `data` и не является обязательным. ErisPulse выносит его в верхний уровень как **обязательное** поле:

- При невозможности получить `message_id` следует установить его в пустую строку `""`
- Обеспечить, чтобы `message_id` всегда существовал, модулям не нужно проверять на null

### 5.2 Поле `{platform}_raw` с исходными ответами

В ответе должно присутствовать поле `{platform}_raw`, содержащее полную копию исходных данных ответа платформы:

```json
{
    "status": "ok",
    "retcode": 0,
    "data": {"message_id": "1234", "time": 1632847927},
    "message_id": "1234",
    "message": "",
    "telegram_raw": {
        "ok": true,
        "result": {"message_id": 1234, "date": 1632847927, ...}
    }
}
```

**Требования**:
- `{platform}_raw` должен быть глубокой копией исходного ответа, а не ссылкой
- `platform` должен полностью совпадать с именем платформы, зарегистрированной в адаптере (регистр чувствителен)
- Ошибки в исходном ответе также должны сохраняться, для облегчения отладки

### 5.3 Расширенные коды возврата фреймворка (34xxx, пользовательские младшие три цифры)

Спецификация OneBot12 позволяет реализациям использовать пользовательские младшие три цифры `3xxxx`. Семантика `34xxx` — **Platform Error** (ошибка платформы, например, из-за ограничений платформы). Внутри `34xxx` используется следующая иерархия:

| Младшие три цифры | Назначение | Использование |
|-------------------|------------|---------------|
| `340xx` | Реализация адаптера | Группа операций запроса (Request Not Found / Already Handled / Not Supported / Permission Denied, см. request-action-spec §7) |
| `341xx`–`345xx` | Реализация адаптера | Ошибки платформы, связанные с правами, рисками, ограничениями аккаунта (реализация определяет младшие три цифры, исходная ошибка сохраняется в `{platform}_raw`) |
| `346xx` | **Фреймворк ErisPulse (зарезервировано)** | Ошибки, возникающие внутри фреймворка, адаптеры/модули не должны использовать |
| `347xx`–`349xx` | Реализация адаптера | Другие ошибки выполнения платформы |

В настоящее время фреймворк ErisPulse использует коды `346xx`:

| Код ошибки | Название ошибки | Описание |
|------------|-----------------|----------|
| 34600 | SDK Failure | Общая ошибка фреймворка (значение по умолчанию `make_error()`) |
| 34601 | Action Denied | Выходящая операция заблокирована в `scope.actions`, вызов не запускается, возвращается этот ответ |

> Разграничение ответственности: `34601` — **блокировка фреймворком до вызова** (модуль не имеет права инициировать действие); `34004` / `34xxx` — **действие уже отправлено, но платформа отклонила** (например, у бота нет прав, он заблокирован). Модули при проверке прав должны учитывать оба случая: сначала проверить `34601` (действие заблокировано в `scope`), затем `34xxx` (платформа запретила).

Структура ответа соответствует стандартному неудачному ответу §2:

```json
{
    "status": "failed",
    "retcode": 34601,
    "data": null,
    "message_id": "",
    "message": "action 'send' denied by scope.actions"
}
```

### 5.5 Проверочный список для реализации адаптера

- [ ] В ответе присутствуют поля `status`, `retcode`, `data`, `message_id`, `message`
- [ ] Код возврата соответствует спецификации OneBot12 (см. §3.2)
- [ ] Поле `message_id` всегда существует (при невозможности получения устанавливается в пустую строку)
- [ ] Поле `{platform}_raw` содержит исходные данные ответа платформы

## 6. Примечания
- Для кодов ошибок 3xxxx последние три цифры могут быть определены реализацией
- Избегайте использования зарезервированных диапазонов ошибок (4xxxx, 5xxxx)
- **`34600` / `34601` зарезервированы для фреймворка ErisPulse** (см. §5.3), адаптеры/модули должны избегать их использования
- Сообщения об ошибках должны быть краткими и понятными, чтобы облегчить отладку
