# Стандарт спецификации возвращаемых значений адаптеров ErisPulse

> [!TIP]
> **Когда нужно читать этот документ**: когда вы реализуете в адаптере возвращаемые значения `call_api` / Send / Request и вам нужно убедиться, что структура ответа и коды возврата соответствуют стандарту ErisPulse, или когда требуется выяснить значение конкретного `retcode` — сверяйтесь с этим документом. Если это не требуется, пропустите.

## 1. Описание
Зачем нужна эта спецификация?

Для обеспечения единообразия возвращаемых значений интерфейсов отправки на различных платформах и совместимости с OneBot12 адаптеры ErisPulse при форматировании ответов API используют стандарт структуры возврата отправки сообщений, определённый в OneBot12.

Однако протокол ErisPulse имеет некоторые особые определения:
- 1. Среди базовых полей message_id является обязательным, но в стандарте OneBot12 такого поля нет
- 2. В возвращаемое содержимое необходимо добавить поле {platform_name}_raw для хранения исходных данных ответа

## 2. Базовая структура ответа
Все ответы на действия должны содержать следующие базовые поля:

| Имя поля | Тип данных | Обязательное | Описание |
|-------|---------|------|------|
| status | string | Да | Статус выполнения, должен быть "ok" или "failed" |
| retcode | int64 | Да | Код возврата, следует правилам кодов возврата OneBot12 |
| data | any | Да | Данные ответа; при успехе содержит результат запроса, при неудаче — null |
| message_id | string | Да | ID сообщения для идентификации сообщения; если отсутствует — пустая строка |
| message | string | Да | Сообщение об ошибке; при успехе — пустая строка |
| {platform_name}_raw | any | Нет | Исходные данные ответа |

Необязательные поля:
| Имя поля | Тип данных | Обязательное | Описание |
|-------|---------|------|------|
| echo | string | Нет | Если запрос содержит поле echo, возвращается в неизменном виде |

## 3. Полная спецификация полей

### 3.1 Общие поля

#### Пример успешного ответа
```json
{
    "status": "ok",
    "retcode": 0,
    "data": {
        "message_id": "1234",
        "time": 1632847927.599013
    },
    "message_id": "1234",
    "message": "",
    "echo": "1234",
    "telegram_raw": {...}
}
```

#### Пример ответа при ошибке
```json
{
    "status": "failed",
    "retcode": 10003,
    "data": null,
    "message_id": "",
    "message": "Отсутствует обязательный параметр: user_id",
    "echo": "1234",
    "telegram_raw": {...}
}
```

### 3.2 Спецификация кодов возврата

#### 0 Успех (OK)
- 0: Успех (OK)

#### 1xxxx Ошибка запроса действия (Request Error)
| Код ошибки | Название ошибки | Описание |
|-------|-------|------|
| 10001 | Bad Request | Некорректный запрос действия |
| 10002 | Unsupported Action | Неподдерживаемый запрос действия |
| 10003 | Bad Param | Некорректные параметры запроса действия |
| 10004 | Unsupported Param | Неподдерживаемые параметры запроса действия |
| 10005 | Unsupported Segment | Неподдерживаемый тип сегмента сообщения |
| 10006 | Bad Segment Data | Некорректные данные сегмента сообщения |
| 10007 | Unsupported Segment Data | Неподдерживаемые данные сегмента сообщения |
| 10101 | Who Am I | Не указан аккаунт бота |
| 10102 | Unknown Self | Неизвестный аккаунт бота |

#### 2xxxx Ошибка обработчика действия (Handler Error)
| Код ошибки | Название ошибки | Описание |
|-------|-------|------|
| 20001 | Bad Handler | Ошибка реализации обработчика действия |
| 20002 | Internal Handler Error | Исключение, возникшее во время выполнения обработчика действия |

#### 3xxxx Ошибка выполнения действия (Execution Error)
| Диапазон кодов ошибок | Тип ошибки | Описание |
|-----------|---------|------|
| 31xxx | Database Error | Ошибка базы данных |
| 32xxx | Filesystem Error | Ошибка файловой системы |
| 33xxx | Network Error | Сетевая ошибка |
| 34xxx | Platform Error | Ошибка платформы бота |
| 35xxx | Logic Error | Ошибка логики действия |
| 36xxx | I Am Tired | Реализация решила устроить забастовку |

#### Зарезервированные диапазоны ошибок
- 4xxxx, 5xxxx: зарезервированные диапазоны, использовать не следует
- 6xxxx–9xxxx: прочие диапазоны ошибок, предназначены для пользовательских определений реализации

## 4. Требования к реализации
1. Все ответы должны содержать поля status, retcode, data и message
2. Если запрос содержит непустое поле echo, ответ должен содержать поле echo с тем же значением
3. Коды возврата должны строго соответствовать спецификации OneBot12
4. Сообщение об ошибке (message) должно быть человекочитаемым описанием

## 5. Спецификация расширений

ErisPulse вносит следующие расширения поверх стандартной структуры возврата OneBot12:

### 5.1 Обязательное поле `message_id`

В стандарте OneBot12 `message_id` находится внутри объекта `data` и не является обязательным. ErisPulse повышает его до **обязательного** поля верхнего уровня:

- Если `message_id` получить невозможно, следует установить пустую строку `""`
- Гарантирует, что `message_id` всегда присутствует, и модулям не нужно выполнять проверку на null

> **Различайте эти две стороны**: повышение до верхнего уровня в данном разделе относится только к **ответам на действия** (исходящим). `message_id` во входящих **событиях** message — это обязательное поле верхнего уровня согласно базовой спецификации OneBot12, см. [стандарт преобразования событий](event-conversion.md).

### 5.2 Поле исходного ответа `{platform}_raw`

Возвращаемое значение должно содержать поле `{platform}_raw`, в котором хранится полная копия исходных данных ответа платформы:

```json
{
    "status": "ok",
    "retcode": 0,
    "data": {"message_id": "1234", "time": 1632847927},
    "message_id": "1234",
    "message": "",
    "telegram_raw": {
        "ok": true,
        "result": {"message_id": 1234, "date": 1632847927, ...}
    }
}
```

**Требования**:
- `{platform}_raw` должен быть глубокой копией исходного ответа, а не ссылкой
- `platform` должен полностью совпадать с именем платформы, указанным при регистрации адаптера (с учётом регистра)
- Информация об ошибках в исходном ответе также должна сохраняться для упрощения отладки

### 5.3 Коды возврата расширений фреймворка (пользовательские младшие три цифры в диапазоне ошибок платформы 34xxx)

Спецификация OneBot12 позволяет реализациям определять собственные младшие три цифры для `3xxxx`. Семантика `34xxx` — **Platform Error**
(ошибка платформы бота, например сбой из-за ограничений платформы). Внутри `34xxx` использование разделено по уровням ответственности:

| Диапазон младших трёх цифр | Принадлежность | Назначение |
|---------|------|------|
| `340xx` | Реализация адаптера | Семейство операций запроса (Request Not Found / Already Handled / Not Supported / Permission Denied, см. request-action-spec §7) |
| `341xx`–`345xx` | Реализация адаптера | Ошибки на стороне платформы: права доступа / антифрод / ограничения аккаунта и т.п. (младшие три цифры определяет реализация, исходная ошибка помещается в `{platform}_raw`) |
| `346xx` | **Фреймворк ErisPulse (зарезервировано)** | Перехват самим фреймворком и общие сбои; адаптерам/модулям не следует занимать этот диапазон |
| `347xx`–`349xx` | Реализация адаптера | Прочие ошибки выполнения на стороне платформы |

Коды `346xx`, используемые в настоящее время фреймворком ErisPulse:

| Код ошибки | Название ошибки | Описание |
|-------|-------|------|
| 34600 | SDK Failure | Общий сбой фреймворка (код возврата по умолчанию для `make_error()`) |
| 34601 | Action Denied | Исходящее действие отключено скоупом (`scope.actions`), вызов не был инициирован, данный ответ возвращается сразу |

> Разделение ответственности: `34601` — это **перехват фреймворком до вызова** (модуль вообще не имеет права инициировать действие);
> `34004` / `34xxx` — платформенные коды означают, что **действие было отправлено, но отклонено платформой** (например, у Bot нет прав доступа, сработал антифрод).
> При диагностике проблем с правами модуль должен проверять оба варианта: сначала `34601` (собственный модуль заблокирован scope),
> затем `34xxx` (ограничения на стороне платформы).

Структура возврата — стандартный ответ об ошибке из §2:

```json
{
    "status": "failed",
    "retcode": 34601,
    "data": null,
    "message_id": "",
    "message": "action 'send' denied by scope.actions"
}
```

### 5.4 Контрольный список для реализации адаптера

- [ ] Содержит поля `status`, `retcode`, `data`, `message_id`, `message`
- [ ] Коды возврата соответствуют спецификации OneBot12 (подробнее в §3.2)
- [ ] `message_id` всегда присутствует (если получить невозможно — пустая строка)
- [ ] `{platform}_raw` содержит исходные данные ответа платформы

## 6. Примечания
- Для кодов ошибок 3xxxx младшие три цифры могут определяться реализацией самостоятельно
- Избегайте использования зарезервированных диапазонов ошибок (4xxxx, 5xxxx)
- **`34600` / `34601` — зарезервированные коды фреймворка ErisPulse** (см. §5.3), адаптерам/модулям следует избегать их использования
- Сообщения об ошибках должны быть краткими и ясными для упрощения отладки
