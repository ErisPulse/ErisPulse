# ErisPulse-Takumi

[ErisPulse-Takumi](https://pypi.org/project/ErisPulse-Takumi/) — это **модуль для рендеринга изображений**, поддерживаемый ccd2s. Базируясь на [takumi-py](https://github.com/BalconyJH/takumi-py), он позволяет рендерить изображения в ваших ботах: HTML, дерево узлов, шаблоны Jinja, SVG, анимация — всё это под силу. Также **встроены шрифты** (Noto Sans SC / Roboto / Source Code Pro), без необходимости дополнительной настройки шрифтов.

> [!IMPORTANT]
> Takumi **не является** встроенной функцией фреймворка ErisPulse, его необходимо устанавливать отдельно:
>
> ```bash
> epsdk install Takumi
> ```

Отлично подходит для следующих сценариев:

- Отображение данных / статистики в виде красивых карточек
- Преобразование Markdown / длинного текста в изображения с фиксированной типографикой для избежания различий стилей на платформах
- Генерация SVG / анимации для создания динамических визуальных эффектов
- Вывод изображений и текста на русском и английском языках (встроенные шрифты готовы к использованию)

## Быстрый старт

После автоматической загрузки модулей вы можете получить их через менеджер модулей или с помощью сокращённого метода `sdk`:

```python
from ErisPulse import sdk

takumi = sdk.module.get("Takumi")
# Эквивалентная запись: takumi = sdk.Takumi
```

### Рендеринг HTML

Самый распространённый способ — отрендерить строку HTML + CSS в PNG:

```python
png = takumi.render_html(
    """
    <div class="card">
      <h1>Привет, ErisPulse</h1>
      <p>Рендеринг с помощью Takumi</p>
    </div>
    """,
    stylesheets=["""
    .card {
      width: 800px;
      height: 400px;
      padding: 48px;
      color: white;
      background: #111827;
      font-family: "Noto Sans SC";
    }
    """],
    width=800,
    height=400,
    lang="zh-CN",
)
```

`png` — это `bytes`, которое можно отправить через `event.reply(png, method="Image")` (подробнее см. [Отправка результата рендеринга](#отправка-результата-рендеринга)).

### Рендеринг дерева узлов

Не нужно вручную писать HTML — достаточно описать структуру словарём, это подходит для программной сборки:

```python
png = takumi.render_node(
    {
        "type": "text",
        "text": "Поддерживается китайский и английский",
        "style": {"fontSize": 48, "color": "#111827"},
    },
    width=800,
    height=200,
    lang="zh-CN",
)

## Шрифты и Рендереры

### Встроенные шрифты

В Takumi уже включены популярные шрифты, дополнительные установки не требуются:

| Ресурс | Описание |
|------|------|
| `takumi.fonts` | Список имен встроенных шрифтовых файлов |
| `takumi.families` | Список зарегистрированных семейств шрифтов |

Удобные методы (`render_html` / `render_node`) автоматически внедряют этот стек резервных шрифтов; если вы напрямую вызываете базовый рендерер, необходимо передать его вручную `font_families`.

### Нативный Renderer

`takumi.renderer` — это исходный экземпляр `takumi_py.Renderer`. Удобные методы автоматически внедряют стек резервных шрифтов; **при прямом вызове рендерера необходимо самостоятельно передать `families`**:

```python
png = takumi.renderer.render_html(
    "<div>Привет</div>",
    font_families=takumi.families,
    lang="zh-CN",
)
```

### Изолированный Renderer

Если требуется изолировать кэш шрифтов / изображений / ресурсов (например, для процессов с длительным жизненным циклом или многоарендаторных сценариев), можно создать новый `Renderer`, встроенные шрифты будут автоматически зарегистрированы:

```python
renderer = takumi.create_renderer(cache_max_bytes=64 * 1024 * 1024)

png = renderer.render_html(
    "<div>Изолированный Renderer</div>",
    font_families=takumi.families,
    width=800,
    height=200,
    lang="zh-CN",
)
```

`create_renderer()` принимает конструктивные аргументы `takumi_py.Renderer`:

- `load_default_fonts=False` (по умолчанию): загружает только встроенные шрифты
- `load_default_fonts=True`: загружает встроенные шрифты Takumi
- `fonts=[...]`: регистрирует кастомные шрифты поверх базовых

> Изолированные экземпляры проходят через отдельный прокси модуля, поэтому для сохранения единого стека резервных шрифтов необходимо явно передать `font_families=takumi.families`.

Если явно передать `font_families`, модуль будет уважать настройки вызывающего объекта и перестанет внедрять стек резервных шрифтов по умолчанию. `RenderOptions(font_families=...)` также работает.

## Отправка результатов рендеринга

После получения изображения через рендеринг, его можно отправить напрямую через событие ответа:

```python
from ErisPulse import sdk

takumi = sdk.Takumi
png = takumi.render_html("<div>hello</div>", lang="ru-CN")

# Способ 1: Отвечать напрямую методом Image
await event.reply(png, method="Image")

# Способ 2: Отвечать через сегмент сообщения OneBot12
from ErisPulse.Core.Event import MessageBuilder
await event.reply_ob12(
    MessageBuilder().image(png).build()
)
```

> Различная инкапсуляция изображений на разных платформах обрабатывается адаптером, о ней беспокоиться не нужно. Подробнее см. [Руководство по MessageBuilder](../ru/advanced/message-builder.md) и [Спецификация методов отправки](../ru/standards/send-method-spec.md).

## Важные советы и подводные камни (извлеченные на собственной шкуре)

В следующих документах этого нет, но я записал, шаг за шагом проверяя при работе с Takumi над модулем полной визуализации данных (радары, эхолоты и т.п., с десятками узлов и линиями связи). Выделил ценные моменты, чтобы сэкономить часы проб и ошибок.

### 1. Не используйте SVG `<text>`, он не отрисовывается

Самая большая ловушка, безальтернативная. Вы хотите нарисовать узлы в `<svg>` и подписать их именем через `<text>` — **полученный текст будет пустым**. Не имеет значения, задаете ли вы `font-family` для `<text>` или устанавливаете наследование на корневом элементе `<svg>` — текст не отображается ни на китайском, ни на английском, на картинке остаются только голые фигуры.

Практический вывод: `takumi-py` не рисует текстовые элементы встроенного SVG. Поэтому правильный подход следующий:

- В SVG рисуйте только **фигуры** (круги, линии, полигоны)
- Текст всегда в **HTML**: поместите `<svg>` в контейнер с `position: relative`, а затем используйте абсолютно позиционированный `<div>` для меток поверх соответствующих координат.

```python
W = H = 600
html = f"""
<div style='position:relative;width:{W}px;height:{H}px'>
  <svg width='{W}' height='{H}' viewBox='0 0 {W} {H}'>
    <!-- Рисуем только круги и линии -->
  </svg>
  <div style='position:absolute;left:{x}px;top:{y}px;transform:translate(-50%,-50%)'>Имя</div>
</div>
"""
```

Условие совпадения координат: SVG должен использовать **фиксированный** `width`/`height` (не экономьте и не пишите `width:100%`), тогда пиксели и контейнер сопоставляются 1:1, и значения `left`/`top` для div можно просто подставлять из координат SVG.

### 2. CSS должен идти через `stylesheets`, не вставляйте целый документ HTML

Первый аргумент функции `render_html(html, ...)` — это **основной HTML**, а не полный документ. Если вы, чтобы сэкономить время, передадите такой код:

```python
takumi.render_html("<!DOCTYPE html><html><head><style>...</style></head><body>...</body></html>")
```

Стили **тихо перестанут работать** — картинка все равно выйдет, но будет выглядеть так, будто CSS нет, всё будет криво. При отладке вы можете заподозрить, что неправильно написали CSS, но на самом деле проблема в способе передачи. Обидно.

Правильный подход всегда такой: отдельный параметр для основного контента и отдельный параметр для CSS.

```python
takumi.render_html(body_html, stylesheets=[css_str], width=..., height=..., lang="zh-CN")
```

### 3. `height` — это высота обрезки, она не растягивается автоматически

`width` — это ширина области просмотра, а `height` — высота холста — **содержимое, превышающее `height`, просто обрежется**, оно не расширится вниз, как в браузере. Поэтому общую высоту нужно оценивать самостоятельно: сложите высоту каждого блока + отступы + расстояние между карточками и передайте это значение.

Опыт подсказывает: **лучше с избытком**. Лишние несколько десятков пикселей пустого места снизу никто не проверит, а если верхнюю часть содержимого обрежут — картинка станет бесполезной. При динамическом контенте (количество элементов в списке непостоянно) считайте на лету:

```python
height = padding * 2 + header_h + sum(высота_каждой_позиции) + gap * (количество_позиций - 1) + 30  # оставим запас на конце
```

### 4. Автоинъекция шрифтов работает только для HTML текста

Удобные методы (например, `render_html` / `render_node`) автоматически подставляют стек отступов встроенных шрифтов, но **это работает только для HTML текста**. Поэтому первый пункт о том, что «текст через HTML» имеет и этот плюс — вы бесплатно получаете поддержку китайских шрифтов, не беспокоясь о настройке `font_families`.

Если вы вызываете базовый рендерер напрямую (`takumi.renderer.render_html`), вам придется передать `font_families=takumi.families` самостоятельно, не забудьте.

### 5. Маленький трюк для отладки без глаз

Вы изменили стили и хотите проверить, действительно ли отрисовался конкретный кусок китайского текста, но не хотите открывать картинку каждый раз? Пусть он выдаст исходные пиксели, чтобы пересчитать:

```python
data = takumi.render_html(body, stylesheets=[css], width=W, height=H,
                          lang="zh-CN", format="raw")  # raw — это байтовый поток RGBA
dark = sum(1 for i in range(0, len(data), 4)
           if data[i] < 120 and data[i+1] < 120 and data[i+2] < 120 and data[i+3] > 128)
```

На светлом фоне разница между «есть текст» (значение около 4000+) и «нет текста» (0) очевидна невооруженным глазом. Это намного быстрее, чем разглядывать PNG. Так я и проверил ловушку с SVG в пункте 1.

### 6. Темы (светлая/темная): просто смените набор stylesheet

Сам Takumi не заботится о вашей теме, все цвета — в вашем CSS. Поэтому переключение между светлой и темной темой очень легкое — подготавливаете два набора цветов и в зависимости от текущего часа или настроек пользователя выбираете один и вставляете в `stylesheets`:

```python
if 19 <= local_hour or local_hour < 7:
    t = {"page": "#000000", "card": "#1c1c1e", "ink": "#f5f5f7", "sep": "#38383a"}   # Темная
else:
    t = {"page": "#f5f5f7", "card": "#ffffff", "ink": "#1d1d1f", "sep": "#e5e5ea"}   # Светлая
css = CSS_TEMPLATE.replace("__INK__", t["ink"]).replace("__CARD__", t["card"])  # и так далее
```

> Небольшое напоминание: CSS-переменные, встроенные в `var(--xxx)`, в takumi **не обязательно поддерживаются**. Чтобы гарантировать стабильность, лучше просто заменять строку цвета прямо в шаблоне на Python, обойдя эту неопределенность.
