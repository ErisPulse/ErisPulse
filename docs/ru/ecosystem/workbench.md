# ErisPulse Workbench

> [!TIP]
> **Когда читать эту статью**: когда вы хотите отправить модуль/адаптер в магазин модулей, подать заявку на получение адреса сайта `plugin-xxx.erisdev.com`, автоматически отправить модуль через скрипты или CI, или добавить на свой сайт поддержку входа с помощью аккаунта ErisPulse. Если не нужно, пропустите эту статью.

[ErisPulse Workbench](https://workbench.erisdev.com/) — это централизованная система аккаунтов и панель разработчика экосистемы: один аккаунт объединяет магазин модулей, доменные имена и открытые интерфейсы. Это полностью онлайн-сервис, **не требующий установки каких-либо пакетов** — просто откройте веб-страницу и войдите.

```text
Вход через GitHub / Codeberg / Юньху / электронную почту
            │
            ▼
      Аккаунт ErisPulse ──── Двухфакторная аутентификация (по желанию)
            │
   ┌────────┼─────────────┬──────────────┐
   ▼        ▼             ▼              ▼
Управление модулями   Доменные имена   Токены доступа   OAuth-приложения
(магазин)          (адрес сайта)     (скрипты/CI)    (вход для сторонних приложений)
```

## Вход и аккаунт

Workbench поддерживает четыре способа входа, не настроенные способы не отображаются на странице входа:

| Способ | Сценарий использования |
|-------|------------------------|
| GitHub | Авторы модулей, код которых размещён на GitHub |
| Codeberg | Авторы модулей, код которых размещён на Codeberg |
| Юньху | Пользователи платформы Юньху |
| Электронная почта | Пользователи без вышеуказанных аккаунтов: имя пользователя + почта + пароль, при регистрации необходимо ввести 6-значный код из письма |

> [!NOTE]
> Один аккаунт может быть привязан к нескольким способам входа на странице «Профиль». При входе через разные способы они объединяются, и в дальнейшем можно войти с любого способа.

**Двухфакторная аутентификация**: на странице «Профиль» можно включить двухфакторную аутентификацию на основе динамических паролей (TOTP), отсканировав QR-код в любом приложении-аутентификаторе. После включения для входа и выполнения чувствительных действ, таких как удаление модуля или домена, потребуется ввод динамического кода.

> [!WARNING]
> Ключ динамического пароля **показывается только один раз при включении**. При потере ключа вход невозможен, поэтому необходимо надёжно сохранить его.

## Управление модулями

Все модули и адаптеры, размещённые в магазине модулей, управляются в Workbench.

### Отправка модуля

1. Перейдите в «Отправить новый модуль» слева
2. Заполните форму:

| Поле | Описание |
|------|----------|
| Название | Название модуля, совпадает с ключом entry-point |
| Тип | `module` (функциональный модуль) или `adapter` (адаптер) |
| Имя пакета PyPI | Например, `ErisPulse-MyModule` |
| Описание | Не менее 10 символов |
| Автор | Имя автора, отображаемое в магазине |
| Адрес репозитория | Репозиторий на `github.com` или `codeberg.org` |
| Категория | Инструменты / Развлечения / Управление / Уведомления / ИИ / Платформа / Анализ |
| Теги, многоязычность, минимальная версия SDK | Необязательно |

3. После отправки модуль появится в магазине в течение нескольких минут после обновления индекса модулей.

Новый отправленный модуль сначала имеет статус «Не проверено» — это означает, что он ещё не прошёл официальную проверку, и при установке пользователи получат предупреждение о риске. После прохождения проверки статус изменится на «Проверено».

### Редактирование и пакетные операции

На странице «Список модулей» перейдите на страницу деталей своего модуля, где можно изменить описание, адрес репозитория, категорию, теги и другие метаданные, загрузить иконку модуля; также можно перейти в режим множественного выбора и выполнить **пакетное подтверждение / отмену подтверждения / удаление** (для пакетных операций требуется вводить динамический код только один раз).

### Привязка модуля

Модули, уже присутствующие в магазине, но не отправленные вами (например, ранее добавленные кем-то другим), можно привязать к вашему аккаунту:

- **Автоматическая привязка**: при входе с аккаунтом GitHub / Codeberg, совпадающим с репозиторием модуля, система автоматически завершает привязку при обнаружении совпадения владельца репозитория.
- **Ручная привязка**: на странице деталей модуля нажмите «Привязать этот модуль» и укажите причину, после чего администратор проверит и завершит перенос.

## Доменные имена

Каждый модуль, добавленный в магазин, может получить бесплатный адрес сайта вида `plugin-модуль.erisdev.com`, который можно использовать для размещения главной страницы, документации или демонстрационного сайта модуля.

| Ограничение | Значение |
|-------------|----------|
| На один модуль | 2 доменных имени |
| На один аккаунт | 10 доменных имен |
| Непроверенные | Через 7 дней освобождаются, доменные имена могут быть снова запрошены другими |

### Четыре способа подключения

| Способ | Как использовать | Подходит для |
|--------|------------------|--------------|
| **Ветка репозитория** (рекомендуется) | Укажите адрес репозитория и имя ветки, Workbench будет считывать статические файлы из этой ветки | Статический сайт находится в репозитории модуля, обновление происходит при отправке изменений |
| **Перенаправление** | При обращении к доменному имени происходит перенаправление 301 на указанный вами `https://` адрес | У вас уже есть собственный сайт, и вы хотите получить удобный адрес |
| **Собственный сервер** | Добавьте запись CNAME / A / AAAA и укажите ваш сервер | Вы сами развернули сайт |
| Загрузка статического сайта | Загрузите zip-архив, платформа будет хостить его с помощью объектного хранилища | В настоящее время доступно только для внутреннего тестирования, не полностью открыто для публики |

Для способа «Ветка репозитория» имя ветки по умолчанию — `ep-site` — общепринятое имя для ветки сайта, рекомендуется размещать файлы сайта в этой отдельной ветке, чтобы не загрязнять основную ветку кода.

### Процесс подачи заявки

1. Перейдите в «Доменные имена» слева, выберите модуль (можно только модули, принадлежащие вам)
2. Укажите префикс, он проверяется в реальном времени на доступность. Префикс может содержать только строчные буквы, цифры и дефисы
3. Выберите способ подключения и укажите соответствующую информацию, затем отправьте заявку

**Правила проверки**: **Первое доменное имя** модуля активируется сразу; начиная с второго, требуется проверка администратором, результат будет отправлен по электронной почте.

### Проверка прав собственности

Для предотвращения неправомерного использования доменных имён, указанных на репозитории или серверы, способы «Ветка репозитория» и «Собственный сервер» требуют проверки прав собственности:

| Способ | Метод проверки |
|--------|----------------|
| Ветка репозитория | Разместите файл `erisdev-site-verify.txt` в корне указанной ветки, содержимое файла — это код подтверждения, предоставленный Workbench |
| Собственный сервер | На вашем сервере предоставьте файл `/.well-known/erisdev-verify.txt`, содержимое файла — то же самое |

После размещения файла вернитесь в Workbench и нажмите «Завершить проверку». До прохождения проверки при обращении к доменному имени будет отображаться страница с предупреждением «Ожидание проверки прав собственности».

### Управление доменами

На каждой карточке доменного имени можно:

- **Приостановить / Возобновить**: при приостановке при обращении будет отображаться «Сайт приостановлен», содержимое сохраняется
- **Удалить**: освободить доменное имя и все связанные с ним ресурсы, требуется ввод динамического кода
- **Изменить репозиторий или ветку**: после изменения карточка переходит в состояние ожидания проверки, после повторной проверки изменения вступают в силу

## Открытые интерфейсы

Workbench также является сервером OAuth 2.0, предоставляющим два типа возможностей.

### Токены доступа

При вызове интерфейсов Workbench из скриптов или CI (например, для автоматической отправки модуля) токены доступа используются вместо логина и пароля:

1. Перейдите в «Открытая платформа → Токены доступа», введите имя и нажмите «Создать токен»
2. Токен имеет формат `epat_` + 40 шестнадцатеричных символов, **показывается только один раз при создании**
3. При запросе добавьте токен в заголовок `Authorization: Bearer epat_…`

На один аккаунт можно создать максимум 10 токенов. Если у аккаунта включена двухфакторная аутентификация, можно установить флажок «Без динамического кода» — при использовании этого токена для вызова чувствительных интерфейсов больше не потребуется динамический код, что подходит для CI без участия человека.

> [!TIP]
> Тело запроса должно быть в кодировке UTF-8. В Windows терминал по умолчанию использует GBK, и отправка китайских символов будет отклонена сервером — сначала выполните `chcp 65001`, или сохраните тело запроса в файл и отправьте с помощью `curl --data-binary @body.json`.

### OAuth-приложения

Если вы хотите, чтобы ваш сайт или инструмент поддерживал вход с аккаунтом ErisPulse:

1. Перейдите в «Открытая платформа», зарегистрируйте приложение: укажите имя и адрес обратного вызова (может быть несколько)
2. Получите `client_id` и `client_secret` — **ключи отображаются только один раз**, их можно перегенерировать в любое время
3. Подключитесь по стандартному протоколу OAuth 2.0:

| Эндпоинт | Назначение |
|----------|------------|
| `/oauth/authorize` | Перенаправление пользователя на авторизацию |
| `/oauth/token` | Получение токена по коду авторизации |
| `/api/userinfo` | Получение информации о пользователе (без электронной почты) по токену |

На один аккаунт можно зарегистрировать максимум 5 приложений.

## Часто задаваемые вопросы

### Почему модуль не появился в магазине сразу после отправки?

Публикация модуля происходит асинхронно через индекс модулей, обычно она происходит в течение нескольких минут. Вы можете проверить статус операции в списке модулей, если отображается «Применено», значит, всё успешно.

### Почему проверка доменного имени не проходит?

Убедитесь, что **путь и содержимое** файла проверки полностью совпадают с тем, что показано в Workbench (путь чувствителен к регистру, содержимое не должно содержать лишних пробелов или переносов строк). При способе «Ветка репозитория» также необходимо убедиться, что файл находится в **указанной вами ветке**.

### Через сколько времени доменное имя становится активным после заявки?

Для способов «Ветка репозитория» и «Перенаправление» активация происходит сразу после прохождения проверки. Для способа «Собственный сервер» требуется время на распространение DNS-записей по всему миру, обычно это занимает несколько минут.
