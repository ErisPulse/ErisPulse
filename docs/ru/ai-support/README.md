# AI-ассистированная разработка

ErisPulse предоставляет предварительно созданные документы для ИИ, которые вы можете использовать в качестве контекста для генерации кода модулей и адаптеров в соответствии со спецификациями фреймворка.

## Документация по материалам

Документация по материалам находится в подкаталоге `prompts/` этого каталога и разделена на три вида в зависимости от сценария разработки:

| Документ | Сценарий | Масштаб | Описание |
|---------|----------|---------|--------|
| **ErisPulse-ModuleDev.md** | Разработка модулей | Средний | Охватывает весь процесс разработки модулей, подходит для большинства сценариев |
| **ErisPulse-AdapterDev.md** | Разработка адаптеров | Средний | Охватывает весь процесс разработки адаптеров, включая стандарты адаптации платформ |
| **ErisPulse-Full.md** | Полный справочник | Большой | Полное собрание документации по разработке, требует модели с большим окном контекста |

### Охват содержания каждого документа

**ModuleDev** включает: основные понятия, введение в обработку событий, основные концепции модулей, подробное описание класса-обертки Event, Conversation многократный диалог, MessageBuilder, систему маршрутизации, управление жизненным циклом, систему ленивой загрузки, стандарты типов сессий, процесс публикации модуля.

**AdapterDev** включает: вышеуказанные основные элементы, а также основные концепции адаптеров, SendDSL цепочечный вызов, дизайн конвертера событий, три технических стандарта: преобразование событий, API-ответы и методы отправки, полное руководство по адаптации платформ, стандарты документирования строк.

**Full** включает: все вышеперечисленное, а также полное руководство для пользователей (установка, настройка, развертывание), полную справочную документацию по API, отслеживание известных проблем. Рекомендуется использовать только для моделей с окном контекста >= 128K токенов.

### Получение последней версии

Документация по материалам автоматически обновляется вместе с выпуском фреймворка. Способы получения:

- Непосредственно из каталога `prompts/` (обновляется синхронно с документацией)
- Скачать соответствующую версию с [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases)

## Инструкции по использованию

### 1. Выбор документации по материалам

Выберите подходящий документ в зависимости от вашей цели разработки:

- Разработка функционального модуля → `ErisPulse-ModuleDev.md`
- Разработка платформенного адаптера → `ErisPulse-AdapterDev.md`
- Несколько или сложные задачи → `ErisPulse-Full.md` (убедитесь, что у модели достаточно большой размер окна контекста)

### 2. Предоставление контекста

Передайте содержимое выбранного документа ИИ, в зависимости от используемого инструмента:

- **Интегрированные ИИ в IDE (Copilot / Cursor)**: добавьте документ в рабочую область или вставьте в диалог
- **Диалоговые ИИ (ChatGPT / Claude)**: вставьте содержимое документа в начало диалога и укажите "Пожалуйста, ответьте, используя следующий документ как базу знаний"
- **API-вызовы**: вставьте документ в качестве system message или контекста

### 3. Написание описания требований

Используйте шаблоны ниже для описания ваших требований, заполните их и отправьте ИИ. Чем более конкретное описание, тем выше качество генерации.

### 4. Проверка сгенерированного результата

После получения кода от ИИ рекомендуется:

1. Проверить, правильно ли наследуется базовый класс (`BaseModule` или `BaseAdapter`)
2. Убедиться, что обработчики событий используют правильные декораторы (`@message.on_message` и т.д.)
3. Выполнить команду `epsdk create module` или `epsdk create adapter` для создания проектной структуры и вставить сгенерированный код в соответствующие файлы
4. Запустить тесты для проверки корректности функциональности

## Часто задаваемые вопросы

**Какие ИИ-инструменты рекомендуется использовать?**

- Инструменты с интеграцией в IDE: Cursor, VS Code + Copilot — можно напрямую управлять файловой системой, подходит для проектов
- Диалоговые инструменты: ChatGPT, Claude — подходит для быстрого прототипирования и генерации отдельных файлов
- Использование через API: подходит для массовой генерации или сценариев CI/CD

**Что делать, если сгенерированный код не соответствует ожиданиям?**

1. Убедитесь, что предоставлены полные и корректные документы по материалам
2. Добавьте больше деталей в описание требований (конкретные примеры входных и выходных данных, граничные условия и т.д.)
3. Попросите ИИ генерировать код поэтапно: сначала сгенерируйте структуру, убедитесь, что она корректна, затем постепенно добавляйте функциональность
4. Используйте примеры кода из каталога [examples/](../../examples/), добавьте их в качестве дополнительного контекста

**Как повысить качество генерации?**

- Укажите в требованиях имя модуля и базовый класс, от которого он должен наследоваться
- Предоставьте конкретные примеры форматов сообщений (исходный формат события платформы → ожидаемый формат OB12)
- Попросите ИИ сгенерировать тестовый код вместе с основным кодом
- Для адаптеров предоставьте ключевые интерфейсы API платформы в качестве дополнительного контекста
