# AI-помощь в разработке

ErisPulse предоставляет два взаимодополняющих способа AI-помощи в разработке, которые позволяют генерировать код на основе последних спецификаций фреймворка:

- **Документация по материалам**: большой Markdown-файл, загружаемый в контекст единовременно, подходит для разработки целого проекта
- **MCP-сервер**: позволяет AI по запросу извлекать официальную документацию, подходит для повседневного дополнения кода и поиска API

| | Документация по материалам | MCP-сервер |
|---|---|---|
| Формат | Один большой Markdown-файл, **загружаемый единовременно** | AI **по запросу извлекает** |
| Стоимость контекста | Высокая (занимает токены) | Низкая (извлекаются только соответствующие фрагменты) |
| Свежесть | Обновляется вместе с выпуском версии | Реальное время (извлечение из GitHub + кэширование) |
| Подходит для | Проекты с большим окном контекста, разработка целого проекта | Повседневное дополнение кода, поиск API |
| Клиент | Любой AI-инструмент | Только клиенты, поддерживающие MCP |

Оба метода не противоречат друг другу: при разработке крупных проектов можно использовать их одновременно — документация по материалам в качестве основы, а MCP-сервер для выявления недостатков.

## Документация по материалам

Документация по материалам находится в каталоге `prompts/` и разделена на три типа в зависимости от сценария разработки:

| Документ | Сценарий | Описание |
|----------|----------|----------|
| **ErisPulse-ModuleDev.md** | Разработка модуля | Охватывает весь процесс разработки модуля (обработка событий, маршрутизация, жизненный цикл и т.д.) |
| **ErisPulse-AdapterDev.md** | Разработка адаптера | На основе разработки модуля, дополнительно включает основные концепции адаптера, SendDSL, руководство по адаптации платформы |
| **ErisPulse-Full.md** | Полное руководство | Все вышеперечисленное + полное руководство пользователя и сводка API |

Способы получения: напрямую из каталога `prompts/` (с синхронизированными обновлениями), или загрузите нужную версию с [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases).

### Способы использования

1. Выберите документ в соответствии с целью (модуль → `ModuleDev`, адаптер → `AdapterDev`, сложные задачи → `Full`)
2. Предоставьте содержимое документа в качестве контекста для ИИ: поместите в рабочую область IDE, вставьте в диалог, или передайте через system message при вызове API
3. Используйте шаблон описания задачи ниже, чем конкретнее описание, тем выше качество генерации

### Шаблон описания задачи

**Модуль:**

```
Пожалуйста, на основе спецификации разработки модуля ErisPulse, сгенерируйте полный код модуля [название модуля].

Описание функции: [основная функция]
События, которые нужно отслеживать: [сообщение / команда / уведомление / запрос], логика обработки: [операция]
Необходимые параметры конфигурации: [ключ]: [назначение] ([обязательный/необязательный], значение по умолчанию: [значение])
Дополнительные требования: [дополнительные ограничения]
```

**Адаптер:**

```
Пожалуйста, на основе спецификации разработки адаптера ErisPulse, сгенерируйте полный код адаптера [название адаптера].

Информация о платформе: [название], протокол связи: [WebSocket / WebHook / HTTP-опрос], документация API: [адрес]
Отображение событий: платформенное событие [тип] → OneBot12 [отображение]
Необходимые реализуемые методы отправки: [текст / изображение / голос ...]
Параметры конфигурации: [ключ]: [назначение] ([обязательный/необязательный])

## MCP сервер

ErisPulse предоставляет MCP-сервер для поиска по документации, который позволяет помощникам по написанию кода (любым, поддерживающим MCP) напрямую искать и просматривать официальную документацию ErisPulse во время написания кода.

Есть два способа подключения: **локальный процесс (рекомендуется)** или **официальный онлайн-эндпоинт**. Набор инструментов одинаков:

| Инструмент | Параметры | Описание |
|-----------|-----------|----------|
| **`search_docs`** | `query` (обязательно), `top_k?=5`, `lang?=zh-CN` | Поиск по ключевым словам BM25, можно передать несколько ключевых слов за раз |
| **`read_document`** | `doc_path` (обязательно), `lang?=zh-CN` | Чтение полного Markdown-документа |
| **`list_documents`** | `lang?=zh-CN` | Вывод всех заголовков, путей и категорий документов на текущем языке |
| **`list_languages`** | — | Вывод всех поддерживаемых языков и количества документов на них |

Поддерживаемые языки: `zh-CN` / `en` / `zh-TW` / `ja` / `ru`. Советы по поиску: используйте **несколько ключевых слов**, а не целые фразы, например, `команда регистрация прослушивание событий` лучше, чем `как зарегистрировать команду`.

### Способ 1: Локальный процесс (рекомендуется)

После установки запустите локально:

```bash
npm i -g @erisdev/mcp-server   # Установка глобально → появится команда epsdk-mcp
epsdk-mcp --server               # Запуск MCP-сервиса; при первом запуске автоматически скачивает документацию в ~/.cache/erispulse-mcp/docs
```

Также можно запустить без глобальной установки с помощью `npx` (без установки):

```bash
npx @erisdev/mcp-server --server
```

Если у вас есть локальная директория с документацией, укажите её (без подключения к интернету):

```bash
ERISPULSE_DOCS_DIR=/path/to/erispulse/docs epsdk-mcp --server
```

В клиенте MCP настройте **stdio-передачу** с помощью стандартных значений (ключ `command` и `args` указывают на способ запуска, описанный выше; конкретное расположение и формат настройки см. в документации каждого клиента по интеграции с MCP):

```json
{
  "command": "epsdk-mcp",
  "args": ["--server"]
}
```

или

```json
{
  "command": "npx",
  "args": ["@erisdev/mcp-server", "--server"]
}
```

### Способ 2: Официальный онлайн-эндпоинт

Если не хотите запускать локальный процесс, подключайтесь к официально хостированному эндпоинту [`mcp.erisdev.com`](https://mcp.erisdev.com/). В клиенте MCP настройте **HTTP-передачу**:

```json
{
  "url": "https://mcp.erisdev.com/"
}
```

Сервис по умолчанию открыт и не требует токена, но есть ограничение по IP (60 запросов в минуту на IP). Официальный эндпоинт может быть отключен в любой момент, поэтому для рабочих процессов **рекомендуется использовать способ 1 (локальный процесс) или самостоятельную развертку**.

## Часто задаваемые вопросы

**Сгенерированный код не соответствует ожиданиям?**  
Проверьте, предоставлен ли полный документ; дополните требования более подробными деталями (примеры ввода и вывода, граничные условия); попросите ИИ генерировать код пошагово (сначала костяк, затем функциональность); используйте примеры из каталога [examples/](../../examples/) в качестве дополнительного контекста.

**После подключения MCP ИИ не вызывает `search_docs`?**  
Убедитесь, что клиент загрузил этот сервер (после **перезапуска клиента** инструмент станет доступен); в некоторых клиентах необходимо явно указать в промпте «использовать инструмент документации ErisPulse для проверки API».
