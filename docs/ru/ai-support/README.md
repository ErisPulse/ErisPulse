# Разработка с помощью ИИ

ErisPulse предлагает два взаимодополняющих способа разработки с помощью ИИ, позволяющих генерировать код на основе последних стандартов фреймворка:

- **Документация материалов**: большой Markdown-файл, загружаемый один раз, подходит для разработки целого проекта
- **MCP-сервер**: позволяет ИИ запрашивать официальную документацию по мере необходимости, подходит для повседневного завершения кода и поиска API

| | Документация материалов | MCP-сервер |
|---|---|---|
| Формат | Один большой Markdown-файл, **загружаемый один раз** | ИИ **запрашивает по мере необходимости** |
| Стоимость контекста | Высокая (занимает токены) | Низкая (загружает только нужные фрагменты) |
| Актуальность | Обновляется вместе с выпуском версии | В реальном времени (обновляется из GitHub + кэш) |
| Подходит для | Большой контекстный окно, разработка целого проекта | Повседневное завершение кода, поиск API |
| Клиент | Любой инструмент ИИ | Только клиенты, поддерживающие MCP |

Оба способа не противоречат друг другу: при разработке крупных проектов можно использовать их одновременно — документация материалов для базы, а MCP-сервер для поиска и заполнения пробелов.

## Документация по материалам

Документация по материалам находится в каталоге `prompts/` и разделена на три типа в зависимости от сценария разработки:

| Документ | Сценарий | Описание |
|------|------|------|
| **ErisPulse-ModuleDev.md** | Разработка модуля | Охватывает весь процесс разработки модуля (обработка событий, маршрутизация, жизненный цикл и т.д.) |
| **ErisPulse-AdapterDev.md** | Разработка адаптера | Дополнительно к разработке модуля, включает основные концепции адаптера, SendDSL и руководство по адаптации к платформе |
| **ErisPulse-Full.md** | Полное руководство | Все вышеперечисленное + полное руководство пользователя и сводка API |

Способы получения: получите напрямую из каталога `prompts/` (документация обновляется синхронно), или скачайте нужную версию с [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases).

### Способы использования

1. Выберите нужный документ в соответствии с задачей (модуль → `ModuleDev`, адаптер → `AdapterDev`, сложные задачи → `Full`)
2. Предоставьте содержимое документа в качестве контекста для ИИ: поместите в рабочую область IDE, вставьте в диалог, или вставьте как system message при вызове API
3. Используйте приведённые ниже шаблоны для описания задачи, чем конкретнее описание, тем выше качество генерации

### Шаблон описания задачи

**Модуль:**

```
Пожалуйста, на основе стандартов разработки модулей ErisPulse, сгенерируйте полный код модуля [название модуля].

Описание функционала: [основная функция]
События, которые нужно прослушивать: [сообщение / команда / уведомление / запрос], логика обработки: [операция]
Необходимые параметры конфигурации: [ключ]: [назначение] ([обязательно/необязательно], значение по умолчанию: [значение])
Дополнительные требования: [дополнительные ограничения]
```

**Адаптер:**

```
Пожалуйста, на основе стандартов разработки адаптеров ErisPulse, сгенерируйте полный код адаптера [название адаптера].

Информация о платформе: [название], протокол связи: [WebSocket / WebHook / HTTP-опрос], документация API: [адрес]
Маппинг событий: платформенное событие [тип] → OneBot12 [отображение]
Необходимые реализуемые методы отправки: [Текст / Изображение / Голос ...]
Параметры конфигурации: [ключ]: [назначение] ([обязательно/необязательно])
```

## Сервер MCP

ErisPulse предоставляет сервер MCP для поиска документов, который позволяет помощникам по написанию кода (все, которые поддерживают MCP) напрямую искать и просматривать официальную документацию ErisPulse во время написания кода.

Существует два способа подключения: **локальный процесс (рекомендуется)** или **официальная удалённая точка доступа**. Набор инструментов одинаков:

| Инструмент | Параметры | Описание |
|-----------|-----------|----------|
| **`search_docs`** | `query` (обязательно), `top_k?=5`, `lang?=zh-CN` | Поиск по ключевым словам с помощью BM25, можно передать несколько ключевых слов за раз |
| **`read_document`** | `doc_path` (обязательно), `lang?=zh-CN` | Чтение полного Markdown-документа |
| **`list_documents`** | `lang?=zh-CN` | Вывод всех заголовков, путей и категорий документов на текущем языке |
| **`list_languages`** | — | Вывод всех поддерживаемых языков документации и количества документов на каждом |

Поддерживаемые языки: `zh-CN` / `en` / `zh-TW` / `ja` / `ru`. Советы по поиску: используйте **несколько ключевых слов**, а не целые фразы, например `командная регистрация событие прослушивания` лучше, чем `как зарегистрировать команду`.

### Способ 1: Локальный процесс (рекомендуется)

После установки запустите локально:

```bash
npm i -g @erisdev/mcp-server   # Установка глобально → появляется команда epsdk-mcp
epsdk-mcp --server               # Запуск сервера MCP; при первом запуске автоматически загружает документацию в ~/.cache/erispulse-mcp/docs
```

Также можно запустить без глобальной установки с помощью `npx` (без установки):

```bash
npx @erisdev/mcp-server --server
```

Если у вас есть локальная директория с документацией, укажите её (без подключения к интернету):

```bash
ERISPULSE_DOCS_DIR=/path/to/erispulse/docs epsdk-mcp --server
```

В клиенте MCP настройте **ввод/вывод через stdio**, используя стандартные ключи (`command` + `args`, указывающие на способ запуска выше; конкретное расположение и формат настройки смотрите в документации каждого клиента по подключению к MCP):

```json
{
  "command": "epsdk-mcp",
  "args": ["--server"]
}
```

или

```json
{
  "command": "npx",
  "args": ["@erisdev/mcp-server", "--server"]
}
```

### Способ 2: Официальная удалённая точка доступа

Если не хотите запускать локальный процесс, подключитесь к официально размещённой точке доступа [`mcp.erisdev.com`](https://mcp.erisdev.com/). В клиенте MCP настройте **HTTP-трансфер**:

```json
{
  "url": "https://mcp.erisdev.com/"
}
```

Сервис по умолчанию открыт, токен не требуется, действует ограничение по IP (60 запросов в минуту на IP). Официальная точка доступа может быть отключена в любой момент, **для производственных рабочих процессов рекомендуется использовать способ 1 (локальный процесс) или самостоятельное размещение**.

## Часто задаваемые вопросы

**Сгенерированный код не соответствует ожиданиям?**  
Убедитесь, что предоставлен полный документ; добавьте больше деталей в требования (примеры входных/выходных данных, граничные условия); попросите ИИ генерировать код пошагово (сначала схему, затем функциональность); обратитесь к примерам в каталоге [examples/](../../examples/) для дополнительного контекста.

**После подключения MCP ИИ не вызывает `search_docs`?**  
Убедитесь, что клиент загрузил этот сервер (после **перезапуска клиента** инструмент должен заработать); в некоторых клиентах необходимо явно указать в промпте «использовать инструмент документации ErisPulse для проверки API».
