# Адаптер WeChatMp (微信公众号适配器) — Документация по платформенным особенностям

## Основная информация
- Имя модуля: `ErisPulse-WechatMpAdapter`
- Идентификатор платформы: `mp` (псевдоним: `wechat_mp`)
- Версия модуля: 4.0.0
- Разработчик: ErisPulse
- Зависимости: `cryptography`

## Поддерживаемые типы отправки сообщений

| Метод | Описание | WeChat API |
|------|------|---------|
| `Text(text)` | Отправить текст | Служебное сообщение `message/custom/send` |
| `Image(file)` | Отправить изображение (автоматическая загрузка для получения media_id) | Служебное сообщение + `media/upload` |
| `Voice(file)` | Отправить голосовое (автоматическая загрузка для получения media_id) | Служебное сообщение + `media/upload` |
| `Video(file, title, description)` | Отправить видео (автоматическая загрузка для получения media_id) | Служебное сообщение + `media/upload` |
| `Music(url, title, description, ...)` | Отправить музыкальное | Служебное сообщение |
| `News(articles)` | Отправить новостную статью | Служебное сообщение |
| `Template(template_id, data, url)` | Отправить шаблонное сообщение | `message/template/send` |
| `Menu(head_content, list, tail_content)` | Отправить сообщение-меню | Служебное сообщение `msgmenu` |
| `Raw_ob12(message)` | Отправить стандартный сегмент сообщения OneBot12 | - |

### Описание медиафайлов
- Поддерживаются три типа параметров:
  - `str` URL (начинается с `http://` / `https://`): автоматическая загрузка
  - `str` локальный путь к файлу: автоматическое чтение и загрузка
  - `bytes` бинарные данные: прямая загрузка
  - `str` media_id: можно использовать с префиксом `media:` без повторной загрузки
- После загрузки получается временный материал `media_id`, срок действия — 3 дня

### Важные ограничения
- Служебные сообщения можно отправлять **в течение 48 часов** только после того, как пользователь взаимодействовал с официальной страницей
- После 48 часов необходимо использовать шаблонные сообщения (требуется сценарий с авторизацией пользователя)

## Типы событий

### Событие сообщения (message)
Все сообщения пользователей — `detail_type: private` (сценарий 1v1 с официальной страницей).

| WeChat MsgType | Тип сегмента | Описание |
|-------------|-----------|------|
| `text` | `text` | Текстовое сообщение |
| `image` | `image` | Изображение |
| `voice` | `voice` | Голосовое сообщение (включает результат распознавания речи) |
| `video` | `video` | Видеосообщение |
| `shortvideo` | `video` | Короткое видео (помечено `mp_shortvideo`) |
| `location` | `location` | Сообщение о геолокации |
| `link` | `text` | Ссылка (преобразовано в текст) |

### Событие уведомления (notice)
Тип события определяется полем `mp_event`.

| WeChat Event | `mp_event` | Описание |
|-----------|-----------|------|
| `subscribe` | `subscribe` | Подписка на официальную страницу |
| `unsubscribe` | `unsubscribe` | Отмена подписки |
| `SCAN` | `scan` | Сканирование QR-кода с параметрами |
| `LOCATION` | `location_report` | Отчет о геолокации |
| `CLICK` | `menu_click` | Клик по пользовательскому меню |
| `VIEW` | `menu_view` | Переход по ссылке меню |
| `TEMPLATESENDJOBFINISH` | `template_send_finish` | Результат отправки шаблонного сообщения |
| `MASSSENDJOBFINISH` | `mass_send_finish` | Результат массовой рассылки |

## Платформенные расширяемые поля

Поля, уникальные для WeChat (префикс `mp_`):

| Поле | Тип | Описание |
|------|------|------|
| `mp_raw` | str | Необработанные XML-данные |
| `mp_raw_type` | str | Тип необработанного сообщения/события |
| `mp_msg_id` | str | ID сообщения WeChat |
| `mp_event` | str | Тип события (только уведомления событий) |
| `mp_event_key` | str | Ключ события (клик по меню, сканирование и т.д.) |
| `mp_to_user` | str | Идентификатор получателя (первичный ID официальной страницы) |
| `mp_from_user` | str | OpenID отправителя |
| `mp_data` | dict | Преобразованный словарь данных XML |

## Методы расширения событий

Регистрируется через `register_event_mixin("mp", ...)` и вызывается напрямую на объекте события:

| Метод | Возвращаемое значение | Описание |
|------|--------|------|
| `get_openid()` | str | OpenID отправителя |
| `get_msg_type()` | str | Оригинальный тип сообщения WeChat |
| `get_event()` | str | Тип события (только уведомления событий) |
| `get_content()` | str | Чистый текст сообщения |
| `get_raw_xml()` | str | Необработанные XML-данные |

## Опции конфигурации

### Конфигурация нескольких учетных записей

Каждая учетная запись соответствует одной официальной странице:

```toml
[WechatMpAdapter.accounts.main]
appid = "wx1234567890abcdef"
appsecret = "your_app_secret_here"
token = "your_callback_token"
encoding_aes_key = ""                    # Требуется только в безопасном/совместимом режиме (43 символа)
callback_path = "/mp/main"               # Путь обратного вызова
enable = true

[WechatMpAdapter.accounts.secondary]
appid = "wx0987654321fedcba"
appsecret = "another_app_secret"
token = "another_callback_token"
callback_path = "/mp/secondary"
enable = true
```

### Описание полей конфигурации

| Поле | Обязательно | Описание |
|------|------|------|
| `appid` | Да | AppID официальной страницы |
| `appsecret` | Да | AppSecret официальной страницы (secret) |
| `token` | Нет | Токен проверки обратного вызова (рекомендуется указать для включения проверки подписи) |
| `encoding_aes_key` | Нет | Ключ шифрования/дешифрования сообщений (43 символа, обязательно в безопасном режиме) |
| `callback_path` | Нет | Шаблон пути обратного вызова, по умолчанию `/mp/{account}`, `{account}` заменяется на имя учетной записи |
| `enable` | Нет | Включить, по умолчанию true |

## Описание режимов шифрования

Официальные страницы WeChat предоставляют три режима шифрования сообщений:

| Режим | Описание | encoding_aes_key | Проверяемое поле |
|------|------|-----------------|---------|
| Простой (明文模式) | Прямая передача XML | Не требуется | `signature` |
| Совместимый (兼容模式) | Прямая передача + шифрование одновременно | Опционально | `signature` / `msg_signature` |
| Безопасный (安全模式) | Полное шифрование | Обязательно | `msg_signature` |

Адаптер автоматически обрабатывает:
- Простой режим: проверка `signature`, прямая обработка XML
- Безопасный/совместимый режим: проверка поля `Encrypt`, проверка `msg_signature`, расшифровка с помощью AES-256-CBC
- Расшифровка зависит от библиотеки `cryptography` (указана в dependencies)

## Маршруты обратного вызова

Адаптор регистрирует два маршрута для каждой включенной учетной записи (GET + POST):

- **GET**: проверка доступа сервера WeChat, возврат `echostr` после проверки подписи
- **POST**: прием сообщений и событий, проверка подписи → расшифровка (при необходимости) → преобразование → emit

Фактический путь доступа автоматически добавляет префикс модуля. Например, зарегистрированный путь `/mp/main`:
- Фактические пути доступа: `/mp_{account}_verify/mp/main` и `/mp_{account}_message/mp/main`.

## Ответы API

Все вызовы `call_api` возвращают стандартизированные ответы:

- Успех: `status: "ok"`, `retcode: 0`
- Ошибка: `status: "failed"`, `retcode: 34000+errcode`
- Всегда содержит `mp_raw` (необработанный ответ) и `message_id`
