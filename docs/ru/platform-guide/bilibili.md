# Документация по функциональности платформы Bilibili

BilibiliAdapter — это адаптер личных сообщений Bilibili, основанный на библиотеке bilibili-api-python. Поддерживает двойную авторизацию Cookie / сканирование QR-кода и обработку событий для отправки и получения личных сообщений.

---

## Информация о документации

- Версия соответствующего модуля: 0.1.0
- Поддержка: ErisPulse

## Основная информация

- Краткое описание платформы: Бот личных сообщений Bilibili (без официального API для личных ботов, использует веб-интерфейс личных сообщений через эмуляцию входа)
- Название адаптера: BilibiliAdapter
- Поддержка нескольких аккаунтов: Поддерживается (каждый аккаунт — отдельный логин Bilibili, отдельная сессия прослушивания)
- Способ подключения: Прослушивание сессий на основе событий (bilibili-api `Session`)
- Способ аутентификации: Cookie (SESSDATA / bili_jct / buvid3 / dedeuserid) или авторизация через QR-код в панели
- Поддержка цепочек модификаторов: Поддерживается, например, `.Reply()`
- Совместимость с OneBot12: Поддерживает стандартные сегменты сообщений (text / image)

## Описание конфигурации

```toml
[BilibiliAdapter.accounts.default]
login_mode = "cookie"          # cookie=ввод凭据 / qrcode=面板扫码（推荐）
sessdata = "YOUR_SESSDATA"     # cookie 模式必填
bili_jct = "YOUR_BILI_JCT"     # cookie 模式必填
buvid3 = "YOUR_BUVID3"         # 可选，降低风控概率
dedeuserid = "YOUR_UID"        # 可选，即账号 UID
bot_id = ""                    # 留空登录后自动获取
enabled = true
```

**Описание параметров конфигурации (для каждого аккаунта):**

- `login_mode`: Способ авторизации. `cookie` — ввод凭据; `qrcode` — авторизация через QR-код (рекомендуется).凭据最终都落在 sessdata/bili_jct 等字段
- `sessdata` / `bili_jct`: Cookie-凭据 авторизации (обязательны для режима cookie;凭据密码形态显示)
- `buvid3`: Cookie-凭据 устройства (опционально), при наличии снижает вероятность рисков
- `dedeuserid`: UID аккаунта (опционально), также используется как источник `bot_id`
- `bot_id`: UID аккаунта, оставьте пустым, чтобы получить его автоматически через `get_self_info` после входа

**Процесс авторизации через QR-код:** `login_mode = "qrcode"` после сохранения конфигурации, в Dashboard → Компоненты → Добавление аккаунта выберите «Авторизация через QR-код Bilibili» → Сканируйте QR-код в приложении Bilibili → Подтвердите на телефоне → Адаптер опрашивает статус авторизации (scan → confirm → done),凭据 автоматически записываются в конфигурацию аккаунта и применяются.

> Адаптер регистрирует два эндпоинта: `POST /bilibili/qr/start` (получение QR-кода, возвращает URL изображения + токен сессии) и `POST /bilibili/qr/poll` (опрос статуса авторизации). Третьи стороны могут напрямую подключаться к этим эндпоинтам. При опросе необходимо передавать `poll_token`, полученный от `start`, чтобы предотвратить несанкционированный опрос.

## Отправка сообщений

Все методы отправки возвращают задачу (Task), ожидание которой даёт стандартный ответ (см. раздел «Формат ответа»).

### Базовая отправка

```python
from ErisPulse import sdk
bili = sdk.adapter.get("bilibili")

# Текстовое личное сообщение (target — UID получателя)
await bili.Send.To("user", "123456789").Text("Hello Bilibili!")

# Личное сообщение с изображением (URL или локальный путь, изображение конвертируется в формат Bilibili)
await bili.Send.To("user", "123456789").Image("https://example.com/pic.jpg")
await bili.Send.To("user", "123456789").Image("./local.png")
```

### Методы цепочек модификаторов

```python
# Ответ на указанное сообщение (msg_key из message_id полученного сообщения)
await bili.Send.To("user", "123456789").Reply("msg_key").Text("Получено!")
```

### Отправка стандартных сегментов OneBot12

```python
message = [
    {"type": "text", "data": {"text": "Первая строка"}},
    {"type": "image", "data": {"file": "https://example.com/img.jpg"}},
]
await bili.Send.To("user", "123456789").Raw_ob12(message)
```

### Отправка с использованием нескольких аккаунтов

```python
await bili.Send.Using("account2").To("user", "123456789").Text("От второго аккаунта")
```

### Поддерживаемые и неподдерживаемые сегменты сообщений

| Сегмент | Поддержка | Описание |
|----|------|------|
| `text` | Поддерживается | Сегменты объединяются и отправляются через `send_msg` (TEXT) |
| `image` | Поддерживается | `file` — URL или локальный путь, отправляется через `send_msg` (PICTURE) |
| `reply` | Частично поддерживается | Модификатор принимается, в личных сообщениях Bilibili нет отображения цитаты, используется только для контекста отправки |
| `mention` / `face` / `voice` / `video` / `file` и др. | Не поддерживается | Возвращается `retcode=10002` и перечисляются полученные типы сегментов |

## Стандартные API-действия (Api)

```python
from ErisPulse import sdk
bili = sdk.adapter.get("bilibili")

# Информация о себе (никнейм/аватар/UID)
result = await bili.Api.get_self_info()

# Общедоступная информация о пользователе (любой пользователь, никнейм/аватар)
result = await bili.Api.get_user_info("123456789")

# Получение истории сообщений в указанной сессии (begin_seqno для прокрутки)
result = await bili.Api.get_session_msgs("123456789", begin_seqno=0)

# Статус и версия
result = await bili.Api.get_status()
result = await bili.Api.get_version()

# Многоаккаунтность
result = await bili.Api.Using("account2").get_self_info()
```

### Поддерживаемые стандартные действия

| Метод | Описание | Источник данных |
|------|------|---------|
| `get_self_info()` | Информация о себе (mid/name/face) | Web API (пространство пользователя) |
| `get_user_info(user_id)` | Общедоступная информация о пользователе (никнейм/аватар) | Web API (карточка пользователя) |
| `get_session_msgs(talker_id, begin_seqno)` | История сообщений в сессии | Web личные сообщения (session_msgs) |
| `get_status()` | Статус работы адаптера | Локально |
| `get_version()` | Версия адаптера | Локально |

### Неподдерживаемые стандартные действия

Для следующих действий в личных сообщениях Bilibili нет соответствующей функциональности, вызов возвращает `retcode=10002`:

- `get_friend_list` / `get_group_list` / `get_group_member_info`
- `delete_message` (в личных сообщениях Bilibili только отправитель может отозвать своё сообщение)
- `set_group_name` / `leave_group` и другие действия по управлению группами

### Общий вход для действий

```python
# send_message: отправка комбинированных сегментов текста и изображения (эквивалентно Send-цепочке)
result = await bili.call_api(
    "send_message",
    _account_id="default",
    target_id="123456789",
    message=[{"type": "text", "data": {"text": "hi"}}],
)
```

## Формат ответа

Все методы отправки и API-действия следуют стандартизированному формату ответа адаптера ErisPulse:

```python
{
    "status": "ok",              # ok / failed
    "retcode": 0,                # 0 — успешно; 10002 — не поддерживается; 10003 — параметры/цель неверны; 33100 — ошибка API Bilibili
    "data": {...},               # Данные ответа (оригинальный ответ send_msg)
    "self": {"platform": "bilibili", "user_id": "..."},
    "message_id": "123456",      # B 站 msg_key
    "message": "",               # Ошибка
    "bilibili_raw": {...}        # Оригинальный ответ
}
```

## Типы событий

Необходимо проверять `platform == "bilibili"`, чтобы использовать функции платформы.

### Сопоставление событий

| Событие личных сообщений Bilibili | Событие адаптера | Описание |
|--------------|--------------|------|
| TEXT (текстовое сообщение) | message (сегмент text) | Обычные личные сообщения |
| PICTURE (изображение) | message (сегмент image) | content.pictures → сегмент image (URL) |
| WITHDRAW (отмена) | Только логирование | Сообщение удалено отправителем |

### Пример полей события

```python
{
  "id": "uuid",
  "time": 1793277000,
  "type": "message",
  "detail_type": "private",
  "platform": "bilibili",
  "self": {"platform": "bilibili", "user_id": "10000", "user_name": "Bot昵称", "account_id": "default"},
  "user_id": "123456789",                  # UID получателя (sender_uid)
  "user_nickname": "小王",                  # content.sender_name (возможно отсутствует)
  "message": [{"type": "text", "data": {"text": "Привет"}}],
  "alt_message": "Привет",
  "bilibili_raw": {...},                   # Оригинальные данные личных сообщений Bilibili
  "bilibili_raw_type": "text"              # text / picture
}
```

### Описание дополнительных полей

- Все специфические поля имеют префикс `bilibili_` (`bilibili_raw` / `bilibili_raw_type`)
- Полученные изображения представлены как сегмент image, `data.file` — URL с сервера Bilibili
- `user_nickname` берётся из `sender_name` в данных сообщения, в некоторых типах сообщений может отсутствовать

## Примечания

1. **Bilibili не имеет официального API для личных ботов**: данный адаптер использует веб-интерфейс личных сообщений через эмуляцию входа, что является неофициальным использованием, и API может изменяться с обновлениями Bilibili
2. **Риски**: Частая или массовая отправка личных сообщений может вызвать риски (временная блокировка функции личных сообщений). Обязательно используйте ограничение скорости на стороне модуля; наличие `buvid3` снижает вероятность рисков
3. **Истечение срока действия凭据**: При истечении срока действия凭据 адаптер будет записывать ошибки в лог, необходимо повторно авторизоваться или обновить凭据;凭据 отображаются в панели в виде пароля
4. **Ограничения личных сообщений**: Поддерживается только личная переписка; публичные группы пока не поддерживаются
5. **Соблюдение правил**: Не используйте для спама, маркетинга и других нарушений, соблюдайте правила сообщества Bilibili
