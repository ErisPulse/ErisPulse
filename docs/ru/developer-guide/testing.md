# Модульное тестирование (ErisPulse-Testing)

[ErisPulse-Testing](https://github.com/ErisPulse/ErisPulse-Testing) — официальный инструментарий для тестирования (RFC EPRFC-2026-001, направление 3):
Предоставляет `TestBot`, фабрику тестовых событий, захват и утверждение исходящих сообщений, делая модульное тестирование простым, как обычные pytest-тесты.

```bash
pip install ErisPulse-Testing
```

> Инструмент для разработки, односторонняя зависимость от фреймворка, нулевое вмешательство в runtime. Для проверки работоспособности адаптеров платформы используйте `tests/devs/test_adapter.py` из репозитория фреймворка.

## Быстрый старт

```python
import pytest
from ErisPulse.Core.Event.command import command
from ErisPulse_Testing import TestBot, create_command_event

async def test_daily(make_testbot):
    async with make_testbot(prefix="/") as bot:
        @command("daily", cooldown="1d", cooldown_reply="Сегодня уже зарегистрирован")
        async def daily(event):
            await event.reply("Регистрация прошла успешно!")

        await bot.dispatch(create_command_event("daily", user_id="123"))
        assert bot.last_reply.text == "Регистрация прошла успешно！"

        await bot.dispatch(create_command_event("daily", user_id="123"))
        bot.assert_reply_contains("Сегодня уже зарегистрирован")   # Второе попадание в кулдаун
```

`TestBot` рекомендуется использовать с `async with`: при запуске регистрируется MockAdapter (захватывает все исходящие), отключается дедупликация событий, применяются переопределения конфигурации; при выходе автоматически очищаются глобальные состояния фреймворка, тесты не влияют друг на друга.

Сопутствующие pytest fixtures (автоматически доступны после установки):

- `testbot`: стандартный TestBot уровня функции (platform=`test`, префикс `/`)
- `make_testbot(**kwargs)`: фабрика с пользовательскими параметрами (`prefix` / `config` / `platform` / `bot_id` ...)

Рекомендуется в конфигурации проекта установить `asyncio_mode = "auto"` (`[tool.pytest.ini_options]`),
или добавить `@pytest.mark.asyncio` к тестовым функциям.

## Фабрика событий

| Функция | Описание |
|------|------|
| `create_message_event(text, user_id=..., group_id=None, ...)` | Событие сообщения; если `group_id` пуст, то личный чат |
| `create_command_event("roll 3", prefix="/")` | Командное сообщение (префикс добавляется автоматически, если уже есть — не дублируется) |
| `create_notice_event(type, ...)` | Событие уведомления (например, `friend_add`) |
| `create_request_event(type, ...)` | Событие запроса (например, заявка в друзья) |
| `create_meta_event("connect", ...)` | Мета-событие (connect позволяет Bot войти в систему) |

Все события имеют уникальный `id` на основе uuid, что избегает дедупликации событий в фреймворке.

Важно: синтезированные события **не содержат оригинальных платформенных сообщений** (`event.get_raw()` возвращает пустой dict). Для определения сценариев (групповой чат / личный чат) используйте `event.is_group_message()` / `event.get_detail_type()` / `event.get_group_id()` и т.д., не читайте raw-данные.

## API TestBot

### Диспетчеризация

```python
trace = await bot.dispatch(event)          # Диспетчеризация и ожидание обработки, возвращает цепочку решений
await bot.dispatch(event, drain=False)     # Первая взаимодействующая сообщение: не ждать (wait_reply обработчики остаются активными)
await bot.send_message("Привет")             # Быстрый способ отправки сообщения
await bot.reply_as("18", user_id="u1")     # Эмуляция ответа пользователя на wait_reply (автоматически ждёт готовности waiter)
```

`dispatch()` после emit собирает все активные задачи обработчиков и возвращает управление сразу после завершения обработки — **в тестах не нужно использовать sleep**.

### Утверждения исходящих сообщений

```python
bot.replies                # Все исходящие сообщения (список SentMessage)
bot.last_reply.text        # Текст последнего ответа
bot.replies_to("123")      # Фильтрация по цели
bot.clear_replies()        # Изоляция между этапами тестирования
bot.assert_replied()                       # Существует хотя бы одно исходящее сообщение
bot.assert_replied(contains="Регистрация", to="123")
bot.assert_not_replied()                   # Нет исходящих сообщений
bot.assert_reply_contains("Регистрация прошла успешно")       # Существует исходящее сообщение с указанным текстом
await bot.wait_for_reply(timeout=2)        # Ожидание асинхронного ответа
```

Поля `SentMessage`: `text` (первый текстовый сегмент), `segments` (полный набор сегментов), 
`target_type` / `target_id` / `bot_id` (контекст отправки), `has_modifier("at")` и т.д.

### Загрузка модулей

```python
await bot.load_module("MyModule")   # Имя уже зарегистрированного модуля (требуется завершение discovery entry-point через sdk.init())
await bot.load_module(MyModule)     # Или подкласс BaseModule (автоматическая регистрация + загрузка, рекомендуется)
await bot.unload_module("MyModule")
```

Обработчики команд / событий, зарегистрированные в `on_load`, принадлежат модулю и автоматически удаляются при выгрузке. Можно напрямую утверждать, что команда не работает после выгрузки.
Важно: использование строки **не выполняет** поиск entry-point (TestBot не инициализирует процесс discovery фреймворка); для тестирования модулей с мягкими зависимостями передавайте напрямую класс или используйте `module.register` перед передачей имени.

### Замена зависимостей (требуется EP>=2.9.0-dev)

```python
with bot.patch_dependency(get_session, fake_session) as mock:
    await bot.dispatch(create_command_event("query"))
    assert mock.called
```

Заменяется функция, объявленная в таблице команд через `Depends(get_session)`, автоматически восстанавливается при выходе из `with`.

### Переопределение конфигурации

```python
bot = TestBot(prefix="//", config={
    "ErisPulse.event.command.case_sensitive": False,
    "MyModule.api_key": "test-key",     # Конфигурация модуля (доступна через self.cfg)
})
```

Изменения конфигурации применяются в памяти, префикс команд и т.д. обновляются мгновенно. Два важных замечания:

1. **Сохранение на диск**: переопределения сохраняются с задержкой (по умолчанию около 5 секунд) в `config/config.toml` в рабочей директории — если ваш проект в Git, добавьте `config/` в `.gitignore`;
2. **Конфликт с сохранением конфигурации модулем во время выполнения (известное ограничение)**: если модуль сохраняет конфигурацию целиком (например, `self.cfg = ...`, как в списке подписок) и одновременно происходит точечное переопределение, возникает проблема согласованности ConfigManager — модуль может не видеть переопределённые значения, а переопределения могут быть перезаписаны при сохранении (исправлено в ErisPulse 2.9.0-dev.2, в 2.8.x всё ещё актуально). Для тестов, где модуль сохраняет конфигурацию во время выполнения, в 2.8.x рекомендуется сбрасывать соответствующие секции конфигурации в fixture целиком.

## Цепочка диспетчеризации (для отладки "почему команда не сработала"; требуется EP>=2.9.0-dev)

`dispatch()` возвращает `DispatchTrace` — цепочку причинно-следственных связей каждого этапа диспетчеризации:

```python
trace = await bot.dispatch(create_command_event("dailyx", user_id="123"))

trace.verdict        # executed / rejected / dropped / failed / no_match / passed
trace.explain()      # Построчное пояснение причинно-следственных связей (текущий язык)
trace.command        # Найденная команда (None, если не найдена)
trace.steps("cooldown")  # Фильтрация по этапу (например, cooldown)

trace.assert_executed("daily")  # Утверждение выполнения (при ошибке выводит полную цепочку)
trace.assert_rejected()         # Утверждение отказа по правилам ACL
trace.assert_dropped()          # Утверждение отбрасывания (например, из-за кулдауна)
trace.assert_no_match()         # Утверждение отсутствия совпадения с командой
```

Покрытые этапы: текст команды, совпадение команды (при неудаче — предложение исправления), область действия, ACL пользователя, проверка владельца, функции прав, кулдаун и отбрасывание, парсинг параметров, результат выполнения, отмена промежуточными middleware.

В продакшене также доступна встроенная в фреймворк `ErisPulse.Core.Event.trace` (`start_dispatch_trace()` / `format_dispatch_trace()`) для сбора и отображения цепочек диспетчеризации.
