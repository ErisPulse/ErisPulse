# AI 輔助開發

ErisPulse 提供了預建的 AI 物料文件，你可以將其作為上下文提供給 AI 模型，從而產生符合框架規範的模組和適配器程式碼。

## 物料文件

物料文件位於本目錄的 `prompts/` 子目錄下，依開發場景分為三種：

| 文件 | 場景 | 規模 | 說明 |
|------|------|------|------|
| **ErisPulse-ModuleDev.md** | 模組開發 | 中 | 覆蓋模組開發全流程，適合大多數場景 |
| **ErisPulse-AdapterDev.md** | 適配器開發 | 中 | 覆蓋適配器開發全流程，包含平台適配規範 |
| **ErisPulse-Full.md** | 全棧參考 | 大 | 完整開發文件合集，需要大上下文視窗的模型 |

### 各文件覆蓋範圍

**ModuleDev** 包含：基礎概念、事件處理入門、模組核心概念、Event 包裝類、Conversation 多輪對話、MessageBuilder、路由系統、生命週期管理、懶加載系統、會話類型標準、模組發布流程。

**AdapterDev** 包含：上述基礎內容，外加適配器核心概念、SendDSL 鏈式呼叫、事件轉換器設計、事件轉換/API 回應/發送方法三項技術標準、全部平台適配指南、文件字串規範。

**Full** 包含：上述全部內容，外加完整的使用者指南（安裝、配置、部署）、全部 API 參考、已知問題追蹤。僅建議用於上下文視窗 >= 128K tokens 的模型。

### 獲取最新版本

物料文件隨框架發布自動更新，獲取方式：

- 從 `prompts/` 目錄直接獲取（與文件同步更新）
- 從 [GitHub Releases](https://github.com/ErisPulse/ErisPulse/releases) 下載對應版本

## 使用步驟

### 1. 選擇物料文件

根據你的開發目標選擇對應的文件：

- 開發功能模組 → `ErisPulse-ModuleDev.md`
- 開發平台適配器 → `ErisPulse-AdapterDev.md`
- 不確定或需求複雜 → `ErisPulse-Full.md`（確保模型上下文視窗足夠大）

### 2. 提供上下文

將選中的物料文件內容提供給 AI，方式取決於你使用的工具：

- **IDE 內建 AI（Copilot / Cursor）**：將文件放入工作區，或在對話中直接貼上
- **對話式 AI（ChatGPT / Claude）**：在對話開頭貼上文件內容，告知 AI "請基於以下文件作為知識庫回答問題"
- **API 調用**：將文件作為 system message 或上下文注入

### 3. 編寫需求描述

使用下方的範本描述你的需求，填入後發送給 AI。描述越具體，產生的品質越高。

### 4. 驗證產生結果

AI 產生程式碼後，建議：

1. 檢查程式碼是否繼承了正確的基類（`BaseModule` 或 `BaseAdapter`）
2. 確認事件處理器使用了正確的裝飾器（`@message.on_message` 等）
3. 執行 `epsdk create module` 或 `epsdk create adapter` 建立專案骨架，將產生的程式碼填入對應檔案
4. 執行測試驗證功能是否正常

## 需求描述範本

### 模組需求

```
請基於 ErisPulse 模組開發規範，產生一個 [模組名稱] 模組的完整程式碼。

功能描述：
[描述模組的核心功能]

需要監聽的事件：
- 事件類型：[訊息 / 命令 / 通知 / 請求]
- 處理邏輯：[描述事件觸發後執行的操作]

需要的配置項：
- [設定鍵名]：[用途說明]（[必填/可選]，預設值：[值]）

其他要求：
- [額外的功能或限制]
```

### 適配器需求

```
請基於 ErisPulse 適配器開發規範，產生一個 [適配器名稱] 適配器的完整程式碼。

平台資訊：
- 平台名稱：[名稱]
- 通訊協定：[WebSocket / WebHook / HTTP 輪詢]
- API 文件位址：[如有]

事件轉換：
- 平台事件類型：[列出平台的主要事件]
- OneBot12 映射關係：[描述平台事件到 OB12 標準的映射]

需要實現的發送方法：
- [Text / Image / Voice 等訊息類型]：[是否需要實現]

設定項：
- [設定鍵名]：[用途說明]（[必填/可選]）
```

## 常見問題

**推薦哪些 AI 工具？**

- IDE 集成類：Cursor、VS Code + Copilot —— 可直接操作檔案系統，適合專案級開發
- 對話類：ChatGPT、Claude —— 適合快速原型和單檔案產生
- API 調用：適合批量產生或 CI 集成場景

**產生的程式碼不符合預期怎麼辦？**

1. 檢查是否提供了完整且正確的物料文件
2. 在需求描述中補充更多細節（具體的輸入輸出示例、邊界條件等）
3. 讓 AI 分步產生：先產生骨架程式碼，確認無誤後再逐步補充功能
4. 參考 [examples/](../../examples/) 目錄中的示例程式碼，將示例作為補充上下文提供

**如何提高產生品質？**

- 在需求中明確指定模組名稱、需要繼承的基類
- 提供具體的訊息格式示例（平台原始事件 → 期望的 OB12 格式）
- 要求 AI 同時產生測試程式碼
- 對於適配器，提供平台 API 文件的關鍵介面資訊作為補充
