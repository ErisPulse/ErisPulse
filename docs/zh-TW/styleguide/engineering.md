# 工程健壯性規則

本頁是 ErisPulse 源碼的健壯性紀律。每條規則給出「為什麼」與本倉庫的真實案例；貢獻程式碼前請過一遍本頁，CI 之外的部分靠審核執行。

## 1. 異常留痕分級

`except` 不是垃圾桶。捕獲異常後要怎麼處理，取決於你吞掉的是什麼：

| 類別 | 判定 | 處理 |
|------|------|------|
| 探測型 | 失敗後有安全預設值，且失敗方向無害（如探測實例屬性名回退類名） | `pass` 可接受 |
| 降級型 | 失敗後走替代路徑，但仍值得知道（如可選依賴缺失） | `logger.debug` 留痕 |
| 資源釋放型 | 連接、檔案句柄、線程、任務的關閉路徑 | 至少 `logger.debug`，重複出現升級 `warning` |
| 數據寫入型 | 配置落盤、訊息記錄、狀態持久化的寫入路徑 | `warning` 起步——靜默丟數據無法事後排查 |

**禁止雙層降級**：不要把「日誌呼叫本身」再包進 `try/except: pass`——告警在異常條件下消失等於沒有告警。

反面案例（均已修復，留作範式）：

- 配置管理器 `close()` 內最後一次刷盤失敗被靜默吞掉——使用者改了配置關程式，變動無痕跡丟失
- HTTP 客戶端替換會話時舊會話 `close()` 失敗被靜默吞掉——連接資源泄漏
- 初始化重複呼叫的 `warning` 本身被 `try/except: pass` 包裹——i18n 未就緒時告警消失

## 2. 日誌分級紀律

- **失敗事件最低 `warning`**：重試耗盡、回滾觸發、訂閱方回呼失敗、狀態重放失敗——這些意味著「系統狀態與預期不一致」，`debug` 級別等於對使用者隱身
- **循環內失敗必須節流**：清理循環、watcher、背景 GC 中的重複異常，用「首次 warning + 後續計數/冷卻」或降為 `debug` 加週期性總結，防止日誌刷屏
- `trace` 僅用於高頻熱路徑的正常流程；`error` 留給已影響請求結果的失敗

## 3. 行為參數集中

超時、重試次數、冷卻期、輪詢間隔一律定義在 `Core/constants.py`（CLI 侧行為參數同樣放入該文件），命名 `*_TIMEOUT_SECS` / `*_RETRY_*` / `*_COOLDOWN_SECS`，並在註釋中寫明使用位置。實現文件禁止出現裸數字超時（`timeout=30`、`sleep(5)`）——同一語義的裸值散落多處是漂移的起點。

**邊界**：此規則約束核心倉庫；第三方模組 / 適配器建議在自身模組內集中定義行為參數，不強制定位到 `Core/constants.py`。

## 4. 公共 API 契約

沒有前置底線的類別與方法必須同時具備：完整的 docstring（參照 [註釋風格規範](docstring.md)）、所有參數與回傳值的類型標註。內部實作（`_` 前綴）可以放寬，但一旦出現在文件或範例中，即應按照公共標準處理。

**既有邊界**：以上要求以**新增 / 觸碰的檔案**為準，不強制對既有程式碼全面補齊；既有問題在檢查中以基線方式呈現，當檔案被觸碰時，其既有問題將升級為阻斷問題。

## 5. 單例回引禁忌

框架組件（管理器、加載器、基類）不得持有「根 SDK 單例」的回引欄位：

- 回引欄位意味著組件生命週期與組裝順序緊耦合，一旦組裝方忘記接線，功能**靜默失效**而非報錯——本項目曾因 `set_sdk_ref` 調用方被移除，熱重載/依賴通知在六個發布版本裡靜默失效
- 需要根引用時：建構注入（組合根傳入）或惰性解析（首次使用時導入），二選一；惰性解析永遠不能「忘記呼叫」
- 需要他人狀態時優先走事件訂閱或門面，不要伸手進別人的註冊表；管理器實例自有狀態必須自清，不得經全局門面繞行（門面內部是單例回引，覆蓋不了獨立實例）

## 6. 清理與回滾紀律

- 卸載/清理路徑必須是冪等的：中途失敗重試、重複卸載都不得二次釋放或拋出錯誤
- 不可逆操作（卸載、重載、刪除配置）前先拍攝快照；快照回滾是「盡力而為」語義，回滾失敗必須留下 `warning`
- 清理順序：任務取消 → 連接關閉 → 外部鉤子 → 注冊表回收，各步獨立容錯，單步失敗不阻斷後續

## 7. 測試紀律

- 改動程式碼必改測試；修復 bug 必須先有能重現該 bug 的紅色測試
- 異常路徑與邊界條件（空輸入、超時、重複呼叫、半初始化）與正常路徑同等對待——回歸防護網是重構的底氣
- 測試允許訪問內部結構，但訪問點應集中：內部佈局變更時遷移測試改的是 import 與路徑，不是斷言語義

**存量邊界**：以上紀律以**新增 / 觸碰的檔案**為準，不強制對存量程式碼全量回補測試；存量覆蓋缺口在檢查中以基線方式呈現，檔案被觸碰時其存量問題升級為阻斷。
