# ErisPulse 注釋風格規範

在建立 EP 核心方法時必須添加方法註解，註解格式如下：

## 模組級文件註釋

每個模組文件開頭應包含模組文件：
```python
"""
[模組名稱]
[模組功能描述]

{!--< tips >!--}
重要使用說明或注意事項
{!--< /tips >!--}
"""
```

## 方法註釋

### 基本格式
```python
def func(param1: type1, param2: type2) -> return_type:
    """
    [功能描述]
    
    :param param1: [類型1] [參數描述1]
    :param param2: [類型2] [參數描述2]
    :return: [返回類型] [返回描述]
    """
    pass
```

### 完整格式（適用於複雜方法）
```python
def complex_func(param1: type1, param2: type2 = None) -> Tuple[type1, type2]:
    """
    [功能詳細描述]
    [可包含多行描述]
    
    :param param1: [類型1] [參數描述1]
    :param param2: [類型2] [可選參數描述2] (預設: None)
    
    :return: 
        type1: [返回參數1描述]
        type2: [返回參數2描述]
    
    :raises ErrorType: [錯誤描述]
    """
    pass
```

## 特殊標籤（用於API文件產生）

當方法註解包含以下內容時，將在API文件建構時產生對應效果：

| 標籤格式 | 作用 | 範例 |
|---------|------|------|
| `{!--< internal-use >!--}` | 標記為內部使用，不產生文件 | `{!--< internal-use >!--}` |
| `{!--< ignore >!--}` | 忽略此方法，不產生文件 | `{!--< ignore >!--}` |
| `{!--< deprecated >!--}` | 標記為過時方法 | `{!--< deprecated >!--} 請使用new_func()代替` |
| `{!--< experimental >!--}` | 標記為實驗性功能 | `{!--< experimental >!--} 可能不穩定` |
| `{!--< tips >!--}...{!--< /tips >!--}` | 多行提示內容 | `{!--< tips >!--}\n重要提示內容\n{!--< /tips >!--}` |
| `{!--< tips >!--}` | 單行提示內容 | `{!--< tips >!--} 注意: 此方法需要先初始化` |

> **邊界說明**：文件正文（`docs/` 下的 Markdown）用 GitHub 提示區塊（`> [!TIP]` 等）標註注意訊息；docstring 內用本節 `{!--< ... >!--}` 標籤——**兩套體系各自獨立，不混用**（docstring 裡的 `> [!TIP]` 不會被 API 文件產生器識別為提示區塊，Markdown 正文裡的 `{!--< >!--}` 標籤也不會被處理）。

## 標籤解析契約

以下為 `scripts/tools/generate-api-docs.py` 中 `process_docstring_for_markdown()` 的**實際解析行為**（核心轉換在 `_process_doc_lines()` 逐行進行），撰寫標籤時依此契約預期產生結果：

1. **`{!--< ignore >!--}` 整體生效**：在轉換開始前對整個 docstring 原文做子字串檢查，命中即該模組 / 類別 / 方法**完全不產生文件**。位置無關——即使寫在程式碼圍欄內也生效
2. **程式碼圍欄優先**：行內含 ` ``` ` 圍欄標記後，圍欄內所有行原樣傳遞，圍欄內的其餘標籤**不會被解析**
3. **`tips` 按行收集**：開標籤所在行「標籤之後」的文字 + 後續各行，直到遇到含 `{!--< /tips >!--}` 的行（取閉標籤之前的文字），整體渲染為 `> **提示**` 引用區塊；區塊內的範例與程式碼區塊照常轉換。開標籤同一行「標籤之前」、閉標籤同一行「閉標籤之後」的文字會被**捨棄**
4. **tips 未閉合不報錯**：閉標籤缺失時靜默收集到 docstring 末尾並整段按提示區塊渲染——不報錯、不告警，靠產生結果審查發現
5. **單行標籤按子字串匹配**：`internal-use` / `deprecated` / `experimental` 輸出為 **內部方法** / **已棄用** / **實驗性功能** + 該行「最後一次出現標籤之後」的文字；標籤之前的文字捨棄
6. **未知與寫錯的標籤**：一行同時含 `{!--<` 與 `>!--}` 但非上述已知標籤時，該行**靜默跳過**；若標籤格式寫錯（如 `{!--< tip >--}` 漏了 `!`），不滿足跳過條件，會**原樣洩漏進產生的 API 文件內文**——產生後請目檢輸出

## 最佳建議

1. **類型註解**：使用 Python 類型註解語法
   ```python
   def func(param: int) -> str:
   ```

2. **參數說明**：對可選參數註明預設值
   ```python
   :param timeout: [int] 超時時間(秒) (預設: 30)
   ```

3. **返回值**：多返回值使用 `Tuple` 或明確說明
   ```python
   :return: 
       str: 狀態資訊
       int: 狀態碼
   ```

4. **異常說明**：使用 `:raises` 標註可能拋出的異常
   ```python
   :raises ValueError: 當參數無效時拋出
   ```

5. **內部方法**：非公開 API 應添加 `{!--< internal-use >!--}` 標籤

6. **過時方法**：標記過時方法並提供替代方案
   ```python
   {!--< deprecated >!--} 請使用 new_method() 代替 | 2025-07-09
   ```
