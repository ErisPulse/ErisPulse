# ErisPulse 工作台

> [!TIP]
> **什麼時候需要閱讀這篇**：當你要把模組 / 適配器提交到模組商店、為模組申請一個 `plugin-xxx.erisdev.com` 網站地址、用腳本或 CI 自動提交模組、或讓自己的網站支援「用 ErisPulse 帳號登入」時閱讀這篇。不需要則跳過。

[ErisPulse 工作台](https://workbench.erisdev.com/) 是生態的**統一帳號中心與創作者後台**：一個帳號貫通模組商店、託管域名與開放介面。它是純線上服務，**無需安裝任何套件**——打開網頁、登入即可使用。

```text
GitHub / Codeberg / 雲湖 / 郵箱 登入
            │
            ▼
      ErisPulse 帳號 ──── 兩步驗證（可選）
            │
   ┌────────┼─────────────┬──────────────┐
   ▼        ▼             ▼              ▼
模組管理   托管域名      訪問令牌      OAuth 應用
（商店）  （網站地址）  （腳本/CI）  （第三方登入）
```

---

## 登入與帳號

工作台支援四種登入方式，未設定的登入方式不會顯示在登入頁面：

| 方式 | 適用場景 |
|------|---------|
| GitHub | 作品碼托管於 GitHub 的作者 |
| Codeberg | 作品碼托管於 Codeberg 的作者 |
| 雲湖 | 使用雲湖平台的使用者 |
| 郵箱 | 沒有上述帳號的使用者：使用者名 + 郵件 + 密碼，註冊時需填寫收到的 6 位驗證碼 |

> [!NOTE]
> 同一個帳號可以在「個人資料」頁面綁定多個登入身份。使用不同方式登入後綁定到一起，下次使用任一種方式都能進入同一個帳號。

**雙重驗證**：在「個人資料」頁面可以開啟基於動態口令（TOTP）的雙重驗證，使用任何驗證器 App 掃碼即可。開啟後，登入以及刪除作品、刪除域名等敏感操作都需要輸入動態碼。

> [!WARNING]
> 動態口令的密鑰**僅在開啟時顯示一次**。遺失密鑰將無法登入，請務必妥善保存。

## 模組管理

模組商店中收錄的所有模組與適配器皆可在工作台中進行管理。

### 提交模組

1. 左側進入「提交新模組」
2. 填寫表單：

| 字段 | 說明 |
|------|------|
| 名稱 | 模組名，與 entry-point 的鍵名一致 |
| 類型 | `module`（功能模組）或 `adapter`（適配器） |
| PyPI 包名 | 如 `ErisPulse-MyModule` |
| 描述 | 至少 10 個字元 |
| 作者 | 顯示在商店中的作者名 |
| 倉庫地址 | `github.com` 或 `codeberg.org` 上的倉庫 |
| 分類 | 工具 / 娛樂 / 管理 / 通知 / AI / 平台 / 分析 |
| 標籤、多語言、最低 SDK 版本 | 可選 |

3. 提交後經模組索引倉庫發佈，**通常數分鐘內**會出現在商店中

新提交的模組初始為「未驗證」——表示尚未通過官方審核，使用者安裝時會收到風險提示。審核通過後轉為「已驗證」。

### 編輯與批量操作

在「模組列表」進入自己的模組詳情頁，可以修改描述、倉庫地址、分類、標籤等全部元數據，並上傳模組圖標；也可以開啟多選模式，對多個模組**批量認證 / 取消認證 / 刪除**（整批操作只需輸入一次動態碼）。

### 歸屬認領

模組商店中已有、但不是由你提交的模組（例如早期由他人代為收錄），可以認領回自己的帳號：

- **自動認領**：使用與模組倉庫相同的 GitHub / Codeberg 帳號登入，系統識別到倉庫歸屬一致時自動完成認領
- **手動認領**：在模組詳情頁點「認領此模組」並填寫理由，由管理員審核後轉移

## 托管域名

每個已收錄的模組可以申請一個免費的網站地址，形如 `plugin-模組名.erisdev.com`，用於放置模組主頁、文件或演示站。

| 限制 | 數值 |
|------|------|
| 每個模組 | 2 個域名 |
| 每個帳號 | 10 個域名 |
| 未完成驗證 | 7 天後釋放，域名可被他人再次申請 |

### 四種接入方式

| 方式 | 怎麼用 | 適合 |
|------|--------|------|
| **倉庫分支**（推薦） | 填倉庫地址 + 分支名，工作台直接讀取該分支下的靜態檔案 | 站點源碼就在模組倉庫裡，推送即更新 |
| **重定向** | 訪問該域名時 301 跳轉到你指定的 `https://` 地址 | 已有自己的網站，只想要一個好記的入口 |
| **自有伺服器** | 添加一條 CNAME / A / AAAA 記錄指向你的伺服器 | 自己部署了站點 |
| 上傳靜態站點 | 上傳 zip 包，由平台物件儲存托管 | 暫僅限內測，未全面開放 |

「倉庫分支」的分支名預設填 `ep-site`——約定俗成的站點分支名，建議把站點檔案放在這個獨立分支裡，不污染主分支程式碼。

### 申請流程

1. 左側進入「托管域名」，選擇要掛域名的模組（只能選自己名下的模組）
2. 填寫前綴，輸入時會即時檢查是否可用。前綴只允許小寫字母、數字和中間的連字號
3. 選擇接入方式並填寫對應資訊，提交

**審核規則**：每個模組的**第一個域名直接生效**；從第二個起需要管理員審核，審核結果會透過郵件通知。

### 所有权驗證

為防止有人把域名指到不屬於自己倉庫或伺服器，「倉庫分支」與「自有伺服器」兩種方式需要驗證所有權：

| 方式 | 驗證方法 |
|------|---------|
| 倉庫分支 | 在該分支根目錄放一個檔案 `erisdev-site-verify.txt`，內容為工作台給出的驗證碼 |
| 自有伺服器 | 在你的伺服器上提供 `/.well-known/erisdev-verify.txt`，內容同上 |

放好檔案後回到工作台點「完成驗證」。驗證通過前，訪問該域名會顯示「等待所有權驗證」的提示頁。

### 管理操作

每個域名卡片上可以：

- **暫停 / 恢復**：暫停後訪問顯示「站點已暫停」，內容保留
- **刪除**：釋放該域名與全部托管資源，需輸入動態碼
- **更換倉庫或分支**：修改後回到待驗證狀態，重新驗證即可生效

## 開放介面

工作台同時是一個 OAuth 2.0 授權伺服器，對外提供兩類能力。

### 訪問令牌

在腳本或 CI 中呼叫工作台介面（如自動提交模組）時，使用訪問令牌取代帳號密碼：

1. 進入「開放平台 → 訪問令牌」，填寫名稱後點擊「生成令牌」
2. 令牌格式為 `epat_` + 40 位十六進位，**僅在生成時顯示一次**
3. 請求時放在 `Authorization: Bearer epat_…` 標頭中

每個帳號最多可擁有 10 個令牌。若已啟用雙重驗證的帳號，可以勾選「免動態碼」——之後使用這個令牌呼叫敏感介面時不再要求動態碼，適合無人值守的 CI。

> [!TIP]  
> 請求主體必須是 UTF-8 編碼的 JSON。Windows 終端預設為 GBK，直接傳中文會被伺服器拒絕——請先執行 `chcp 65001`，或將請求主體儲存為檔案後使用 `curl --data-binary @body.json` 提交。

### OAuth 應用

若您希望自己的網站或工具支援「使用 ErisPulse 帳號登入」：

1. 進入「開放平台」，註冊一個應用：填寫名稱和回調地址（可填多個）
2. 獲得 `client_id` 和 `client_secret`——**密鑰僅顯示一次**，可隨時重設
3. 按標準 OAuth 2.0 授權碼流程進行整合：

| 端點 | 用途 |
|------|------|
| `/oauth/authorize` | 引導用戶授權 |
| `/oauth/token` | 使用授權碼換取令牌 |
| `/api/userinfo` | 使用令牌獲取用戶資訊（不含電子信箱） |

每個帳號最多可註冊 5 個應用。

## 常見問題

### 提交後模組沒有立刻出現在商店裡？

模組收錄經模組索引倉庫異步下發，通常數分鐘內生效。可在模組列表查看操作狀態，顯示「已應用」即為成功。

### 域名驗證一直不通過？

確認驗證檔案的**路徑和內容**都與工作台顯示的完全一致（路徑區分大小寫、內容不要有多餘空格或換行）。倉庫分支方式還需確認檔案在**你填寫的那個分支**上。

### 域名申請後多久生效？

「倉庫分支」和「重定向」不需要等待，驗證通過後立即生效。「自有伺服器」方式還需要等 DNS 記錄在全球傳播，通常幾分鐘。
