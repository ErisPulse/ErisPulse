# 文档与国际化规范

## 文档单一源（强约束）

- **`docs/zh-CN` 是唯一维护源**：只改中文文档；其余语言由 CI 翻译流程生成并自动提交回开发分支，本地无需手动清理残留
- 删除/移动 `docs/zh-CN` 文档时：CI stale 同步自动清理各语言残留，仅需检查中文内部死链接
- **CI 生成物勿手改**（改动会被下轮 CI 覆盖，也不要本地运行生成脚本）：
  - 各语言 `ai-support/prompts/`（AI 提示词包）
  - 各语言 `api-reference/auto_api/`（API 文档，源码 docstring 是唯一内容来源）
  - 生成清单集中在 `scripts/tools/generators/spec.py`（改清单只动它）

## 新增/重构文档的两项必做

1. 更新根文档 README 与相关总结性文档的链接
2. 检查生成脚本清单是否需要同步（`spec.py`）；CI 负责 `gen ai-prompts` / `gen docs-index` / `gen skills`

## 文档行文规则

- **价值先行**：第一屏回答"读这篇我能得到什么"。按需查阅类用 `> [!TIP]`"什么时候需要读这篇：……不需要则跳过"开头；核心必读类用 `> [!NOTE]` 标注阅读路径位置
- **实例优先于叙述**：能写可运行代码块的不写描述性段落；示例含 import 与最小上下文，可复制运行，不给 `...` 省略
- **触发描述即检索入口**：开头一句写具体场景（"当你的适配器需要……"），不写抽象归类（"本文介绍……"）
- **结尾按意图分组**："下一步"链接按读者意图组织，不放无差别目录
- **版本标注**：正文只标行为差异（"X.Y 起 …（此前 …）"）；"本特性需要 X+"类准入标注集中到版本速查表；示例代码版本号用 `x.y.z` 占位

## i18n（强约束）

- 新增翻译键必须同步全部五个语言文件：`zh-CN` / `zh-TW` / `en` / `ja` / `ru`
- 键名点号分隔：`<模块>.<类别>.<描述>`（如 `core.sdk.init.starting`）
- 配置字段 `description` 用 i18n 字典格式：`{"i18n": "key.path", "default": "兜底文本"}`
- 声明了 i18n key 的地方必须确保翻译已注册；示例项目默认纯文本，不用未注册 key

## 模板与示例同步

- 改适配器/模块基类或配置规范 → 同步 `CLI/commands/create.py` 的 `_ADAPTER_CORE` / `_MODULE_CORE` 模板
- 改公共 API → 同步 `examples/` 示例项目；示例体现推荐写法（配置类嵌套 `ConfigClass` 声明、根导入等）
- `create.py` 模板改动后须 `.format()` + `compile()` 验证生成代码合法
